## 1. 视觉 token 化的总览

三条管线的视觉侧（详见 [04-完整推理流程篇](./04-完整推理流程篇.md)）：

```
V1: resize(1024²)      → SAM → 256 tok → CLIP-L(24层) → concat SAM → projector(2048→1280) → 273 tok
V2: dynamic_preprocess → N×[ SAM(768²) → DeepEncoderV2(因果查询) → proj ] + 全局图 → 857 tok
V3: pad(1024²)+crops   → N×[ SAM(640²) → CLIP → proj → 111 tok ] + 全局 272 → 903 tok
```

关键认识：**视觉 token 数 ≈ (输入边长/16/4)²**。除以 16 是 patch 化，
再除以 4 是 SAM neck+downsample 的 4× 空间压缩（16×16 网格）。

## 2. ViT：把图片当句子读

ViT 把 H×W 图片切成 P×P patch（本项目 P=16），每个 patch 展平后过一个
Conv2d(k=P, s=P)——数学上等价于"按 patch 查表"，这就是 patch embedding：

```
tokens = Conv2d(x; W_p) + pos_embed    # [B, (H/P)(W/P), D]
```

- 1024² 输入 → (1024/16)² = 4096 个 patch，维度 768（SAM）
- token 数是平方复杂度：边长翻倍 → 注意力计算 ×4

## 3. SAM Vision Tokenizer：窗口注意力 + 相对位置偏置

SAM ViT-B（12 层）的独特之处是**窗口注意力**（对应 `ds_visual_tokenizer.c` 的
`window_attn_forward`）：

- 层 [0,1,3,4,6,7,9,10]：把 64×64 patch 网格切成 14×14 的窗口（带 padding），
  注意力只在窗口内做 → 复杂度从 O(N²) 降到 O(N·w²)，w=196
- 层 [2,5,8,11]：全局注意力，让信息跨窗口流动（与 Swin 的移位窗口异曲同工）

**相对位置偏置（rel-pos bias）**：SAM 不用 RoPE，而是在注意力分数上叠加
可学习的位置偏置：

```
attn[i,j] += (q_i · rh[Δy(q_i,j)]) + (q_i · rw[Δx(q_i,j)])
```

即"查询向量与按相对位移索引的位置向量做点积"。height 与 width 两个方向
解耦，各查一张 [2w-1, head_dim] 的表。这就是 `rel_pos_h / rel_pos_w` 权重。

## 4. CLIP-L：视觉语义精炼器

CLIP-L 是 24 层标准 ViT（D=1024，16 头，双向注意力）。在本工程中它**不做
patch embedding**（跳过 Conv2d），直接吃 SAM 的输出特征——所以叫"精炼器"：
给 SAM 的几何特征加上语义先验。最后取 CLS 以外的 256 个 patch token，
与 SAM 特征 concat 成 [256, 2048]，经 projector 降到 1280 给解码器。

## 5. 位置嵌入插值：get_abs_pos 的坑

CLIP 的位置嵌入是 [257, 1024]（1 CLS + 16×16 网格）。当输入不是 256 个
patch（例如 V3 的 640² crop 是 10×10=100 个），必须插值。Python 参考：

```python
def get_abs_pos(abs_pos, tgt_size):
    if src_size != tgt_size:                      # 16 != 10
        new = F.interpolate(old.view(1,16,16,D).permute(0,3,1,2),
                            size=(10,10), mode='bicubic',
                            antialias=True, align_corners=False)
```

**工程教训（本项目真实 bug）**：C 端曾经"直接抄位置表前 100 行"——对 10×10
网格来说等于把 16×16 网格的前 6.25 行当位置编码用，视觉 token 的位置信息
系统性错乱，外在表现是 V3 在多裁剪图上幻觉出 `</td></tr></table>` 前缀。
修复为抗锯齿 bicubic 双线性维分离重采样（`ds_deep_encoder.c` 的
`ds_bicubic_resample_dim`）后问题消失。**任何"位置相关"的实现偏差都会
以诡异的方式烧到输出质量上。**

## 6. 动态多裁剪：NaViT 思想的工程化

固定分辨率会"拉伸"长文档或"缩没"小字。DeepSeek-OCR/Unlimited-OCR 的解法
（`ds_image.c: ds_dynamic_preprocess`）：

1. 按长宽比在候选网格 {i×j | min_num ≤ i·j ≤ max_num} 里选最接近原比例的
   （`find_closest_aspect_ratio`，与 Python 实现逐位对齐，含 tie-break）
2. 整图 resize 到 (cols×768, rows×768)（V2）或 (cols×640, rows×640)（V3）
3. 等分成 i·j 个 tile，行主序编号

这就是 NaViT"序列打包"思想的简化版：**保比例 + 分块，而不是硬 resize**。
代价是 token 数随页数线性增长（V3 最多 32 crops ≈ 3323 token）。

## 7. 2D 网格重排与 image_newline

Projector 输出的一维 token 序列需要恢复 2D 空间结构：每行末尾插入一个
可学习的 `image_newline` 向量（[1280]），最后追加 `view_seperator`。
16×16 网格 + 16 个换行 + 1 分隔 = 273 token。这个技巧源自 LLaVA-1.5，
给解码器提供"行边界"信号，对表格/多栏版面很关键。

## 8. V1 / V2 / V3 三代视觉侧对比

| | V1 | V2 | V3 (Unlimited-OCR) |
|---|---|---|---|
| 编码器 | CLIP-L | Qwen2-0.5B 改（因果流查询+GQA） | CLIP-L + R-SWA |
| 裁剪 | 无（拉伸 1024） | 768², 2–6 crops | 640², 2–32 crops |
| 小图 token | 273 | 257 | 111 |
| 大图 token | 273 | 857 (6-crop) | 111~3323 |

## 9. 动手实验

1. `DS_DUMP_TENSORS=1 ./ds_ocr …` 导出 SAM 逐层张量，验证窗口注意力输出形状
2. 把 `ds_bicubic_resample_dim` 临时改回"抄前 N 行"，对比 V3 输出差异
3. 用 `compare_neck.py` 对比 SAM neck 的 C 输出与 Python 参考（corr ≈ 0.995）
4. 思考题：为什么 V3 小图（111 token）比大图快得多，但 decode tok/s 反而
   接近？提示：decode 每步注意力读的是 KV cache，与视觉 token 数相关但
   不是主导项——主导项是 MoE 专家与 LM head。

---

**小结**：视觉侧的本质是"把图变成一串带位置语义的向量"。SAM 给几何、
CLIP 给语义、多裁剪给分辨率自适应；位置信息（插值、网格重排、换行符）
比网络本体更容易出 bug，也最值得写对齐测试。
