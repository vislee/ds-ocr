## 1. 训练数学：从 loss 到每个权重

**前向最后一层**：logits z，交叉熵 L = −log softmax(z)[y]。
联合 softmax 求导得到全深度学习最优雅的梯度：

```
∂L/∂z_i = p_i − 1{i=y}        （预测概率 − one-hot）
```

**反向传播 = 链式法则 + 局部导数**。以本仓库 RMSNorm 为例
（y = x·g/rms(x)）：

```
∂L/∂x = (∂L/∂y)·g/rms + x·(−1/2)·rms⁻³·(∂/∂x 内 Σx²) …
```

框架用自动微分生成；手写推理引擎之所以**不需要反向**，是因为只做前向——
但读训练代码时你要能默写：Linear 梯度 dW = dyᵀ·x，dx = dy·W。

**为什么注意力除以 √d**：独立分量下 q·k 的方差 ≈ d·Var(q)·Var(k)，
维度越高点积方差越大，softmax 进入饱和区 → 梯度消失。除 √d 把方差
归一到 O(1)。

## 2. FlashAttention：online softmax 推导

朴素注意力要物化 S=QKᵀ（N×N）再 softmax，显存爆炸。核心观察：
**softmax 的行最大值 m 和归一化和 l 可以流式合并**：

```
处理新块 [m_new, l_new, O_new]：
  m'   = max(m_old, m_block)
  l'   = e^{m_old−m'}·l_old + e^{m_block−m'}·l_block
  O'   = e^{m_old−m'}·O_old + e^{m_block−m'}·(P_block·V_block)
最后 O /= l
```

数学上与全量 softmax **逐位等价**（每行 exp 都带着正确的大值修正）。
GPU 上再叠加 tiling 到 SRAM、跳过因果掩码块 → 显存 O(N)、计算更快。
本工程 `ds_causal_attention_aligned` 的"在线 softmax + 预计算 RoPE +
F32 KV 直读"就是同一思想的手写单请求版。进阶：Flash Decoding
（decode 沿 seq 维并行）、FlashAttention-3（异步+FP8）。

## 3. 注意力三十年：MHA → MQA → GQA → MLA

| 方案 | KV 头数 | KV cache | 质量 |
|---|---|---|---|
| MHA | =Q 头（10） | 100% | 基准（本仓库解码器） |
| MQA | 1 | 1/10 | 有质量损失 |
| GQA | g 组（如 8/32） | g/Q | 接近 MHA（Llama2-70b+） |
| MLA (DeepSeek-V2) | **潜在压缩 c_kv(512) + 解耦 RoPE 键** | ~1/10 且质量持平 | SOTA |

MLA 的洞见：KV 可低秩压缩。只缓存潜在向量 c（配合上投影矩阵在用的时候
"吸收"进 Q/输出投影，即 weight absorption），RoPE 部分因不可吸收而单独
保留一个解耦键。代价：实现复杂度大增——这就是为什么"读得懂 MLA 的
absorption"被放进精通自测。

## 4. 长上下文：外推的四代技术

预训练 L=4k 的模型直接用到 32k 会崩（RoPE 相位超出训练范围）：

1. **位置插值 PI**（arXiv:2306.15595）：位置 m → m·(L_train/L_target)，
   少量续训即可扩展
2. **NTK-aware 缩放**：不动位置、把 RoPE 底数 θ 调大
   （θ' = θ·s^{D/(D−2)}），高频外插低频内插
3. **YaRN**：按频率分段插值 + 注意力温度因子，效果最佳且续训 token 少
4. **无需训练**：Attention Sinks（StreamingLLM，arXiv:2309.17453）——
   保留最初几个 token 的 KV（softmax 的"注意力宿"）+ 滑窗即可无限流式

本仓库 R-SWA 的"参考集+滑窗"与 Sinks 滑窗思想同源，但参考集是**全部
视觉+prompt token**——这是 OCR"图必须全程可见"的任务约束决定的。
思考：若把 V3 上下文扩到 100k，四个方案各自要改推理引擎的哪里？
（答：RoPE 缓存生成器、KV cache 容量、R-SWA 窗口逻辑。）

## 5. MoE 训练细节：工程里看不见、质量里躲不掉

- **Capacity factor**：每个专家每 batch 只收 c×(N/E) 个 token，超量
  token 被 drop（训练与推理都有）；c 太小丢 token，太大浪费算力
- **负载均衡 aux loss**（Switch）：L_aux = α·N·Σᵢ fᵢ·Pᵢ（f=实际路由频率，
  P=平均路由概率），强迫路由均匀
- **aux-loss-free**（DeepSeek-V3）：不改 loss，给每个专家一个偏置 bᵢ，
  **只参与 top-k 选择、不进门控值**；超载就调低 bᵢ——消除了 aux loss
  干扰主梯度的副作用
- 共享专家 + 细粒度专家（专家更多更小）= DeepSeek-MoE 的两大架构贡献

推理端对照：本工程没有 capacity 限制（单 token 必然全部被服务），
但**批处理推理**时就必须引入——这是 04→13 的进阶分水岭。

## 6. 服务系统：从单请求到生产

- **Continuous batching**（Orca, OSDI'22）：调度粒度从"请求"细化到
  "token 迭代"，早结束的请求立刻让位 → 吞吐 2-20×。本仓库
  `ds_decoder_forward_batch` 是其雏形
- **Chunked prefill**：长 prompt 切块与 decode 混排，避免长 prefill 阻塞
- **Prefix caching**：相同前缀（system prompt/同一张图的视觉 token）
  复用 KV——OCR 多页解析同版式时收益巨大
- **张量并行推理**：QKV 列切（各卡算自己头）+ O 行切（all-reduce），
  通信量 2·hidden/层；PP 按层切但气泡率高
- **Prefill/Decode 分离**（PD disaggregation）：两类负载资源画像不同，
  分池部署（DistServe/ Mooncake）

## 7. 线性注意力与混合架构：从 DeltaNet 到 KDA

本仓库 V3 的 R-SWA（第 6 节 05 篇）已把 KV cache 控制在 O(prefill+W)，
但 **decode 每步仍要读全部 reference 段 K/V**——访存量没有降。业界更激进的
路线是**线性注意力**：把历史压进一个固定大小的状态矩阵，彻底消除逐 token
的 KV 读取。本节按"演进 → 推导 → 系统"三步讲清这条线。

### 7.1 为什么需要线性注意力

Softmax attention 的三个 O(N)（N=上下文长度）：
1. **显存容量**：KV cache 随 N 线性增长
2. **显存带宽**：decode 每步读一遍全部历史 K/V
3. **计算量**：每步与全部历史做点积

R-SWA/滑窗只解决 2、3（保留固定窗口），容量问题靠丢弃窗口外 token。
线性注意力换范式：**RNN**。

```
线性注意力核心：S_t = S_{t-1} + v_t k_tᵀ    （外积写入）
读出：        o_t = S_t q_t                    （矩阵×向量）
S ∈ ℝ^{d_v×d_k} 固定大小 → 显存/读取/计算相对 N 都是 O(1)
```

这本质上把"历史 KV cache"换成了"一份随序列演化的权重矩阵"。

### 7.2 演进主线：四档状态更新

从 fast-weight 视角（*Linear Transformers Are Secretly Fast Weight
Programmers*, ICML 2020）看：S 是一组**随上下文在线更新的快权重**，存储
key→value 的临时关联；query 读取 = 按匹配度聚合历史 value。

| 架构 | 状态更新 | 遗忘 | 写门 |
|---|---|---|---|
| 线性注意力 | S_t = S_{t-1} + v_t k_tᵀ | 无 | 无 |
| DeltaNet | S_t = S_{t-1} + β_t(v_t − S_{t-1}k_t)k_tᵀ | 无 | β_t (标量) |
| GDN | S̄_t = α_t S_{t-1}，再 Delta 更新 | 每 head 一个 α_t | β_t, α_t |
| KDA | S̄_t = S_{t-1}Diag(α_t)，再 Delta 更新 | 每 head 每 key 通道 α_t | β_t; α_t[h, d_k] |

**DeltaNet 的洞见（Delta Rule = 对当前样本做一步 SGD）**：
把 S 看成"从 key 预测 value 的线性模型"，每来一个 (k_t, v_t) 样本：

```
重建损失：L(S) = ½‖v_t − S k_t‖²
梯度：    ∇L = (S k_t − v_t) k_tᵀ
SGD 一步：S_t = S_{t-1} − β_t ∇L = S_{t-1} + β_t(v_t − S_{t-1}k_t)k_tᵀ
```

- 普通线性注意力 = **无条件累加**：同一个 key 的新旧 value 直接叠加，
  重复特征反复写入 → 数值爆炸
- DeltaNet = **残差写入**：先检查旧记忆已能预测什么（S k_t），只写入
  预测残差。若旧记忆已正确（S k_t = v_t），残差为零，不重复写

**遗忘门的由来（正则化视角）**：对重建损失加 L2 正则 λ‖S‖²，SGD 更新
中旧权重被乘上 (1−ηλ) 缩放因子——这正是 GDN 遗忘门 α_t 的形式：

```
S_t = (1−β_t λ_t) S_{t-1} + β_t v_t k_tᵀ    （α_t = 1−β_t λ_t）
```

遗忘不是 hack，而是**快权重的权重衰减**：α 控制旧记忆保留多少，
β 控制当前关联纠正多少，二者由模型按输入独立生成。

**KDA（Kimi Delta Attention，GLM-5.3-Flash / Kimi Linear 采用）** 把
GDN 的每 head 标量 α 拆成 **每 head 每 key 通道**的向量 α_t ∈ (e⁻⁵, 1)ᵈᵏ
——状态 S 的每一列独立衰减，能选择性记住/遗忘不同的 key 模式：
- 高频通道（语法、格式）快速遗忘，保留最新
- 低频通道（实体、主题）缓慢衰减，长期保留

KDA 完整单步更新（先衰减，再读残差，再写入，最后读出）：

```
S̄_t = S_{t-1} ⊙ α_t          # 遗忘：按 key 通道缩放
Δv  = v_t − S̄_t k_t           # 残差：旧记忆预测不到的部分
S_t = S̄_t + (β_t Δv) k_tᵀ     # 写入
o_t = S_t q_t                 # 读出（后续过 RMSNorm ⊙ 输出门 γ）
```

**L2 norm 的必要性**：DeltaNet 对 q/k 做 L2 归一化（‖k‖=1），保证转移
I − β_t k_t k_tᵀ 的谱范数 ≤ 1（k 方向特征值 1−β_t，正交补为 1）——
**旧状态转移只收缩不放大**，长序列下状态有界。代价：β_t=1 的精确覆写
仅在 ‖k_t‖=1 时成立；非单位范数时残差按 ‖k‖² 缩放，β_t=1 会过冲。

**短卷积（causal conv1d, kernel=4, SiLU）**：固定状态对局部相邻 token
建模弱，因此在投影后的 q/k/v 上先做因果短卷积再进全局状态——
"卷积补局部，线性注意力聚全局"是这类架构的标配（H3 → Mamba →
DeltaNet 一脉相承）。

### 7.3 并行化：非线性递归 → 仿射变换 + 下三角系统

RNN 的历史问题：状态更新有**时间维递归依赖**，无法像 attention 那样
各位置并行。对比：

- **经典 RNN**：h_t = tanh(W h_{t-1} + x_t)，tanh 嵌在状态反馈链里，
  h_t 依赖 h_{t-1}，串行
- **Attention**：各位置的 q/k/v 都由**当前层输入**投影得到，softmax
  非线性不建立"本层前一位置输出 → 本层后一位置输出"的反馈链 → 并行

KDA 介于两者之间。关键观察：把 KDA 单步更新中的旧状态项合并：

```
S_t = S_{t-1}Diag(α_t) − β_t S̄_t(α_t⊙k_t)k_tᵀ + β_t v_t k_tᵀ
     = S_{t-1}·T_t + H_t
```

**只要当前步的 k_t, v_t, α_t, β_t 已知（可并行预计算），状态更新就是
对旧状态的仿射变换**——非线性门控全部进入系数 T_t/H_t，不进入状态反馈
链。这是整条并行化路线的支点。

**Chunkwise（C=64，分三阶段）**：把序列切成 chunk，
S_C = S_0·Transition_chunk + Δ_chunk：

```
阶段 1（块内预计算）：各 chunk 并行算 Transition_chunk、Δ_chunk
阶段 2（块间传递）：  按块序传递状态（唯一串行点，但只是 chunk 数量级）
阶段 3（块内输出）：  各 chunk 并行算每 token 输出 o_i
```

块内的残差递归 u_t = β_t(v_t − Σ_j A_tj u_j) 改写成**单位下三角系统**：

```
(I + A) U = B V        # I+A 对角全 1 → 总可逆，不要求 key 线性无关
A_tj = β_t k_tᵀ (α_{j+1}⊙...⊙α_t ⊙ k_j)   # 历史 key 衰减后与当前 key 的对齐度
```

工程上把 64×64 下三角切成 16×16 子块：子块内部短递推、跨子块合并用
矩阵乘法（子块求逆可独立准备，再矩阵乘合并）。同一套 (I+A)⁻¹ 系数矩阵
被复用于计算传入状态修正 W 和块内读出矩阵 M——一次求逆，三处复用。

**与 FlashAttention 的关键区别**：FlashAttention 的并行来自"softmax
的行统计量（m, l）可流式合并"；Chunkwise KDA 的并行来自"状态更新是
仿射变换、递归可组合"。前者并行的是**块内行**，后者并行的是**块间
预计算** + 块内下三角求解。

### 7.4 系统层：vLLM 怎么把 KDA 塞进 PagedAttention

KDA/Mamba 层每请求只有一个固定 state，而 PagedAttention 整套机制
（block、hash、block table）为"逐 token 增长的 KV"设计。vLLM 的做法：

1. **一份 state = 一个 block**：让 Mamba state 的字节数对齐 attention
   单层 page size。GLM-5.3-Flash：MLA 每 token 1×512×2B=1024B（NoPE），
   KDA state [8,128,128] fp32 + conv_state = 542,720B →
   block_size = 128×cdiv(542720, 128×1024) = **640**，state padding 到
   655,360B（多 20.7%）。这就是 hybrid 模型 block_size 动辄几百的原因。
2. **KVCacheGroup**：同 spec 的层共用一张 block table。MLA + Indexer
   通过 UniformTypeKVCacheSpecs 合成一个 Group；34 层 KDA 按一个 block
   能装的 state 数切成 [9,9,8,8] 四组。
3. **Marconi 式共享前缀分叉**：Mamba 只在块尾存 S，"长 system prompt +
   不同用户问题"的中间分叉点命中不了。做法：full attention 的命中结果
   反推出分叉点 → 下一个请求在分叉点截断并存 S → 第三个请求直接命中。
4. **推测解码状态快照**：Full Attention 的被拒 draft 不污染历史（KV
   独立）；KDA 的递归状态 S 是**原地混合更新**，draft 拒绝后必须回滚——
   为每个候选 token 各存一份 S（num_speculative_blocks 个槽位），验证后
   按接受数索引回滚。ReplaySSM/RecoverSSM 是缓存输入重放/保存修正量的
   优化路线，可省去逐步写回 S 的带宽。

**对照本仓库**：ds-ocr 是单请求引擎，无 PagedAttention/推测解码，但
V3 的 R-SWA 与 KDA 共享同一动机（控制 KV 访存）；ds_moe_decoder.c 的
逐 token decode 循环就是"最朴素的 recurrent 路径"——如果未来接 KDA 类
层，decode 侧几乎不用改（本来就是单步递推），改的是 prefill 侧：把
sgemm 批量注意力换成 chunkwise 状态传递。
