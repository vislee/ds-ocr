## 1. 预训练全景

预训练 = 在海量无标注文本上，用**下一个 token 预测**做自监督学习：

```
loss = -Σ_t log P(x_t | x_<t; θ)
```

> **为什么"猜下一个词"能逼出理解？** 填空题有难度梯度："白日依山尽，黄河入海__"背过就能填；而"该合同第 7.2 条与第 9.1 条存在__，故违约金条款不适用"——想填对，必须真的看懂两条条款的逻辑关系。当语料足够广、题目足够多，想把这个游戏的分数刷高，唯一的捷径就是长出语法、指代消解、逻辑推演这些"理解"能力——**能力不是被编程出来的，是被"刷分"倒逼出来的**。

模型背的是"人类知识的压缩包"。本仓库三模型的解码器（3B-MoE）就是这么
练出来的：给它 903 个视觉 token + "document parsing."，它续写出解析文本——
这个能力完全来自预训练语料里的"图像描述/文档转写"混合数据（多模态预训练
阶段注入）。

## 2. 数据：爬取 → 清洗 → 去重 → 配比

工业共识：**数据质量 > 数据量 > 模型大小**（在算力给定后）。

- 获取：CommonCrawl 为底， 加 wikipedia/书籍/代码/论文
- 清洗：语言识别、质量分类器打分（fastText 式）、启发式规则（符号率、重复行）
- 去重：精确 hash + 模糊 MinHash/LSH——重复数据既浪费算力又加剧记忆
- 配比：自然语言 : 代码 : 数学 ≈ 按 Chinchilla 最优与下游用途调，
  DeepSeek-V3 预训练 14.8T token，代码与数学占比显著提高以换推理能力
- **课程**：末段上高质量数据（退火阶段），DeepSeek-V3 在最后阶段把
  学习率拉低并换精选数据——这是"预训练里藏后训练"的现代做法

工程对应：本仓库遇到的"幻觉/重复"，很多能追溯到数据分布——模型没见过
"图里没有文字时该输出 EOS" 的足够样本。

## 3. 词表与架构决策

训练前锁死、推理端只能接受的决定：

- **词表**（本工程 129280）：改变词表 = 全部 embedding 重训。BPE 在
  预训练语料上训练（见 07 篇）；中文场景偏大词表降低序列长度
- **架构**：层数/隐藏维/头数/RoPE θ/MoE 超参。DeepSeek 系的
  hidden=1280、64 专家 top-6、共享专家 2 —— 推理引擎的常量
  `DS_DEC_*` 就是这些决定的化石
- **精度**：BF16 训练 → 权重文件是 BF16 → 本工程 mmap 零拷贝 + 左移 16 位还原

### 3.1 权重初始化：为什么是 std=0.02

初始化是"训练前锁死"的另一个决定，且**直接写在权重文件里**——推理端读到的
数值分布就是初始化 + 训练共同塑造的结果。理解它，才能理解为什么某些层
的权重看起来"特别小"。

**核心问题**：若每层输出的方差随层数指数放大或缩小，深层网络必然爆炸或
消失。**目标**：让每层输出的方差 ≈ 输入的方差（方差守恒）。

**Xavier/Glorot 初始化**（适用于 tanh/sigmoid 这类"线性区"激活）。设输入
$x$ 各分量独立、均值 0、方差 $\sigma_x^2$，权重 $W$ 独立同分布、均值 0、
方差 $\sigma_w^2$，则输出 $y_j = \sum_{i=1}^{n_{in}} W_{ji}x_i$ 的方差：

$$ \operatorname{Var}(y_j) = n_{in}\,\sigma_w^2\,\sigma_x^2 $$

要 $\operatorname{Var}(y)=\operatorname{Var}(x)$，需 $\sigma_w^2 = 1/n_{in}$。
反向传播同理要求 $\sigma_w^2 = 1/n_{out}$。两者折中取调和平均：

$$ \sigma_w = \sqrt{\frac{2}{n_{in}+n_{out}}} \quad\text{（Xavier）} $$

**Kaiming/He 初始化**（适用于 ReLU）。ReLU 把负半轴砍成 0，输出方差只剩
一半（$\operatorname{Var}=\frac{1}{2}n_{in}\sigma_w^2\sigma_x^2$），所以要
补一个 2：

$$ \sigma_w = \sqrt{\frac{2}{n_{in}}} \quad\text{（Kaiming，fan\_in 模式）} $$

**为什么 LLM 用 `std=0.02` 而不是上面两个公式**：LLM 的残差流（residual
stream）结构改变了方差账。Pre-Norm 下每层是 $x \leftarrow x + \text{SubLayer}
(\text{Norm}(x))$，**残差是加法**——若每个子层输出方差为 $\sigma^2$，L 层后
残差流方差累积为 $\sigma_x^2 + L\sigma^2$，随层数**线性增长**（不是指数，
这是 Pre-Norm 稳定的根源）。要让这个增长温和，子层输出必须**远小于**输入，
于是初始化不再追求"方差守恒"，而是取一个**与 hidden 无关的小常数**。

GPT-2 的做法（论文 §2.3）是双管齐下：所有权重 $N(0, 0.02^2)$，同时把
残差分支的输出在相加前乘 $1/\sqrt{2N}$（N 为层数）——前者让每层修正量小，
后者抵消 $L$ 层累积。**本工程可验证**：`models/Unlimited-OCR/config.json`
与 `models/Unlimited-OCR-2/config.json` 都写着 `"initializer_range": 0.02`
——这个数字就是训练框架按此约定初始化权重时留下的化石，推理端读到的
embedding 数值量级（~0.02）直接来自它。

**推理端的三个可观测后果**：

1. **embedding 数值小**（~0.02 量级）→ 与位置编码相加后位置信息占比不小，
   这也是为什么位置编码的插值误差会显著影响输出（docs/06 §6）
2. **BF16 精度足够**：0.02 量级的数在 BF16（8 位指数、7 位尾数）下相对
   精度 ~0.8%，与 FP32 的差异在残差累积中被 RMSNorm 反复拉回——这是
   `ds_bf16_simulate_python` 能对齐 Python 的前提（docs/03 §3）
3. **量化误差可控**：per-row INT8 量化的相对误差 ~0.39%（docs/09 §2.3），
   与初始化量级无关，但**小权重行**（如某些专家的 down 投影）更容易被
   量化噪声淹没——这是 docs/09 §4 讨论 outlier 的另一面

## 4. Scaling Laws：算力怎么花最划算

Chinchilla 修正了 Kaplan 的结论：给定算力预算，**参数量和数据量应等比例
扩展**（约 20 token/参数）。由此推导：

- 3B 模型的"Chinchilla 最优"≈60B token——但实践会**多练**（overtrain），
  因为推理成本跟随参数量，训练多花点、推理终身受益（Llama 系全部如此）
- MoE 的修正：总参数 3B、激活 570M，等效算力按激活算——MoE 是
  "用内存买算力"的缩放路径（02 篇）

## 5. 训练的数值细节

### 5.1 损失函数：交叉熵与困惑度（推理端 logits 的源头）

预训练的唯一目标函数是**下一 token 的交叉熵**（cross-entropy, CE）。给定
上下文 $x_{<t}$，模型输出词表上的分布 $p = \text{softmax}(z)$（$z$ 就是
推理端 `ds_moe_decoder.c` 里那个 129280 维 logits），真实下一个 token 是
$y$，则单点损失：

$$ \mathcal{L}_t = -\log p_y = -z_y + \log\sum_{j=1}^{V} e^{z_j} $$

后一项 $\log\sum e^{z_j}$ 叫 **logsumexp**，是"配分函数"的对数——它保证
分布归一化，也是数值稳定实现的关键（见下）。整句损失是各位置平均：

$$ \mathcal{L} = -\frac{1}{T}\sum_{t=1}^{T}\log p(y_t \mid x_{<t}) $$

**为什么是它**：最小化 CE 等价于最小化真实分布与模型分布的 KL 散度
（真实分布是 one-hot，其熵为 0，故 $H(q,p) = H(q) + D_{KL}(q\|p) = D_{KL}$）。
换句话说，**训练就是在最小化"模型分布偏离 one-hot 真值"的程度**。

**链式法则逐步拆**：把 $\mathcal{L}_t$ 看成三个算子的复合
$z \xrightarrow{\text{softmax}} p \xrightarrow{-\log(\cdot)_y} \mathcal{L}_t$
（NLL = negative log-likelihood，负对数似然）。利用 $\mathcal{L}_t = -z_y +
\log\sum_j e^{z_j}$ 这个"目标分量 + logsumexp"的拆分，对任意分量 $z_i$：

$$ \frac{\partial \mathcal{L}_t}{\partial z_i} = -\mathbb{1}\{i=y\} + \frac{e^{z_i}}{\sum_j e^{z_j}} = p_i - \mathbb{1}\{i=y\} $$

第一项是目标 logit 的直接贡献（当且仅当 $i=y$ 时为 −1）；第二项是
logsumexp 对每个分量的导数——**恰好就是 softmax 本身**（见 13 篇 §1.1
的完整雅可比推导）。合并成一句口诀：**梯度 = 预测概率 − 真值**。预测
过高的分量按"虚高的概率"被往下压，真值分量按"缺席的概率"被往上抬，
梯度各分量之和恒为 0（概率质量守恒）。反向传播从这里出发逐层穿过整个
网络（13 篇 §1 把这条链推到每个权重）。

**训练管线的第一块试金石**：随机初始化时 logits 近乎均匀，
$p \approx 1/V = 1/129280 \approx 7.7\times10^{-6}$，故第 0 步 loss 应约等于

$$ \ln V = \ln 129280 \approx 11.77 $$

任何一次从零训练，第一个 log 的 loss 不在 ln V 附近 = 数据/标签/mask
管线有 bug（比如 padding 位置也被计损）。

**困惑度（perplexity, PPL）** 是 CE 的指数形式，单位回到"等效候选词数"：

$$ \text{PPL} = \exp(\mathcal{L}) $$

PPL=10 意味着模型平均在"10 个等概率候选"之间犹豫。它是预训练最常用的
监控指标（docs/11 §9 评估），但**与 OCR 任务质量不直接挂钩**——OCR 关心
的是字符错误率（CER，见 08 篇），PPL 低不等于转写准。

**手算一个小例子**（V=3 便于笔算，道理与 129280 完全相同）。设模型在某
位置输出 logits $z = [1.0,\ 2.0,\ 0.0]$，真实下一个 token 是 $y=1$：

```
exp(z) = [2.718, 7.389, 1.000]，配分函数 Z = 11.107
p      = [0.2447, 0.6652, 0.0900]        （softmax 归一化）
loss   = −ln 0.6652 = 0.4076
梯度   = p − onehot(1) = [+0.2447, −0.3348, +0.0900]   （和 = 0 ✓）
PPL    = exp(0.4076) = 1.503
```

**PPL=exp(loss) 的来历**：整段损失是 $T$ 个位置的平均
$\mathcal{L} = \frac{1}{T}\sum_t(-\ln p_t)$，故

$$ \text{PPL} = e^{\mathcal{L}} = \left(\prod_{t=1}^{T} \frac{1}{p_t}\right)^{1/T} $$

即"每步真值 token 的逆概率"的**几何平均**——等效分支数。两条好用脑的
换算：loss 每降 $\ln 2 \approx 0.693$，PPL 恰好减半；PPL 从 20 降到 10
与从 10 降到 5 是"同样的进步"（对数尺度），在训练曲线上要看 log 轴。

**数值稳定：logsumexp 技巧**。直接算 $\log\sum e^{z_j}$ 在 $z$ 很大时溢出
（$e^{1000}=\infty$）。标准做法是先减最大值 $m=\max_j z_j$：

$$ \log\sum_j e^{z_j} = m + \log\sum_j e^{z_j - m} $$

减完后指数项都 $\le 1$，不会溢出；$m$ 在 log 外被加回，结果精确不变。
**这正是推理端 softmax 的同一技巧**——`ds_moe_decoder.c` 温度采样路径
`expf((logits[i] - max_logit) / temp)`、`ds_dash.c` 的 entmax15 阈值求解，
都靠"减 max"把数值钉在安全区。训练与推理共享同一个数值稳定范式。

> **一个真实教训**：Google DeepMind 2024 年发现主流框架（PyTorch/JAX）的
> softmax+CE 实现在极端 logits 下有精度 bug——减 max 之后仍可能因
> `log(1+ε)` 的抵消误差丢精度。这提醒我们：**数值稳定不是"减个 max 就完事"**，
> 而是要在目标硬件上实测边界情况（本工程 `test_unit` 的 `test_fast_expf`
> 与 `test_activations` 就是这类边界测试）。

### 5.2 权重共享：tied embeddings

词嵌入矩阵 $E$（`[V, d]`，本工程 `[129280, 1280]`）和输出投影
$W_{\text{lm\_head}}$（`[V, d]`）形状完全相同。**tied embeddings** 让二者
共享同一份权重：$W_{\text{lm\_head}} = E$。

- **省参数**：129280×1280 ≈ 1.66 亿参数，占 3B 模型的 5%+；共享直接省一半
- **正则化**：输入侧"词→向量"和输出侧"向量→词"用同一套语义空间，迫使
  嵌入空间自洽，通常带来小幅质量提升（Press & Wolf, 2017）
- **推理端体现**：`ds_moe_decoder.c` 的 LM head 选择
  `dec->lm_head_bf16 ? dec->lm_head_bf16 : dec->tok_embeddings_bf16`——
  权重文件里没有独立 `lm_head` 时自动回退到词嵌入矩阵，这就是 tied 的运行时形态
- **本工程四模型实测**：safetensors 头部四个模型**都有独立的 `lm_head.weight`**
  （与 `model.embed_tokens.weight` 分开存储），即**都不共享**；
  `models/Unlimited-OCR{,-2}/config.json` 显式写着 `"tie_word_embeddings": false`，
  DeepSeek-OCR 系 config 无此键但权重文件同样带独立 lm_head——**是否共享是
  训练时的决定，推理端必须按权重文件实际内容判断，不能假设**

### 5.3 显存与数值的工程手段

- **AMP/BF16**：权重主拷贝 FP32 + 前向反向用 BF16。**这正是推理端
  `ds_bf16_simulate_python` 要模拟的东西**——训练在哪些点截断 BF16，
  推理端在相同点截断才能逐位对齐（Prefill 的 QKV/共享专家/final norm）
- **loss scaling**：FP16 动态范围窄（最大 65504），小梯度会下溢成 0。
  做法是先把 loss 乘一个大常数 $S$（如 65536）再反向，梯度同比放大后
  不溢出，更新前再除回 $S$。BF16 指数位与 FP32 相同（8 位），动态范围
  足够，**通常不需要 loss scaling**——这是 BF16 相对 FP16 的核心优势，
  也是本工程选 BF16 而非 FP16 存权重的深层原因（docs/09 §2.1）
- **梯度累积**：显存装不下 batch → 小批累积再 step，等效大 batch
- **梯度裁剪**：`g ← g · (clip_norm/‖g‖)`，防 loss 尖峰
- **梯度检查点（gradient checkpointing）**：前向时不保存中间激活，反向时
  重算——用 ~33% 额外计算换 O(√L) 的激活显存（L 为层数）。这是"训练
  大模型显存不够"的第一救命手段，与推理端的 KV cache 是同一类"用算力
  换显存"的权衡
- loss spike 处理：回滚到上一个 checkpoint 跳过问题数据

### 5.4 反向传播最小例子：两层标量网络手推梯度

§5.1 只推到 logits 的梯度 $\partial\mathcal{L}/\partial z$；训练真正要的是
**每个权重**的梯度。用一个最小的两层**标量**网络把链式法则从头走一遍
（无矩阵、无框架，每步可心算），走完再推广到矩阵形式。

网络：输入 $x$ → 权重 $w_1$ → 预激活 $a = w_1 x$ → ReLU → 隐藏 $h$ →
权重 $w_2$ → 预测 $\hat y = w_2 h$ → 平方损失 $\mathcal{L} = \frac12(\hat y - t)^2$。

取 $x=2,\ w_1=0.5,\ w_2=3,\ t=1$。**前向**（推理引擎做的全部工作）：

```
a = w₁·x = 1.0        h = ReLU(a) = 1.0      ŷ = w₂·h = 3.0
L = ½(3.0 − 1)² = 2.0
```

**反向**（训练独有：从 loss 出发，沿计算图逐节点用链式法则往回乘）：

```
∂L/∂ŷ = ŷ − t = 2.0                          ← loss 对自己的输出
∂L/∂w₂ = ∂L/∂ŷ · ∂ŷ/∂w₂ = 2.0 · h = 2.0       ← ŷ = w₂·h，∂ŷ/∂w₂ = h
∂L/∂h  = ∂L/∂ŷ · ∂ŷ/∂h  = 2.0 · w₂ = 6.0      ← 误差折返回隐藏层
∂L/∂a  = ∂L/∂h · 1{a>0} = 6.0                 ← ReLU 的导数是指示函数
∂L/∂w₁ = ∂L/∂a · ∂a/∂w₁ = 6.0 · x = 12.0      ← a = w₁·x，∂a/∂w₁ = x
```

两条规则一目了然：**对权重的梯度 = 上游误差 × 该权重的前向输入**；
**对层输入的梯度 = 上游误差 × 该层的权重**——前者用来更新参数，后者
把误差继续送回上一层。更新一步（学习率 η=0.01）并验证：

```
w₁ ← 0.5 − 0.01×12 = 0.38      w₂ ← 3 − 0.01×2 = 2.98
重算前向：a = 0.76, h = 0.76, ŷ = 2.2648, L = ½(1.2648)² ≈ 0.80 < 2.0 ✓
```

**推广到矩阵形式**（13 篇 §1.2 有完整推导）：标量关系"权重梯度 =
误差 × 输入"在线性层 $y = Wx$ 上变成**外积**——
$dW = \text{dy}\cdot x^T$（$[\text{out},1]\times[1,\text{in}]$），
输入梯度 $dx = W^T\text{dy}$。一个 batch 的梯度是各样本外积之和：
$dW = \sum_t \text{dy}_t x_t^T = dY \cdot X^T$——§5.5 的梯度累积在数学上
正是分块做这个求和。**训练比推理多了什么**：每个前向节点值（$a, h$…）
都要留着喂反向（这就是"激活显存"的来源）、每个权重多一份 $dW$；
本仓库 `ds_moe_decoder.c` 的 `ds_decoder_forward` 执行的正是上面"前向"
那一行——推理引擎把它之后的三步（算 loss、反向、更新）整个裁掉了。

### 5.5 三笔工程账：梯度累积、梯度裁剪、混合精度

§5.3 一句话带过的三件套，各自的"显存/稳定性"账展开如下。

**梯度累积——省的是激活，不省状态**。显存装不下大 batch 时，把等效
batch $B_{\text{eff}} = B_{\text{micro}} \times \text{accum}$ 拆成 accum 次
小前向，每次 loss **除以 accum** 再 backward，梯度自然累加成大 batch 的
平均梯度（数学上就是 §5.4 的 $dW = dY\cdot X^T$ 分块求和）。能省的只有
**激活显存**（从 $B_{\text{eff}}$ 份降到 $B_{\text{micro}}$ 份）；梯度
（4B/参数）与 Adam 的 m/v（8B/参数）一分不省——它们按参数计，与 batch
无关。例：B_micro=2、accum=8 → B_eff=16，激活显存 1/8，优化器状态不变。
坑：micro-batch 内 loss 取了 mean，必须除以 accum 再加，否则等效 batch
越大梯度越被放大 accum 倍；本仓库的 RMSNorm 没有 cross-token 统计，
累积安全（BatchNorm 类层与累积不兼容）。

**梯度裁剪——只改步长、不改方向**。把全部参数梯度拼成向量 $g$，算全局
范数 $\|g\|_2 = \sqrt{\sum_i g_i^2}$，超阈值 $c$（典型 1.0）则
$g \leftarrow (c/\|g\|)\cdot g$。手算：$g = [3, 4]$，$\|g\| = 5$，
$c=1$ → $g' = [0.6, 0.8]$——方向不变，步长压到 1。防的是 loss 尖峰的
巨梯度把参数推飞（§15 表的"周期性尖峰"）；clip 在 Adam 的 m/v 更新
**之前**做，只影响当前步采到的梯度，不污染动量估计。

**混合精度——三份权重 + loss scaling 的边界**。BF16 混合精度的显存账：
FP32 主权重 4B（Adam 更新发生在这里，因为 BF16 每步 ~0.8% 相对误差
会累积）+ BF16 前向/反向工作拷贝 2B + FP32 梯度 4B + m/v 各 4B
= **18 B/参数**（§11 表的"16~20B"就落在这一格）。稳定性账：BF16 的
指数位与 FP32 相同（8 位），最小正常数 ~1e-38，梯度跨 1e-8~1e2 也
不会成片下溢——**所以 BF16 通常不需要 loss scaling**；FP16 最小正常数
~6e-5，小梯度下溢成 0，才需要先把 loss 乘 $S$（如 65536）再反向、更新
前除回。**为什么推理端关心这套布局**：`ds_bf16_simulate_python` 模拟的
"截断点"就是混合精度的算子边界——训练在哪些位置转 BF16，推理端在相同
位置转 BF16 才能逐位对齐（03 篇 §3）。

## 6. 优化器 AdamW 与学习率日程

AdamW = Adam + 解耦权重衰减（Loshchilov & Hutter, ICLR 2019）：

```
m ← β1·m + (1-β1)·g        一阶矩
v ← β2·v + (1-β2)·g²       二阶矩
θ ← θ - lr·m̂/(√v̂+ε) - lr·λ·θ
```

- lr 日程：warmup（前 ~1-2% 步线性升）→ 余弦/线性衰减到峰值的 ~10%
- 本工程没有任何训练代码，但 RoPE 的 `inv_freq`、norm 的 ε 这些常量
  与训练配置一一对应——改推理端这些值 = 换了一个模型

### 6.1 为什么 warmup 是必需的：Adam 的二阶矩冷启动

Adam 的更新量是 $\hat m/(\sqrt{\hat v}+\epsilon)$。训练第 1 步时 $v$ 只见过
一个梯度样本，$\sqrt{\hat v}$ 极小，导致更新量 $|\Delta\theta| \approx
\text{lr}\cdot\text{sign}(g)$——**步长被放大到 lr 量级，与梯度大小无关**。
若 lr 一开始就是峰值（如 3e-4），第一步就会把权重推离初始化很远，loss 直接
爆炸。warmup 让 lr 从 0 线性升到峰值，给 $v$ 足够多步累积到稳定估计。

**偏差修正（bias correction）**：$\hat m = m/(1-\beta_1^t)$、
$\hat v = v/(1-\beta_2^t)$——因为 $m,v$ 初始化为 0，前几步天然偏小，
除以 $(1-\beta^t)$ 把它拉回无偏估计。$\beta_2=0.999$ 时 $1-\beta_2^1=0.001$，
修正因子高达 1000 倍——**没有偏差修正，第一步的 $\sqrt{\hat v}$ 会小 31.6 倍**。

### 6.2 梯度噪声尺度与 critical batch size

**梯度噪声尺度（gradient noise scale）** 回答一个实践问题：**batch 该开多大？**
设单样本梯度为 $g_i$，batch 平均梯度 $g = \frac{1}{B}\sum_i g_i$，则

$$ \mathcal{B}_{\text{simple}} = \frac{\operatorname{tr}(\Sigma)}{\|g\|^2} $$

其中 $\Sigma$ 是单样本梯度的协方差。直觉：$\mathcal{B}_{\text{simple}}$ 是
"梯度信号与噪声相等"的 batch 大小。

**critical batch size**（McCandlish et al. 2018）：当 $B \ll \mathcal{B}$，
增大 batch 几乎线性减少所需步数（**算力换步数，划算**）；当 $B \gg \mathcal{B}$，
再增大 batch 几乎不减少步数（**纯浪费算力**）。所以最优 batch 在
$\mathcal{B}$ 附近。

**为什么推理工程师该知道**：它解释了"为什么大模型训练用几千的 batch"——
不是显存允许，而是 $\mathcal{B}$ 随模型规模增长。也解释了**为什么
learning rate 要随 batch 缩放**（线性缩放规则：$B$ 翻倍则 lr 翻倍），
因为更大的 batch 意味着更小的梯度噪声，需要更大的步长才能走同样距离。

**与本工程的间接联系**：训练时的 batch/lr 决定了权重的"平坦度"——大 batch
训出的模型往往更平坦（对量化/精度扰动更鲁棒），小 batch 训出的更尖锐
（对 BF16 截断点更敏感）。这解释了为什么某些模型对 `ds_bf16_simulate_python`
的开关特别敏感（docs/08 §9 的幻觉成因链）。

### 6.3 AdamW 手算 3 步（含 bias correction）

公式背得出不算懂，代数走三步。取单参数 $\theta = 1.0$、lr $=0.1$、
$\beta_1=0.9$、$\beta_2=0.999$、$\epsilon=10^{-8}$、先关掉 weight decay
（$\lambda=0$），三步的梯度读数 $g_1 = -2.0,\ g_2 = -0.5,\ g_3 = +0.5$
（第三步变号——典型的"接近最优点后开始震荡"）：

```
t=1:  m = 0.9×0    + 0.1×(−2)  = −0.200      v = 0.999×0      + 0.001×4   = 0.004000
      m̂ = −0.200/(1−0.9¹)   = −2.0000      v̂ = 0.004000/(1−0.999¹)  = 4.0000
      θ ← 1.0 − 0.1×(−2.0000/√4.0000) = 1.0 + 0.100 = 1.1000
                                                    ← 更新量恰为 lr·sign(g)

t=2:  m = 0.9×(−0.200) + 0.1×(−0.5) = −0.230     v = 0.999×0.004 + 0.001×0.25 = 0.004246
      m̂ = −0.230/(1−0.9²)   = −1.2105            v̂ = 0.004246/(1−0.998001) = 2.1241
      θ ← 1.1 − 0.1×(−1.2105/1.4574) = 1.1 + 0.0831 = 1.1831

t=3:  m = 0.9×(−0.230) + 0.1×0.5 = −0.157        v = 0.999×0.004246 + 0.001×0.25 = 0.0044918
      m̂ = −0.157/(1−0.9³)   = −0.5793            v̂ = 0.0044918/0.002997 = 1.4987
      θ ← 1.1831 − 0.1×(−0.5793/1.2242) = 1.1831 + 0.0473 = 1.2304
```

三个观察，每条都是 §6.1 论断的数值落地：

1. **第 1 步更新量 = lr·sign(g)**：$|\hat m/\sqrt{\hat v}| = 2/2 = 1$——
   这就是 warmup 必要性的根源。没有 bias correction 时 $\sqrt{v}$ 只有
   $\sqrt{0.004}=0.063$，修正因子 $1/\sqrt{1-\beta_2^1}$ 把它拉回 31.6 倍。
2. **动量压得住单步变号**：t=3 梯度已 +0.5，更新仍是 +0.047（θ 继续涨）
   ——m 是梯度的指数平均，一次变号被稀释；Adam 平滑，但"刹车慢"。
3. **自适应步长对梯度缩放不变**：g 从 2.0 缩到 0.5（4 倍），更新量只从
   0.100 缩到 0.083（1.2 倍）——把梯度整体乘 k，m̂ 与 √v̂ 同乘 k，比值
   不变。这是 Adam 与 SGD 的本质区别（§6.5）。

若开 weight decay（λ=0.1）：每步额外减 $\text{lr}\cdot\lambda\cdot\theta$，
t=1 即 0.1×0.1×1.0 = 0.01 → θ₁ = 1.09。注意这一项**不经过 m/v**——
这正是 §6.4 要讲的"解耦"。

### 6.4 weight decay 与 L2：在 SGD 里等价，在 Adam 里是两种算法

两个术语常被混用，因为**对 SGD 它们确实等价**：

```
SGD + L2 正则：  L' = L + (λ/2)‖θ‖²  → 梯度多一项 λθ
                 θ ← θ − lr·(g + λθ) = (1 − lr·λ)·θ − lr·g
SGD + 解耦衰减： θ ← θ − lr·g − lr·λ·θ = (1 − lr·λ)·θ − lr·g    完全相同
```

**在 Adam 里分道扬镳**。L2 版把 λθ 混进梯度 g，随后被自适应归一化
$\hat m/(\sqrt{\hat v}+\epsilon)$ 缩放——衰减量不再是 lr·λ·θ，而是被
1/√v̂ 扭曲的量：梯度大的参数（v̂ 大）衰减被**稀释**，梯度小的参数衰减
被**放大**。AdamW 版（§6.3 最后一项）把衰减放在归一化**之外**：每个
参数每步严格缩掉 lr·λ 比例，与该参数梯度大小无关。

数字感受一下：θ=1、λ=0.1、lr=0.1，标准衰减 0.01/步。若该参数此刻
梯度很大（√v̂≈100）：L2 版的有效衰减被稀释近两个量级；AdamW 恒为
0.01。LLM 里 embedding/lm_head 的梯度统计与 FFN 截然不同，**逐参数
均匀的衰减**让正则强度可预测——这是 LLM 清一色 AdamW 的直接原因
（原论文标题即 "Decoupled Weight Decay Regularization"）。

### 6.5 AdamW 与 SGD 的收敛差异：为什么 Transformer 训不动 SGD

SGD：$\theta \leftarrow \theta - \text{lr}\cdot g$——所有参数共享一个标量
步长，梯度尺度直接决定步幅。Adam：每参数一个归一化步长
$\hat m/(\sqrt{\hat v}+\epsilon)$（梯度平稳时约为 ±1 量级）→ 步长对梯度
**整体缩放不变**（§6.3 观察 3）。三个后果：

1. **病态曲率**：loss 面各维度曲率差几个量级是 LLM 的常态（embedding
   与 FFN 的梯度尺度差 10×+），SGD 只能取"最窄方向的安全步长"，在窄
   方向上反复震荡；Adam 每维各自归一，窄方向不震荡，可以走大步。
2. **稀疏梯度**：embedding 每步只更新出现过的 token 行（几十行/129280），
   SGD+momentum 下这些行的更新几乎停滞；Adam 的 v̂ 也只在被更新的步
   累积，稀疏行的步长不缩水。
3. **代价**：归一化抹掉了"梯度大 = 该方向更陡"的信息，且 v̂ 对突然增大
   的梯度反应滞后（√v̂ 还没涨上来 → 步长瞬间巨大）——这是 loss spike
   的常见来源，实践中靠 β₂∈[0.95, 0.999]、grad clip、warmup 三件套
   压制。经验规则：CNN 上 SGD+momentum 泛化常更好；Transformer/LLM
   上 AdamW 几乎不可替代。

### 6.6 学习率日程：cosine decay 的公式与关键点

完整日程 = warmup（§6.1）+ 衰减。最常用的 **cosine decay**：

$$ \text{lr}(t) = \text{lr}_{\min} + \frac{1}{2}\big(\text{lr}_{\text{peak}} - \text{lr}_{\min}\big)\left(1 + \cos\frac{\pi t}{T}\right), \qquad t \in [0, T] $$

T 为总步数。取 lr_min = 0（许多 LLM 取 0.1×peak）画几个点（相对峰值）：

```
t/T :  0      0.1     0.25    0.5     0.75    1.0
lr  :  1.00   0.976   0.854   0.500   0.146   0.00
```

前 1/4 只降到 85%——**大部分训练保持高 lr 粗勘探**；最后 1/4 快速下探
——**末期小 lr 让参数在窄谷里落底**（大 lr 时参数在谷壁间来回跳，loss
平台震荡；小 lr 后同一条曲线能再降一截）。这也是 §2 "退火阶段换精选
数据"的窗口所在：lr 最低的末端，喂进去的数据对最终权重的影响占比最大
——数据课程是和 lr 日程一起设计的。变体 WSD
（warmup-stable-decay）：平台保持 + 末端短衰减，为"随时可从中间
checkpoint 继续训或做模型裁剪"设计。§14 伪代码里
`warmup_then_cosine(peak=3e-4, min=3e-5, warmup=2000)` 就是工业默认形状。

## 7. 分布式并行：DP/TP/PP/ZeRO/FSDP

单卡装不下 3B 训练态（权重+梯度+优化器状态 ≈ 16 bytes/param ≈ 48GB+）：

| 并行 | 切什么 | 通信 |
|---|---|---|
| 数据并行 DP | batch | 梯度 all-reduce |
| ZeRO/FSDP | 参数/梯度/优化器状态分片 | 用时 all-gather |
| 张量并行 TP | 单层权重矩阵切（列切/行切） | 每层 2 次 all-reduce |
| 流水线 PP | 按层切，micro-batch 流水 | 点对点激活 |
| 专家并行 EP | MoE 专家分卡 | all-to-all（DeepSeek-MoE 必备）|

MoE 训练额外难题：负载均衡辅助损失（让路由别把流量全压给 2 个专家）
——推理端的路由阈值行为就是这个损失"训"出来的。

## 8. 训练基础设施与容错

## 11. 动手前先算账：算力与显存

先把"每参数 16~20 字节"的来历推出来。训练态下每个参数要同时住着四样
东西，默认各按 FP32 存：

| 组件 | 字节/参数 | 为什么 |
|---|---|---|
| 权重主拷贝 | 4B | Adam 的更新发生在 FP32（BF16 每步 ~0.8% 相对误差会跨步累积） |
| 梯度 | 4B | 反向输出，与权重同形状 |
| Adam 一阶矩 m | 4B | 梯度的指数平均，同形状 |
| Adam 二阶矩 v | 4B | 梯度**平方**的指数平均，量纲不同，不能与 m 合并 |

合计 **16 B/参数**；BF16 混合精度再加一份 BF16 前向拷贝 +2B；加上
workspace/临时缓冲，工程口径常说"每参数 16~20 字节"。代入 3B：

$$ 3\times10^{9} \times 16\,\text{B} = 48\,\text{GB}\quad(\text{权重+梯度+m+v，与 batch 大小无关}) $$

这 48GB 是"每参数固定开销"，§5.5 的梯度累积再大也压不下去。压它的
只有三条路：8-bit 优化器（m/v 各压到 1B → ~24GB，下表第 3 行）、
ZeRO/FSDP 分片（§7）、LoRA（12 篇 §3：不训练的参数不配拥有梯度与
m/v）。激活是另一笔（§5.5：随 batch×seq×层数增长，checkpointing 与
梯度累积管它）。

训练显存 ≈ 权重 + 梯度 + 优化器状态 + 激活：

| 精度 | 权重/参数 | AdamW 全态/参数 | 3B 模型全态 |
|---|---|---|---|
| FP32 | 4B | 16B | 48GB |
| BF16 混合 | 2B(+4B 主拷贝) | 16B | 48GB+ |
| BF16 + 8bit 优化器 | 2B | ~8B | ~24GB |

3B 模型单卡 80GB 只能勉强做全参训练（还要激活）——这就是 11 节并行术的由来。
**算力账**（Chinchilla 近似）：训练 FLOPs ≈ 6·N·D（N 参数、D token）。
3B×100B token ≈ 1.8e21 FLOP；一张 H100 有效 400 TFLOPS → 约 52 天。
所以"从零预训练"在单机上只现实于 0.1B 级——这是下面实战的规模选择。

## 13. 数据配方实例（0.5B 级实操配比）

以 1T token 目标为例的常见配方（OLMo/TinyLlama 风格）：

```
网页清洗(C4/FineWeb-Edu)   60-70%
代码(The Stack v2)         15-20%   ← 提升推理与结构化输出
数学(OpenWebMath/ProofPile) 5-10%   ← CoT 能力源头
百科/书籍/论文              10%      ← 知识密度
多语言                      按目标市场 5-30%
```

质量过滤流水线（FineWeb-Edu 公开配方）：启发式规则 → 教育价值小模型打分
→ 顶级样本上采样。**退火**：最后 ~5% token 换高质量配比+降 lr。

## 14. 训练循环伪代码（读懂框架的 30 行）

```python
model, optimizer = init(model_cfg, adamw(β1=0.9, β2=0.95, wd=0.1))
lr = warmup_then_cosine(peak=3e-4, min=3e-5, warmup=2000)
for step, batch in enumerate(dataloader):        # batch = 4M token 量级
    with autocast(bf16):                         # 前向 BF16（主权重 FP32）
        loss = cross_entropy(model(batch.input), batch.target)
    loss.backward()                              # 反向：BF16 计算，梯度 FP32
    clip_grad_norm_(model, 1.0)                  # 防尖峰
    if step % accum == accum-1:                  # 梯度累积凑大 batch
        optimizer.step(); optimizer.zero_grad()
    lr_scheduler.step()
    if step % 1000 == 0: async_checkpoint()      # 容错快照
```

调参手册：loss 爆炸 → 降 lr/查数据；loss 平台 → 查学习率日程与 batch 大小；
下游差但 loss 低 → 查数据配比与污染。

**与推理代码对照（本仓库）**：训练循环的骨架与 `ds_moe_decoder.c` 的
`ds_decoder_forward` 逐段对应——训练 = **同一个前向** + 推理没有的三步：

| 训练伪代码 | 本仓库对应 | 训练多算/多存的部分 |
|---|---|---|
| `with autocast(bf16): model(batch.input)` | `ds_decoder_forward`：embed → 12 × `decoder_layer_forward` → final norm → lm_head | 前向完全一致（同一数学、同一 BF16 截断点，03 篇 §3） |
| `cross_entropy(model(batch.input), target)` | 贪心 `ds_argmax_matvec_bf16`（流式 argmax）/ 采样路径 | 训练必须物化 [T, 129280] logits，对全词表算 loss 与梯度（§5.1） |
| `loss.backward()` | **不存在** | 每个权重一份 dW（§5.4 外积），每层前向激活留驻显存（§5.5） |
| `clip_grad_norm_ / optimizer.step()` | **不存在** | Adam 的 m、v 两份 FP32 数组随权重常驻（§11 的 48GB 大头） |
| ——（训练没有 KV cache） | `alloc_decoder_buffers` 预分配 KV，decode 逐步读写 | 训练一次前向看全句（序列维并行），无需缓存历史 |

一句话：**前向是训练与推理共享的 100% 重合段**（这就是为什么
`ds_bf16_simulate_python` 能逐位对齐训练框架）；KV cache 恰好是推理独有、
训练没有的东西——训练的"序列"在 batch 内并行展开，不需要缓存历史。

## 15. 训练监控与失败模式速查

| 现象 | 诊断 |
|---|---|
| 前 100 步 loss 不降 | lr 太小 / 数据打乱失败 |
| 周期性尖峰 | 数据坏 batch / 数值溢出（升 eps、降 lr） |
| loss 低但评测差 | 数据污染 / 配比失衡 |
| 无法过拟合 1 个 batch | 前向写错 / mask 泄漏 |

## 16. OCR 模型的预训练特殊性

多模态预训练 = 文本语料 + 图文对 + OCR 转写数据混合；视觉编码器
（SAM/CLIP）通常**冻结或低 lr**，主训 projector+解码器——这就是为什么
本仓库三模型的视觉侧权重是 F32（训练时被动的格式），解码器是 BF16。
DeepSeek-OCR 报告的"contexts optical mapping"：用 100~100 token 表示
~1000 文字 token，数据侧构造了高压缩比的"光学上下文"样本——**视觉压缩比
是数据课程设计出来的，不是网络白送的**。
