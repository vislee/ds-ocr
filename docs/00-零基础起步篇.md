## 1. 这个项目是什么（30 秒版）

**ds-ocr 是一个用纯 C 语言写的大模型推理引擎**。你喂给它一张图片（截图、文档照片、扫描页），它输出图片里的文字内容——这就是 **OCR**（Optical Character Recognition，光学字符识别）。

它不调用任何 Python、不依赖 PyTorch/TensorFlow，只靠 C 语言 + CPU 的矩阵运算指令，就能运行 DeepSeek-OCR / DeepSeek-OCR-2 / Unlimited-OCR / Unlimited-OCR-2 这四个开源多模态大模型（多模态 = 同时理解图像和文本）。

**为什么值得读它的源码？** 因为它把大模型推理的每一步都摊开在了你面前：

- 主流推理框架（vLLM、llama.cpp）代码量在几十万行级，初学者容易迷路
- ds-ocr 只有 **1.4 万行** C 代码，却实现了同样的核心机制：注意力、MoE、KV 缓存、量化、采样……
- 每一行都对应大模型的一个知识点，读完源码 = 把"大模型推理"这门课的公式全部用手写了一遍

这段历史本身就是一部"裂缝修补史"——书中每个古怪名词，最初都是为了修一个具体的问题：

| 裂缝（问题） | 发明的砖（技术） | 详见 |
|---|---|---|
| 机器不认识词，只认识数字 | 分词（token）与词向量（embedding） | 01、07 章 |
| 从左到右读会遗忘前文 | 注意力机制 | 01 章 |
| 摊开对读就丢了语序 | 位置编码（RoPE） | 01 章 |
| 全参数每次都参与计算太浪费 | MoE 混合专家 | 02 章 |
| 图片不是文字，怎么喂给语言模型 | 视觉编码器（SAM/CLIP/ViT） | 06 章 |
| 权重太大，搬不动 | 量化与 mmap | 03、09 章 |
| 接龙会结巴、复读、胡编 | 采样策略与后处理 | 08 章 |
| 一页图 4096 个"字"太贵 | 视觉 token 压缩、动态裁剪 | 06 章 |

> ** companion 项目**：[qwen-asr](https://github.com/antirez/qwen-asr)（antirez 的语音识别推理引擎）是本项目的架构参照。两者读其一，另一个便触类旁通。

## 2. 最小数学包

全书只用到下面四个概念。每个都只用一句话+一个例子讲清，不需要线代基础。

### 2.1 向量：一串数字

**向量**就是按顺序排列的一串数字。`[1.0, -0.5, 0.3]` 是一个 3 维向量。大模型里，一个"词"或"图像小块"都被表示成向量——比如 1280 维的向量。**维度**就是向量里数字的个数。

> 🗣️ **说人话**：向量就是一排带编号的储物格——"1280 维"不是说它有 1280 个格子装 1280 件不同的东西，而是说任何一个词、任何一块图像，最后都被登记成**同一规格**的 1280 个数，好让机器用同一套算盘处理所有输入。为什么要统一规格？因为下一步（§2.2 的点积）要求两个向量"格子数一样多"才能一一配对相乘——两个班人数不等就合不了班。所以 §2.1 那句"词和图像小块都被表示成向量"的实质是：**先把万物压成同一长度的一串数，后面所有运算才有统一的舞台**（01 章 §3 会看到 129,280 个词条每个都对应这样一行数）。
> *边界*："维度"只是"数字个数"，不对应任何现实单位——第 37 维不是"温度"、第 512 维不是"颜色"；每个维度本身没有独立含义，语义藏在整串数字的方向和距离里（01 章 §3.1）。

### 2.2 点积：两个向量有多"像"

**点积**（dot product）把两个同样长度的向量对应相乘再求和，得到一个数：

```
[1, 2, 3] · [4, 5, 6] = 1×4 + 2×5 + 3×6 = 4 + 10 + 18 = 32
```

直觉：两个向量方向越一致，点积越大；方向相反则点积为负。**注意力机制的全部魔力就建立在"点积衡量相似度"上**——第 5 章会看到，模型用点积判断"图像的这个位置和那个位置有多相关"。

在 ds-ocr 中，这个运算叫 `ds_dot_f32`，是整个引擎被调用次数最多的函数。

> 🗣️ **说人话**：相似不是长得像，而是"每一步都朝同一个方向使劲"——把两个向量想成两个人在同一组议题上投票：议题一是"要不要辣"，议题二是"要不要甜"。甲投 [+1, +1]（都要），乙投 [+1, +1]（都要），对应相乘再相加 = 2，分很高——他俩在每件事上态度一致。丙投 [+1, -1]（要辣不要甜），跟甲乘出来是 1×1 + 1×(-1) = 0，态度打平。丁投 [-1, -1]（跟甲完全反着来），乘出来是 -2，负分。所以 §2.2 那句"方向越一致点积越大"的实质是：**点积把"同向就加分、反向就扣分"这套投票规则，用一个乘法一次算完**。注意力机制就是让图上的每个位置跟其他位置这样互相投票，票多的（点积大的）就被多看一眼。
> *边界*：点积偏袒"数字大"的向量——[100, 100] 和 [1, 1] 点积是 200，但它们方向明明一样；所以要谈"相似"时原文那套通常会先把向量归一化成长度 1（余弦相似度），否则数值大的一方会霸占分数。

### 2.3 矩阵×向量：一次算一堆点积

**矩阵**是数字的表格（多行多列）。**矩阵×向量** = 矩阵的每一行分别与向量做点积，得到一列新数字：

```
[1  0] × [3]   [1×3 + 0×4]   [3]
[0  1]   [4] = [0×3 + 1×4] = [4]
[2  2]   [ ]   [2×3 + 2×4]   [14]
```

这就是神经网络的"计算"本体：**一层网络 = 一次矩阵×向量 + 一个简单的非线性函数**。ds-ocr 加载的 6GB `.safetensors` 文件里装的就是这些矩阵的数字（叫**权重**），推理就是让输入数据流过这些矩阵。

> 🗣️ **说人话**：矩阵×向量就是"一次问一堆问题"——矩阵的每一行是一张打分表，向量是考生答卷，逐行做点积（§2.2）就是逐行打分。上面例子里 3 行矩阵对答卷 [3,4] 打出 3、4、14 三个分：第三行 [2,2] 两门课都乘 2，说明这位"评委"对两门课一视同仁且加倍权重。ds-ocr 那 6.2GB 权重文件（§4.3 的 31 亿个参数）装的就是几万张这样的打分表，所谓"跑一次推理"就是让答卷挨个流过这些表。所以"一层网络 = 矩阵×向量 + 非线性"翻译成人话：**先按权重表集体打分，再把分数弯一弯**（"弯"见 §4.1）。
> *边界*：行数决定"一次打出几个分"，不改变打分规则本身——矩阵并不"理解"答卷内容，只是死板地按行乘加；换一份权重，同一行对同一答卷会打出完全不同的分，所以"智能"全在权重里，不在运算形式里。

### 2.4 概率分布：模型怎么"选字"

大模型每一步输出的不是文字，而是**词表里每个词的概率**。词表有 12.9 万个词条，模型输出 12.9 万个数，全部加起来等于 1——这叫**概率分布**。挑概率最大的那个词作为输出，叫**贪心解码**（greedy decoding，第 08 章详讲）。

把任意一堆数变成"加和为 1 的概率分布"的标准函数叫 **softmax**——你只需要知道它的作用，不需要会推导。

> 🗣️ **说人话**：softmax 不是"选一个"，而是"分一块蛋糕"——它只决定谁分几成，不负责挑人。§2.4 说模型输出 12.9 万个数、加起来等于 1。很多人误以为 softmax 在"选字"，其实它只干一件体力活：**把一桌乱七八糟的分数，换算成"每人切到多大一块蛋糕"**。比如三个词的原始打分是 [2, 3, 5]，softmax 先取指数（数学上为的是保证都变正、再拉开差距），得到大约 [7.4, 20.1, 148.4]，总和 175.9，于是分到 [4%、11%、84%]——打 5 分的那个独吞八成。注意"加起来等于 1"是换算后的结果，不是它一开始就有。至于要不要真把蛋糕递给那个 84% 的人，是 **§2.4 说的贪心解码**在管：softmax 只算概率，挑不挑是采样策略的事（第 08 章）。
> *边界*：原始打分里的"2、3、5"本身大小没有绝对意义，只有彼此差距有意义——把 [2,3,5] 整体平移成 [102,103,105]，softmax 出来的蛋糕一模一样（指数把公共偏移消掉了），所以别指望靠"分数绝对值"读出模型有多自信。

## 3. 机器学习 10 分钟：模型怎么"学"

后面两节讲"神经元"和"训练 vs 推理"，先把这两个词背后的**机器学习**框架一次立起来。深度学习是大模型的地基，也是全书所有训练章节（11/12 篇）的公共语言。

### 3.1 学习 = 从数据中自动找规律

机器学习的定义可以压成一句话：**不手写规则，从数据里自动归纳规律**。对比三种范式：

| 范式 | 输入 | 人的工作 | 例子 |
|---|---|---|---|
| 规则系统 | 专家写的 if-else | 写规则 | "句号后首字母大写" |
| 传统机器学习 | 数据 + **人设计的特征** | 挑特征、选模型 | 垃圾邮件过滤：人工定"含'中奖'次数"这个特征 |
| 深度学习 | 只有原始数据 | 设计网络结构 | 大模型：像素/文字直接进，特征自己长出来 |

深度学习省掉的正是最贵的环节——**特征工程**。"中奖"两个字可以换着花样写（"忄关井"），人工特征永远追不上；让网络自己从数据里长特征，才有了大模型。

> 🗣️ **说人话**：三种范式的差别就是"老师替学生做多少事"。规则系统：老师把每条规则写死，学生只管执行；传统机器学习：老师不出规则，但替学生挑好"该看哪些特征"（数一数含"中奖"几次）；深度学习：老师只给原始题海，连"该看什么"都让学生自己悟。§3.1 表格里最贵的人工环节是中间那列——挑特征。为什么人工特征必败？"中奖"能改写成"忄关井"、谐音、拆字，规则永远追不完；而网络自己长出来的特征，只要变体在数据里出现过，它自己就能把"这类字样很危险"学成某个向量方向。所以深度学习的实质是**把"看什么"也交给数据决定**（哪些还得人来定，见 §3.5 归纳偏置）。
> *边界*：省掉特征工程不等于省掉人——网络结构（几层、多宽、什么激活）仍要人设计，结构选错数据再多也学不动；"特征自己长"是 11 篇预训练章节（自监督、§3.2）才有的待遇，传统机器学习的"挑特征"环节在真实业务里今天也没消失。

### 3.2 监督/无监督/自监督：三种拿例题的方式

- **监督学习**：每道题带标准答案（标注）。"这张图里是猫"——标注贵，是监督学习的天花板。
- **无监督学习**：没有答案，只找数据内在结构（聚类、降维）。
- **自监督学习**：**从数据自己身上造答案**。大模型的核心把戏："The cat sat on the __"——把词遮住当答案，题目和答案都来自原始文本，一分钱标注不用花。预训练（11 篇）就是把这个完形填空游戏玩到几万亿 token 量级。

> 🗣️ **说人话**：自监督就是"题目和答案是从同一段文字里'掰'出来的，没人出钱标"——§3.2 把三种"拿例题"的方式列在一起，最容易混的是"自监督到底怎么白嫖答案"。打个比方：给你一篇没标点没人注释的文章，让你自己**在每个句子里挖一个洞**——"今天天气真___"，你挖掉"好"，原文剩下的字就自动成了答案。题目（挖空的句子）和答案（挖走的字）都从同一段文本里出，**一分钱标注费都不用花**，这就是自监督的核心把戏。它跟"无监督"的区别在这里：无监督连答案都没有、只找结构（比如把相似的文章聚成一堆）；自监督是"自己动手造出了答案"。预训练（11 篇）做的就是把这个挖洞游戏重复几万亿个 token。
> *边界*：白嫖的代价是"答案可能挖得没技术含量"——挖掉常见字比挖掉难字学得少，且挖洞这种玩法假设"上下文能推出答案"，碰上需要外部世界知识的填空（"中国首都是___"）就露怯，这也是后来要补指令微调的原因。

### 3.3 训练集/验证集/测试集：考试怎么出才公平

把数据分成三份，各司其职：

```
训练集（~90%）    验证集（~5%）      测试集（~5%）
做题、调旋钮      监控成绩、选超参    交卷前封存，最后只看一次
```

关键规则：**模型训练时永远见不到后两份**。只看训练成绩的教训：一个把训练语料背得滚瓜烂熟的学生，考场上遇到新题就崩——训练分高、考试分低。验证集就是"模拟考"：它告诉你改进是真能力还是背题；测试集必须像高考一样封存，反复"偷看"再改进，等于把测试集也练进了模型（大模型领域的"评测集污染"顽疾就是这么来的，11 篇 §9 会回看）。

> 🗣️ **说人话**：三份数据是三场考试，角色必须分开——训练集是平时作业（~90%，反复做、对着改），验证集是模拟考（~5%，看完分数决定要不要改复习策略），测试集是高考（~5%，封存到最后一刻、只拆封一次）。为什么高考必须封存？因为学生是"应付考试的鬼才"：你按哪份卷子改策略，他就把哪份卷子背进能力里——反复偷看测试集再改进，等于把高考题混进平时作业，分数全虚高。所以"训练时永远见不到后两份"不是道德要求，而是**让"考试分"这三个字还有意义的唯一办法**——这也是 §8.3 那张工程安全网（regress 脚本）背后的同一套纪律。
> *边界*：验证集用多了同样会"渗"——对它调几十次超参，它已间接影响了模型，严谨做法是换一个全新测试集复核；90/5/5 的比例也不是铁律，数据极少时连划分本身就是奢侈。

### 3.4 过拟合/欠拟合：学习的两种病

把 3.3 的"背题学生"变成术语：

- **过拟合（overfitting）**：训练分数高、新数据分数低——把训练集的噪声当规律背下来了。信号：训练 loss 继续降、验证 loss 开始升（两条曲线张开的"剪刀差"是训练监控里最重要的一张图，12 篇 §15 的第一行处方就是它）。
- **欠拟合（underfitting）**：两份都差——模型容量太小或训练不够，规律没学进去。

**泛化（generalization）** = 在没见过的数据上的表现，机器学习的唯一 KPI。对抗过拟合的手段统称**正则化**：weight decay（惩罚过大的权重，11 篇 §6.4）、dropout（训练时随机掐掉一部分神经元，逼模型不依赖任何单条通路）、早停（验证 loss 一升就停）、加数据。

**大模型的反直觉之处**：参数 31 亿 >> 数据里的"规律"数量，按经典理论必过拟合无疑——但大模型实际泛化极好。现代解释：海量数据 + 多轮不重复（每个参数见过的"题目"更多）改变了图景，"双下降"现象（模型大到一定程度，测试误差反而再降）至今没有完全定论——这是深度学习理论尚未攻克的深水区，读 11 篇时带着这个问号。

> 🗣️ **说人话**：过拟合是"背题"，欠拟合是"没学"。背题学生的破绽是两份成绩单打架：作业满分、模拟考砸——落到训练监控上，就是训练 loss 还在降、验证 loss 却开始升，两条曲线张开的"剪刀差"就是背题实锤（12 篇 §15 的第一行处方）。没学的学生是两份都差：题海没刷够，或脑子（模型容量）太小。对抗背题的手段统称正则化：weight decay 罚那些调得太狠的旋钮（11 篇 §6.4）、dropout 训练时随机让一部分神经元请假（逼模型不依赖单一思路）、早停见好就收。最反直觉的是末段那条：31 亿参数按经典理论必成背题巨兽，实际泛化极好——题海足够大、每道题不重样时，"背题"比"理解"还贵，这是理论没攻克的深水区。
> *边界*：正则化不是越强越好——weight decay 调过头会把模型压成欠拟合；"大模型泛化好"依赖海量数据这个前提，小数据配大参数照样标准过拟合，31 亿这个数字本身救不了它。

### 3.5 归纳偏置：没有免费的午餐

任何模型学得好，都因为它带着**对世界的预先假设**（归纳偏置，inductive bias）：CNN 假设"相邻像素相关"（所以卷积核在图上滑动）、RNN 假设"前文影响后文"、Transformer 的假设最少——**只假设"该关注谁由数据自己说了算"**。假设越贴合任务，需要的数据越少；假设越少，越通用但越吃数据。Transformer 用"少假设"换来通用性，代价就是必须喂海量数据——这就是"大力出奇迹"的理论注脚，也是视觉侧仍保留卷积/窗口假设的原因（06 篇 SAM 的窗口注意力，正是给纯注意力补回"局部相关"这个便宜假设）。

> 🗣️ **说人话**：归纳偏置就是"入学前自带的预习笔记"。CNN 的笔记写着"相邻的东西多半相关"（所以它敢拿小窗口扫图）；RNN 的写着"顺序很重要"；Transformer 的笔记几乎是白纸——只留一条"该关注谁，听数据的"。白纸的好处是限制少、什么任务都能学；代价是白纸学生必须靠海量题海才能悟出别人笔记里现成的常识。本仓库就是两条路线的混血：解码器走白纸路线，SAM 视觉编码器却保留卷积和 14×14 的窗口注意力（`DS_SAM_WINDOW_SIZE`，ds_ocr.h；06 篇细讲）——图像的"相邻像素相关"太便宜了，扔掉它纯靠数据补太浪费。所以"没有免费的午餐"的实质是：**假设押对了省数据、押错了伤通用，没有不带偏见的模型**。
> *边界*："白纸"不等于零假设——注意力本身仍假设"相似就该互相关注"（§2.2 的点积）；且"假设越少越通用"只在数据充足时成立，数据不够时一张写满的笔记反而救命。

## 4. 神经网络 10 分钟

在拆神经元之前，先花 60 秒交代"深度学习"在机器学习谱系里的位置——一部三幕剧。**第一幕·规则时代**（1950s–1980s）：语言学家手写规则，败给了"例外之外还有例外"——这正是 §3.1 说的"规则系统天花板"。**第二幕·统计时代**（1980s–2013）：不再问"这句话符合哪条语法"，改问"语料里这个说法出现过多少次"——频率取代规则（传统机器学习的代表）；但 n-gram 模型预测下一个词只看前两三个词，处理不了"主语在第 1 句、谓语照应在第 5 句"的长程结构。**第三幕·深度学习**：既不给规则也不限视野，给海量例题 + 一台有百万个可调旋钮的评分器，让"规则"自己从例子里长出来。神经网络就是那台评分器，本节拆它。

### 4.1 神经元：加权求和 + 非线性

一个"神经元"做两件事：①对输入做加权求和（就是 2.3 的矩阵×向量，权重是学出来的）；②过一个**非线性函数**（如 GELU/SiLU——把负数压向 0、正数基本保留的简单弯曲函数）。没有非线性函数，叠 100 层等价于 1 层，网络学不到复杂模式。

先看"叠 100 层等价于 1 层"为什么成立。若每层只做线性变换（§2.3 的矩阵×向量），三层连算是 W₃(W₂(W₁x))——矩阵乘法满足结合律，先算 W₃W₂W₁ 得到一个新矩阵 W，y = Wx，无论叠多少层都被一个矩阵吃掉：层数白叠，能力上限仍是"一次打分"。非线性的作用是在每层之间打断这种"可合并性"——GELU/SiLU 把负数压向 0、正数基本放行（01 章 §7.2、§7.3），每夹一层弯折，后面的矩阵就只能作用在"弯过的结果"上，再也无法合并成一个 W。这在代码里可以直接对照：`ds_kernels.c` 的 `ds_linear_nobias_bf16` 只做一次矩阵乘加，而 `ds_moe_decoder.c` 的 `decoder_layer_forward` 必须在两次线性层之间插入 `ds_swiglu_multiply`（SwiGLU 非线性，01 章 §7.3）——少了这一步，12 层就真的塌成 1 层了。

> 🗣️ **说人话**：神经元 = 先加权打分、再把分数弯一弯。加权求和就是 §2.3 的矩阵×向量（评委按权重表打分）；非线性函数像一根"只能折、不能拉直的尺子"，把分数压一压（GELU/SiLU 让负数趋 0、正数照旧）。为什么非要弯这一下？上面推导说了：不弯，100 层会被合并成 1 层。所以 §4.1 那句"没有非线性就学不到复杂模式"的实质是：**线性负责"打多少分"，非线性负责"让多层打分不能被一层替代"**——深度从此才有意义。
> *边界*：弯曲不是越狠越好——ReLU 类硬截断在零点不可导，太陡的非线性会让训练梯度断流；现代模型偏爱 GELU/SiLU 这类"缓弯"（01 章 §7.3 的 SwiGLU 门控是在这个弯上再加一道逐通道阀门）。

### 4.2 层与深度

神经元组成**层**，层叠层构成"深度"网络。ds-ocr 的解码器有 **12 层**，每层包含：

```
输入 → [注意力：位置之间交换信息] → [前馈网络：逐位置加工] → 输出
```

> 🗣️ **说人话**：一层 = "开一场圆桌会 + 各自回去消化"：注意力让各向量互相通气（谁跟谁相关），FFN 让每个向量独自加工（把听来的信息变成自己的结论），正是代码块里那两段流水线。ds-ocr 解码器把这套流程重复 12 层（`DS_DEC_LAYERS`，ds_ocr.h），为什么 12 层就够 OCR？因为"看图说话"的语义层级远比写长文浅——浅层拼局部特征，深层拼版面与语义。层数也不是越多越好：每层都要付注意力的 n² 交互账（01 章 §1.2）与 FFN 参数账（02 章，第 1~11 层的 FFN 还是 64 专家的 MoE）。所以"深度"的实质：**同一套"开会+消化"动作，重复做就能一层层提炼出更抽象的表示**。
> *边界*："深度 = 智能"只是经验规律——层数翻倍未必更强，还得配数据量与训练技巧；12 层是 31 亿参数、6.2GB 权重这个具体配置下的产物，换个规模答案就变（02 章 §6.1 的参数表）。

### 4.3 参数量：6GB 是什么概念

权重矩阵里所有数字的个数 = **参数量**。BF16 存储（每个数字 2 字节）下 6.2GB 文件 ≈ 31 亿参数——其中大部分是专家网络（第 02 章讲 MoE）。**推理 = 只做前向计算**，不更新这些数字。

> 🗣️ **说人话**：6GB 不是"数据多大"，而是"旋钮有几颗"——§4.3 那句"6.2GB ≈ 31 亿参数"，很多人卡在"参数"到底指什么。把它想成一台有 31 亿颗旋钮的收音机：每颗旋钮存一个小数（就是 §2.3 说的权重），调频靠的是把所有旋钮一起掰到特定位置。为什么 31 亿颗？因为 31 亿 × 2 字节 = 6.2GB——**文件大小 ÷ 每颗旋钮占的字节数，就是旋钮总数**（BF16 每颗 2 字节）。而 §5 说的"推理不写权重"，翻译成人话就是：上考场时这 31 亿颗旋钮全被焊死，一个都不许再拧，输入进来只是顺着固定的旋钮走一遍。
> *边界*：旋钮数 ≠ 每次运行都要挨个拧——MoE 结构（第 02 章）让一次前向只用得上一部分旋钮（64 个专家里挑 top-6），所以"31 亿参数"是"库存总数"，不等于"每次计算量"，两者差好几倍。

### 4.4 多模态：图片怎么变成"词"

ds-ocr 先把图片切成 16×16 像素的小块（patch），每个小块经过视觉编码器变成一个向量——于是"一张图"变成了几百个"视觉词"，后面接的文本解码器像处理文字一样处理它们（第 06 章详讲）。

## 5. 训练 vs 推理

先用一句最直白的话把两者分开：**训练是"在学校学习"，推理是"上考场"**。学校阶段（训练），模型对着海量"完形填空题"反复作答，每答错一点，就把几百万个可调的旋钮（权重）往"更对的答案"方向拧一点——这叫**调参**；上考场阶段（推理），所有旋钮**焊死不动**，题目（一张图 + 一条指令）进来，模型顺着这些焊死的旋钮把答案算出来。本仓库只做"上考场"：`ds_recognize_image()`（ds_ocr.c）从头到尾只**读**权重、从不**写**权重。

| | 训练（第 11、12 章） | 推理（本书主线） |
|---|---|---|
| 目的 | 学出权重 | 用权重出结果 |
| 计算方向 | 前向 + 反向传播更新权重 | 只前向 |
| 硬件需求 | 通常要 GPU 集群 | 一台笔记本 CPU 即可（本项目） |
| 本项目是否涉及 | 否（只加载现成权重） | 是 |

**本书全部 16 篇的主线是推理**：权重已经训练好了（下载即可），我们研究的是"怎么在 CPU 上把它跑得又准又快"。

> 💡 **一点思想史**：机器的"学习"不含"领悟"——它只会算当前输出、算错误的坡度，然后往坡低的方向拧旋钮（梯度下降：水往低处流）。这等于把经验主义认识论工程化：不预设范畴，只靠反复归纳修正。能力不是设计出来的，是试错统计的沉淀——第 11 章会看到这个事实的训练侧细节。

## 6. 一个张量的一生

> **张量**（tensor）就是多维数组：一维叫向量，二维叫矩阵，更多维统称张量。本节跟着一份真实数据走完全程——你喂给 `./ds_ocr -i 截图.png` 的那张 1794×1578 的截图，从像素变成文字的**每一步形状变化**，以及"这一步发生在哪个源文件的哪个函数"。先不求懂每一步的原理（后续章节会逐个拆），只求记住"数据依次变成什么"。

以 V1（DeepSeek-OCR，单张全局图）为例，完整旅程如下：

| # | 数据变成了什么 | 形状（例子） | 在哪个函数 |
|---|---|---|---|
| ① | PNG/JPEG 文件解码成 RGB 像素（0~255 整数） | 1794×1578×3 ≈ 845 万个数 | `ds_load_image()`（ds_image.c，底层是 stb_image.h） |
| ② | 四边补灰边成方形（训练时模型只见过方图） | 1024×1024×3 | `ds_visual_tokenizer_forward()` 内调 `ds_image_pad()`（ds_visual_tokenizer.c / ds_image.c） |
| ③ | 整数→浮点（0~1），行优先转通道优先 | [3, 1024, 1024] | `ds_image_to_float_chw()`（ds_image.c） |
| ④ | 切成 16×16 像素小块，每块线性投影成一个向量（**patch embedding**） | [4096, 768]（64×64 个块） | `sam_patch_embed()`（ds_visual_tokenizer.c） |
| ⑤ | SAM ViT-B 12 层加工：8 层窗口注意力 + 4 层全局注意力，形状不变 | [4096, 768] | `sam_layer_forward()`（内部走 `window_attn_forward()` 等，ds_visual_tokenizer.c） |
| ⑥ | neck 收通道：768→256 | [256, 64, 64] | `sam_neck_forward()`（ds_visual_tokenizer.c） |
| ⑦ | 两次 stride=2 卷积做 4× 空间压缩：64×64→32×32→16×16，通道升到 1024 | [1024, 16, 16]，即 **256 个视觉 token** | `sam_downsample_forward()`（ds_visual_tokenizer.c） |
| ⑧ | CLIP 再编码一遍 + 与 SAM 特征拼接 + 线性投影到解码器维度 | [256,1024]⊕[256,1024]→[256,2048]→**[256,1280]** | `ds_clip_encoder_forward()`（内部调 `ds_linear()` 做 projector，ds_deep_encoder.c） |
| ⑨ | 每 16 个 token 后插入一个换行向量、末尾加分隔向量（保住版面行结构） | 16×17+1 = **273 个 token** | 同上（`ds_clip_encoder_forward()` 尾部的 newline 插入） |
| ⑩ | 文本指令分词、查 embedding 表，与视觉向量拼成一条序列 | [≈281, 1280]（273 图 + BOS + 指令） | `ds_recognize_image()`（ds_ocr.c）+ `ds_tokenizer_encode()`（ds_tokenizer.c） |
| ⑪ | **prefill**：整段一次批量矩阵乘，算出每个位置的 K/V 存进缓存，并读出第一个输出字的概率 | KV cache ≈ [12 层, 281, 2×1280] | `ds_decoder_prefill()`（ds_moe_decoder.c） |
| ⑫ | **decode**：循环逐字生成，每步一次矩阵×向量 + top-6 专家挑选，输出 129280 维概率 | 每步 [1,1280]→[129280] | `ds_decoder_forward()` 循环内 `decoder_layer_forward()` + `moe_forward()`（ds_moe_decoder.c） |
| ⑬ | token 编号反查回文字（含后处理清理标签） | 字符串 | `ds_tokenizer_decode()`（ds_tokenizer.c）+ ds_ocr.c 后处理 |

一张图看压缩全过程（数字为 1024² 全局图）：

```
像素          patches       SAM 加工      卷积压缩       投影对齐      token 序列
3.1M ──▶ 4096×768 ──▶ 4096×768 ──▶ 256×1024 ──▶ 256×1280 ──▶ 273×1280
 floats   (64×64 块)   (形状不变)    (16×16 网格)  (projector)  (+newline +文本≈8)
                                                                    │
                              输出文字 ◀── 逐 token 解码 ◀── prefill ─┘
```

三个值得停留的观察：

1. **"图变词"发生在第⑦步**：64×64 的 patch 网格被两次卷积压成 16×16——4096 个块压成 256 个"视觉词"，加上行分隔共 273 个。845 万个像素数最终只剩 273×1280 ≈ 35 万个浮点数（约 1.4 MB），这就是 [10-论文导读与进阶路线篇](./10-论文导读与进阶路线篇.md) 里"上下文光学会压缩"的字面含义。
2. **视觉 token 和文字 token 在第⑩步才汇合**，且汇合后解码器**一视同仁**——对注意力来说它们都是"1280 维向量序列"，只是来源不同。
3. **prefill 与 decode 的分野在第⑪/⑫步**：prefill 一次算 281 个位置（批量矩阵乘，算力富裕），decode 每次只算 1 个新位置（矩阵×向量，卡在内存带宽）——这条分界线贯穿全书（03 章第 6 节、09 章第 1 节都在算这笔账）。

> 🗣️ **说人话**：上面那张 ①→⑬ 的表，一列数字变来变去最劝退——一句话记住：**换的是"装箱方式"，不是"内容"**。给个统一直觉：形状变化绝大多数只是"把同一批数重新装箱"，数本身没变。看清两类：一类是**纯搬运**——③的 [3,1024,1024] 到 ④ 的 [4096,768]，1024×1024 个像素点被 16×16 切成 64×64=4096 块、每块 256 个像素展平成一行乘 3 通道，数还是那 300 万个，只是从"按行摆"改成"按块摆"。另一类是**真压缩**——⑦把 64×64 的块网格用两次卷积塌成 16×16（每个数都换成了新的加权和），4096 个视觉块只剩 256 个"视觉词"，845 万个数最终变成约 273×1280 ≈ 35 万个数（见上面观察一）。分不清这两种，就会以为每一步都在"丢信息"。
> *边界*：搬运不等于没有代价——③那步行优先转通道优先（HWC→CHW）看着无损，但它把"同一通道的像素"在内存里聚到一起，正是后面矩阵乘能快的物理前提；装箱方式选错，结果对但速度垮，这也是本书反复较劲内存布局的原因（03 章）。

V2/V3/V4 的差异也都能落到这张表上：V2 把 ④–⑧ 换成 DeepEncoder V2（`ds_encoder_forward_v2()`，ds_deep_encoder.c）；V3/V4 视觉侧同 V1，差异在 ⑫ 的注意力方案（R-SWA / DASH，见 14 章）。

## 7. 环境搭建

### 7.1 你需要

- macOS（推荐，M 系列芯片有加速指令）或 Linux；Windows 用 WSL2
- Xcode 命令行工具（macOS：`xcode-select --install`）或 gcc/make（Linux：`sudo apt install build-essential`）
- 约 30GB 磁盘（四个模型的权重各 ~6.2GB）

### 7.2 三步跑通

```bash
# 1. 克隆仓库
git clone https://github.com/vislee/ds-ocr
cd ds-ocr

# 2. 编译（macOS 自动启用 Accelerate 框架 + Metal）
make blas

# 3. 下载一个模型并识别（以 DeepSeek-OCR 为例）
./download_model.sh          # 交互选择模型；或直接跑 ./models 下已有的
./ds_ocr -d ./models/DeepSeek-OCR -i ./test截屏.png
```

看到输出 markdown 或结构化文本，恭喜——你已经完成了一次完整的大模型推理。四条常用命令：

```bash
./ds_ocr -d ./models/DeepSeek-OCR   -i 图.png   # V1
./ds_ocr -d ./models/DeepSeek-OCR-2 -i 图.png   # V2
./ds_ocr -d ./models/Unlimited-OCR  -i 图.png   # V3
./ds_ocr -d ./models/Unlimited-OCR-2 -i 图.png  # V4（DASH 块稀疏注意力，第 14 章）
./ds_ocr -d ./models/DeepSeek-OCR -i 图.png --profile   # 输出各阶段耗时
```

> 🗣️ **说人话**：这三步分别是"领菜谱、开火、点菜"。`git clone` 把源码领回家；`make blas` 是让编译器把 C 代码翻译成你这台机器的原生指令——macOS 上自动接上 Accelerate/Metal（矩阵乘走系统调优实现），所以第一次编译要等一会儿；第三步最值得停下来想：`./ds_ocr` 首次运行要把 6.2GB 权重从磁盘"安家"，加载比识别还慢（§7.3 提示用 `--stream` 摊薄这笔一次性开销），之后真正识别一张图反而只要几秒。所以"跑通"这个动作本身就演示了推理引擎的两笔开销：**一次性把 31 亿参数读进内存（慢），之后每次推理只是顺着它们算（快）**——03 章的 mmap 优化的正是第一笔。
> *边界*：加载慢不代表识别慢，两者瓶颈不同（磁盘 I/O vs CPU 计算）；`make blas` 依赖系统 BLAS 环境（§7.1 的 build-essential），第三步报错时先查依赖装没装，别急着怀疑模型文件。

### 7.3 批量页与交互模式（进阶，可跳过）

```bash
# PDF 直接当输入：逐页渲染、逐页识别，输出按页拼接
./ds_ocr -d ./models/Unlimited-OCR-2 -i 文档.pdf

# 交互模式（REPL）：模型只加载一次，适合批量试图
./ds_ocr -d ./models/Unlimited-OCR-2 --stream
#   提示符下每行输入 @路径/图.png 识别一张（也支持 PDF），
#   Ctrl-D 或 q 退出。--silent 时提示符走 stderr，stdout 只有识别文本，
#   可以 2>/dev/null 重定向出干净结果。
```

第一次跑模型要读几个 GB 权重，加载时间比识别还长；多张图就用
`--stream` 摊薄它。想给脚本喂一目录图片，`for f in *.png; do ... done`
包一层即可。

### 7.4 两个随手可做的实验

```bash
# 看每个阶段花多久（编码/预填充/解码）
./ds_ocr -d ./models/DeepSeek-OCR -i test截屏.png --profile

# 跑回归测试：30 个"图片↔正确文本"组合，验证引擎没被改坏
bash tools/regress.sh
```

> 🗣️ **说人话**：这两条命令是给引擎"体检"和"验伤"。`--profile` 把一次识别拆成编码/预填充/解码三段计时——你会看到 decode 占大头且吐字速度稳定，这正是 §6 观察三说的"prefill 批量、decode 逐字"两条路径的不同性格；`tools/regress.sh` 则拿着 30 组"图片↔标准答案"逐字核对，红了就是改动把引擎改坏了。别把它们当可选装饰：**profile 回答"哪里慢"，regress 回答"还准不准"**——第 05 章每个性能优化的提交，都是这两张体检单一起看（§8.3 的安全网）。
> *边界*：profile 的耗时是"这台机器此刻"的数字，换机器、换后台负载都会变，别拿它当绝对基准；regress 只保 30 个组合逐字一致，绿了不等于任意输入都无损，覆盖面之外仍要人工抽查。

## 8. 怎么读这个 C 项目

### 8.1 文件地图

```
main.c                  程序入口：解析命令行 → 调 ds_load → ds_recognize
ds_ocr.c/h              总指挥：加载权重、构建输入、循环解码、后处理
ds_safetensors.c/h      权重读取器：mmap 零拷贝读 .safetensors
ds_image.c/h            图像加载与切分（stb_image）
ds_visual_tokenizer.c/h 视觉编码器：SAM + 卷积下采样（图片→视觉词）
ds_deep_encoder.c/h     DeepEncoder：SAM 特征与 CLIP 的混合编码
ds_moe_decoder.c/h      MoE 解码器：12 层、64 专家、逐 token 生成
ds_kernels.c/h + _impl.h + _neon/_generic/_avx.c   数学内核与平台分发
ds_tokenizer.c/h        BPE 分词器（文本↔token id）
ds_dash.c/h             V4 专用：DASH 块稀疏注意力（第 14 章）
ds_quantize.c/h         INT4/INT8 量化
tools/regress.sh        30 组合精度回归（改代码后必跑）
test_unit.c             单元测试（make coverage 看覆盖率）
docs/                   本书
```

> 🗣️ **说人话**：读这张地图的方法是"一个文件 = 一个器官"：main.c 是嘴（收命令行），ds_ocr.c 是大脑（总指挥），ds_visual_tokenizer.c / ds_deep_encoder.c 是眼睛（把图变成 256 个视觉词，§6 张量一生的第④–⑧步），ds_moe_decoder.c 是语言中枢（12 层、64 专家逐字吐字），ds_kernels.c 是肌肉（所有乘加都在这里出力），ds_safetensors.c 是肠道（吸收 6.2GB 权重）。整只"动物"只有 1.4 万行 C（§1），每个器官薄到能一次读完。先读哪个不迷路，就是下一节 §8.2 的路线。
> *边界*：地图省略了变体细节——ds_dash.c 只在 V4 生效、ds_quantize.c 是第 09 章的可选路径、`_neon/_avx/_generic` 三个平台内核文件也没展开；文件名相近不代表能互相替代，ds_visual_tokenizer.c 与 ds_deep_encoder.c 是串联的两级编码，不是重复实现。

### 8.2 建议的第一条阅读路线

1. `main.c` 的 `main()`——只有 300 行，看完知道一次识别的完整步骤
2. `ds_ocr.c` 的 `ds_recognize_image()`——输入怎么构造
3. `ds_moe_decoder.c` 的 `decoder_layer_forward()`——一层解码器长什么样
4. 带着问题跳读本书对应章节

> 🗣️ **说人话**：这条路线是"先看戏、再看舞台机关"。第 1 站 main() 只有 300 行，相当于看一遍"点单→上菜"的全流程但不进后厨；第 2 站 ds_recognize_image() 看菜怎么配（输入怎么拼装，§6 张量一生表的第⑩步就落在这里）；第 3 站 decoder_layer_forward() 才进后厨看一道"层"怎么炒——注意力、FFN、残差一行行都在。**三站各回答一个问题：程序从哪进、数据怎么备、一层怎么算**；看完你会发现，全书的每一章都在给这三站里的某个词做注释。
> *边界*：第 3 站的单 token 路径不是全貌——prefill 走的是 `ds_decoder_prefill()` 的批量版本（01 章 §9.5、03 章），只读 decode 路径会误以为引擎只有一种算注意力的方式。

### 8.3 修改代码的安全网

```bash
bash tools/regress.sh      # 30 组合精度回归，红了说明改坏了
make coverage              # 单元测试 + 覆盖率报告
```

这是 §3 的过拟合诊断闭环：任何性能优化提交前，这两个命令必须绿——第 05 章的每一个优化都是这么验证的。

> 🗣️ **说人话**：安全网的两根绳子各管一件事：`tools/regress.sh` 管"准不准"（30 组图片↔答案逐字比对，一个字变了就报警），`make coverage` 管"每个函数有没有被测到"（覆盖率报告揪出裸奔的代码）。为什么改完必须跑？因为推理是逐 token 串行生成的——§4.3 里那 31 亿颗焊死的旋钮顺一遍出结果，任何微小的数值顺序改动都可能让后面的字全变。这其实就是 §3.3 考试纪律的工程翻版：**regress 是封存的"标准答案"，开发期间从不参与改进，改完交卷立刻知道分数**——05 章所有优化都靠这张网兜底。
> *边界*：安全网防"改坏"，不防"改错方向"——回归全绿只说明行为没变，不证明新优化更快（那要 §7.4 的 --profile），也不证明 30 组之外的图片类型仍然正确。
