## 1. 这个项目是什么（30 秒版）

**ds-ocr 是一个用纯 C 语言写的大模型推理引擎**。你喂给它一张图片（截图、文档照片、扫描页），它输出图片里的文字内容——这就是 **OCR**（Optical Character Recognition，光学字符识别）。

它不调用任何 Python、不依赖 PyTorch/TensorFlow，只靠 C 语言 + CPU 的矩阵运算指令，就能运行 DeepSeek-OCR / DeepSeek-OCR-2 / Unlimited-OCR / Unlimited-OCR-2 这四个开源多模态大模型（多模态 = 同时理解图像和文本）。

**为什么值得读它的源码？** 因为它把大模型推理的每一步都摊开在了你面前：

- 主流推理框架（vLLM、llama.cpp）代码量在几十万行级，初学者容易迷路
- ds-ocr 只有 **1.4 万行** C 代码，却实现了同样的核心机制：注意力、MoE、KV 缓存、量化、采样……
- 每一行都对应大模型的一个知识点，读完源码 = 把"大模型推理"这门课的公式全部用手写了一遍

> ** companion 项目**：[qwen-asr](https://github.com/antirez/qwen-asr)（antirez 的语音识别推理引擎）是本项目的架构参照。两者读其一，另一个便触类旁通。

## 2. 最小数学包

全书只用到下面四个概念。每个都只用一句话+一个例子讲清，不需要线代基础。

### 2.1 向量：一串数字

**向量**就是按顺序排列的一串数字。`[1.0, -0.5, 0.3]` 是一个 3 维向量。大模型里，一个"词"或"图像小块"都被表示成向量——比如 1280 维的向量。**维度**就是向量里数字的个数。

### 2.2 点积：两个向量有多"像"

**点积**（dot product）把两个同样长度的向量对应相乘再求和，得到一个数：

```
[1, 2, 3] · [4, 5, 6] = 1×4 + 2×5 + 3×6 = 4 + 10 + 18 = 32
```

直觉：两个向量方向越一致，点积越大；方向相反则点积为负。**注意力机制的全部魔力就建立在"点积衡量相似度"上**——第 5 章会看到，模型用点积判断"图像的这个位置和那个位置有多相关"。

在 ds-ocr 中，这个运算叫 `ds_dot_f32`，是整个引擎被调用次数最多的函数。

### 2.3 矩阵×向量：一次算一堆点积

**矩阵**是数字的表格（多行多列）。**矩阵×向量** = 矩阵的每一行分别与向量做点积，得到一列新数字：

```
[1  0] × [3]   [1×3 + 0×4]   [3]
[0  1]   [4] = [0×3 + 1×4] = [4]
[2  2]   [ ]   [2×3 + 2×4]   [14]
```

这就是神经网络的"计算"本体：**一层网络 = 一次矩阵×向量 + 一个简单的非线性函数**。ds-ocr 加载的 6GB `.safetensors` 文件里装的就是这些矩阵的数字（叫**权重**），推理就是让输入数据流过这些矩阵。

### 2.4 概率分布：模型怎么"选字"

大模型每一步输出的不是文字，而是**词表里每个词的概率**。词表有 12.9 万个词条，模型输出 12.9 万个数，全部加起来等于 1——这叫**概率分布**。挑概率最大的那个词作为输出，叫**贪心解码**（greedy decoding，第 08 章详讲）。

把任意一堆数变成"加和为 1 的概率分布"的标准函数叫 **softmax**——你只需要知道它的作用，不需要会推导。

## 3. 神经网络 10 分钟

### 3.1 神经元：加权求和 + 非线性

一个"神经元"做两件事：①对输入做加权求和（就是 2.3 的矩阵×向量，权重是学出来的）；②过一个**非线性函数**（如 GELU/SiLU——把负数压向 0、正数基本保留的简单弯曲函数）。没有非线性函数，叠 100 层等价于 1 层，网络学不到复杂模式。

### 3.2 层与深度

神经元组成**层**，层叠层构成"深度"网络。ds-ocr 的解码器有 **12 层**，每层包含：

```
输入 → [注意力：位置之间交换信息] → [前馈网络：逐位置加工] → 输出
```

### 3.3 参数量：6GB 是什么概念

权重矩阵里所有数字的个数 = **参数量**。BF16 存储（每个数字 2 字节）下 6.2GB 文件 ≈ 31 亿参数——其中大部分是专家网络（第 02 章讲 MoE）。**推理 = 只做前向计算**，不更新这些数字。

### 3.4 多模态：图片怎么变成"词"

ds-ocr 先把图片切成 14×14 像素的小块（patch），每个小块经过视觉编码器变成一个向量——于是"一张图"变成了几百个"视觉词"，后面接的文本解码器像处理文字一样处理它们（第 06 章详讲）。

## 4. 训练 vs 推理

| | 训练（第 11、12 章） | 推理（本书主线） |
|---|---|---|
| 目的 | 学出权重 | 用权重出结果 |
| 计算方向 | 前向 + 反向传播更新权重 | 只前向 |
| 硬件需求 | 通常要 GPU 集群 | 一台笔记本 CPU 即可（本项目） |
| 本项目是否涉及 | 否（只加载现成权重） | 是 |

**本书全部 15 篇的主线是推理**：权重已经训练好了（下载即可），我们研究的是"怎么在 CPU 上把它跑得又准又快"。

## 5. 环境搭建

### 5.1 你需要

- macOS（推荐，M 系列芯片有加速指令）或 Linux；Windows 用 WSL2
- Xcode 命令行工具（macOS：`xcode-select --install`）或 gcc/make（Linux：`sudo apt install build-essential`）
- 约 30GB 磁盘（四个模型的权重各 ~6.2GB）

### 5.2 三步跑通

```bash
# 1. 克隆仓库
git clone https://github.com/vislee/ds-ocr
cd ds-ocr

# 2. 编译（macOS 自动启用 Accelerate 框架 + Metal）
make blas

# 3. 下载一个模型并识别（以 DeepSeek-OCR 为例）
./download_model.sh          # 交互选择模型；或直接跑 ./models 下已有的
./ds_ocr -d ./models/DeepSeek-OCR -i ./test截屏.png
```

看到输出 markdown 或结构化文本，恭喜——你已经完成了一次完整的大模型推理。四条常用命令：

```bash
./ds_ocr -d ./models/DeepSeek-OCR   -i 图.png   # V1
./ds_ocr -d ./models/DeepSeek-OCR-2 -i 图.png   # V2
./ds_ocr -d ./models/Unlimited-OCR  -i 图.png   # V3
./ds_ocr -d ./models/Unlimited-OCR-2 -i 图.png  # V4（DASH 块稀疏注意力，第 14 章）
./ds_ocr -d ./models/DeepSeek-OCR -i 图.png --profile   # 输出各阶段耗时
```

### 5.3 两个随手可做的实验

```bash
# 看每个阶段花多久（编码/预填充/解码）
./ds_ocr -d ./models/DeepSeek-OCR -i test截屏.png --profile

# 跑回归测试：30 个"图片↔正确文本"组合，验证引擎没被改坏
bash tools/regress.sh
```

## 6. 怎么读这个 C 项目

### 6.1 文件地图

```
main.c                  程序入口：解析命令行 → 调 ds_load → ds_recognize
ds_ocr.c/h              总指挥：加载权重、构建输入、循环解码、后处理
ds_safetensors.c/h      权重读取器：mmap 零拷贝读 .safetensors
ds_image.c/h            图像加载与切分（stb_image）
ds_visual_tokenizer.c/h 视觉编码器：SAM + 卷积下采样（图片→视觉词）
ds_deep_encoder.c/h     DeepEncoder：SAM 特征与 CLIP 的混合编码
ds_moe_decoder.c/h      MoE 解码器：12 层、64 专家、逐 token 生成
ds_kernels.c/h + _impl.h + _neon/_generic/_avx.c   数学内核与平台分发
ds_tokenizer.c/h        BPE 分词器（文本↔token id）
ds_dash.c/h             V4 专用：DASH 块稀疏注意力（第 14 章）
ds_quantize.c/h         INT4/INT8 量化
tools/regress.sh        30 组合精度回归（改代码后必跑）
test_unit.c             单元测试（make coverage 看覆盖率）
docs/                   本书
```

### 6.2 建议的第一条阅读路线

1. `main.c` 的 `main()`——只有 300 行，看完知道一次识别的完整步骤
2. `ds_ocr.c` 的 `ds_recognize_image()`——输入怎么构造
3. `ds_moe_decoder.c` 的 `decoder_layer_forward()`——一层解码器长什么样
4. 带着问题跳读本书对应章节

### 6.3 修改代码的安全网

```bash
bash tools/regress.sh      # 30 组合精度回归，红了说明改坏了
make coverage              # 单元测试 + 覆盖率报告
```

任何性能优化提交前，这两个命令必须绿——第 05 章的每一个优化都是这么验证的。

## 7. 全书术语速查表

| 术语 | 一句话解释 | 详解 |
|------|-----------|------|
| token / 词元 | 模型处理的最小单位（词、字或子词），每个有编号 | 07 章 |
| 词表 | 所有 token 的编号表，本模型 12.9 万条 | 07 章 |
| 嵌入 / embedding | token 编号查表得到的向量 | 01 章 |
| 权重 / 参数 | 网络里学出来的矩阵数字，6.2GB 文件的本体 | 3.3 节 |
| 注意力 | 用点积衡量位置间相关性并交换信息的机制 | 01 章 |
| 多头 | 把注意力并行做 10 份，每份看不同的"角度" | 01 章 |
| MoE | 混合专家：每层 64 个子网络，按 token 挑 6 个用 | 02 章 |
| KV 缓存 | 已生成 token 的 Key/Value 存档，避免重复计算 | 03 章 |
| prefill / 预填充 | 一次算完整段输入的 KV 缓存 | 03 章 |
| decode / 解码 | 逐 token 生成，每步只算新 token | 03 章 |
| 采样 / 贪心 | 从概率分布里挑下一个词的策略 | 08 章 |
| RoPE | 旋转位置编码：用旋转角度表示"谁在谁前面" | 01 章 |
| BF16 | 16 位浮点：权重存储格式，1 位符号+8 位指数+7 位尾数 | 03 章 |
| INT4/INT8 | 用 4/8 位整数近似权重，省带宽 | 09 章 |
| R-SWA | V3 的注意力方案：参考集+滑动窗口 | 04 章 |
| DASH | V4 的注意力方案：块稀疏+页坐标（14 章专讲） | 14 章 |
| prefill token 计数 | 每页视觉 token 数，解码坐标状态机用它 | 14 章 |
