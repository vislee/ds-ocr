## 1. 后训练全景

```
预训练基座(续写机)
   ↓ SFT：万级~百万级 指令-回答对
会聊天的模型
   ↓ 偏好优化：RM + PPO / DPO / GRPO
对齐人类偏好的模型
   ↓ 安全对齐：安全SFT + 红队 + 拒绝训练
可部署模型
```

每个阶段都可能在评测集上"退化"预训练能力（alignment tax），
所以现代流程各阶段都要混入通用数据防遗忘。

## 2. SFT 监督微调：指令跟随的来源

- 数据：(指令, 回答) 对；人工撰写 + 强模型合成（self-instruct/蒸馏）
- 格式：**对话模板**（chat template）把多轮对话拼成一条序列，
  用特殊 token 标记角色边界——训练与推理必须用同一模板
- 只对回答部分算 loss（prompt 部分掩码）；packed 训练时注意
  attention 跨样本隔离
- 数据质量铁律：1k 条精心清洗的 SFT 数据可以打赢 10 万条脏数据
  （LIMA, Zhou et al., 2023, arXiv:2305.11206）

**与推理端的关系（本仓库实例）**：V3 的提示词 `document parsing.`
之所以能触发"解析模式"输出 det 标签，就是因为 SFT/继续预训练阶段
见过大量"<image> + 指令 → 结构化输出"样本；V1/V2 的
`Convert the document to markdown.` 同理。**模型的行为模式 =
预训练能力 × 后训练格式**，推理端的 prompt 就是在请求这些格式。

## 3. 参数高效微调：LoRA/QLoRA

全参微调 3B 模型要数十 GB 显存存优化器状态。LoRA 的洞察：

```
ΔW = B·A，其中 B∈R^{d×r}, A∈R^{r×k}，r ≪ d
前向: h = W₀x + (α/r)·BAx     A 初始化为零，B 高斯
```

只训练 B、A（r=8~64），可训练参数降 ~100×；QLoRA 再把 W₀ 冻结成
NF4 量化。本工程 3B-MoE 若要做垂直场景微调（如手写体），LoRA 到
attention 的 WQ/WO 上是最常见起点；推理端合并方式：`W = W₀ + BA`
后导出（或运行时双权重，本仓库未实现，可作为进阶课题）。

## 4. 偏好数据与奖励建模

- 收集同一 prompt 的多个回答 → 人类标注 y_w ≻ y_l（chosen vs rejected）
- **奖励模型 RM**：在 SFT 模型上改造，输出标量分；用 Bradley-Terry
  成对损失训练：`loss = -log σ(r(y_w) − r(y_l))`
- RM 的坑：偏好 hacking（长回答加分 → 模型变啰嗦）、分布外失效

## 5. RLHF/PPO：用强化学习对齐

PPO 四件套：actor（策略模型）、critic（价值模型）、RM、参考模型（KL 锚）：

```
objective = E[ r(y) ] − β·KL( π_θ ‖ π_ref )
```

KL 项防止策略为讨好 RM 而漂离语言分布（reward hacking）。
成本高：4 个大模型同时在显存里、超参敏感。推理端关联：PPO 之后的模型
EOS 时机、输出长度、格式稳定性都被改变——**本仓库 V3 的 min_new_tokens=32
这种推理补丁，本质是在补偿"对齐后 EOS 行为变化"**。

## 6. DPO 与 GRPO：绕开奖励模型的两条路

- **DPO**：从偏好对直接优化策略，数学上等价于带 KL 约束的 RLHF 目标，
  但把 RM 隐式吸收进策略本身：
  `loss = −log σ( β·[log π(y_w)/π_ref(y_w) − log π(y_l)/π_ref(y_l)] )`
  简单稳定，成为开源社区默认
- **GRPO**（DeepSeek 系）：去掉 critic，用同一问题的 G 个采样答案的
  组内相对优势做 baseline——特别适合**有可验证奖励**（数学答案对错、
  OCR 的编辑距离）的场景，是 R1 类推理模型的核心配方
- RLVR（可验证奖励 RL）：OCR 工程里的对应物——用"识别结果 vs GT 的
  编辑距离"当奖励微调视觉模型，是当前学术热点

## 7. 蒸馏：把大模型能力"练"进小模型

- 输出蒸馏：小模型学大模型的 token 分布（KL）；本工程 3B-MoE 若想再小，
  这是路线
- 数据蒸馏：用强模型生成 SFT 数据（弱标注员不可用时）；注意许可与
  污染问题
- DeepSeek-R1 报告展示了"R1 蒸馏到 1.5B~70B 稠密模型"的完整配方

## 8. 安全对齐：拒绝、红队、越狱与评测

- **安全 SFT**：把有害请求的规范拒绝写进训练数据；分类体系
  （暴力/欺诈/隐私/儿童…）+ 每类拒答话术
- **红队**：攻击者视角找漏洞——角色扮演、编码绕过、多轮诱导、
  模板注入（图片里的文字也是注入源！OCR 模型读图上的"ignore previous
  instructions"是真实风险）
- **越狱军火库**：DAN、前缀注入、低资源语言绕过——对齐是军备竞赛
- **Constitutional AI**（Anthropic）：用一组原则让模型自我批评改写，
  减少人工标注
- **评测**：拒绝率（过度拒绝也是 bug）、ToxiGen/TruthfulQA、
  越狱成功率；OCR 场景特有：**图片内容安全**（违禁文字识别该不该输出？）
  ——边界要产品定义
- 分布外的诚实性：OCR 的对应物是"图里没字时输出 [Non-Text]/EOS"，
  本仓库 V3 的 Non-Text 行为就是训练出来的"不知道就说不知道"

## 9. 本仓库的"后训练指纹"：推理端看到的一切

| 后训练痕迹 | 推理端表现/补丁 |
|---|---|
| 对话模板（plain，无角色标记） | prompt 只有 BOS+图像+指令文本 |
| 指令格式（document parsing / markdown） | prompt 文本切换模型行为模式 |
| grounding/结构化标签训练 | `<\|det\|>` 输出与清理流水线（08 篇） |
| EOS 对齐行为 | min_new_tokens=32、EOS+Ġ 抑制 |
| [Non-Text] 训练 | V3 小图空结果标记 |
| BF16 训练精度 | `ds_bf16_simulate_python` 对齐 |

理解这张表，就理解了"为什么推理引擎长这样"：**推理端一半的复杂度
在优化算力，另一半在补偿/利用后训练塑造的行为**。

## 10. 动手实验

1. 用 llama.cpp/OLLAMA 跑一个 1B 模型，对比其 base 版与 instruct 版对
   同一 prompt 的行为（体会 SFT 的作用）
2. 给本仓库造 20 条"手写数字图→文本"数据，思考若做 LoRA 微调，
   数据格式与 chat template 应该怎么定
3. 把 `min_new_tokens` 设 0/32/128 跑 V3 小图，观察 EOS 行为与幻觉的关系
4. 思考题：OCR 的"可验证奖励"是什么？如果给你 10 万张标注图做 GRPO，
   reward 函数怎么设计才不会 reward hacking？（提示：编辑距离之外，
   要防"输出空串/复读 GT 片段"的投机策略。）

---

**小结**：预训练给能力，后训练给行为。SFT 教格式、RLHF/DPO 教偏好、
安全对齐教边界；推理工程师每天打交道的 prompt 模板、EOS 行为、
结构化标签，全是这两个阶段的产物。至此 01→12 篇串成完整闭环：
**训练决定模型是什么，推理决定模型值多少。**
