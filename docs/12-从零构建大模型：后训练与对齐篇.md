## 1. 后训练全景

```
预训练基座(续写机)
   ↓ SFT：万级~百万级 指令-回答对
会聊天的模型
   ↓ 偏好优化：RM + PPO / DPO / GRPO
对齐人类偏好的模型
   ↓ 安全对齐：安全SFT + 红队 + 拒绝训练
可部署模型
```

每个阶段都可能在评测集上"退化"预训练能力（alignment tax），
所以现代流程各阶段都要混入通用数据防遗忘。

## 2. SFT 监督微调：指令跟随的来源

- 数据：(指令, 回答) 对；人工撰写 + 强模型合成（self-instruct/蒸馏）
- 格式：**对话模板**（chat template）把多轮对话拼成一条序列，
  用特殊 token 标记角色边界——训练与推理必须用同一模板
- 只对回答部分算 loss（prompt 部分掩码）；packed 训练时注意
  attention 跨样本隔离
- 数据质量铁律：1k 条精心清洗的 SFT 数据可以打赢 10 万条脏数据
  （LIMA, Zhou et al., 2023, arXiv:2305.11206）

**与推理端的关系（本仓库实例）**：V3 的提示词 `document parsing.`
之所以能触发"解析模式"输出 det 标签，就是因为 SFT/继续预训练阶段
见过大量"<image> + 指令 → 结构化输出"样本；V1/V2 的
`Convert the document to markdown.` 同理。**模型的行为模式 =
预训练能力 × 后训练格式**，推理端的 prompt 就是在请求这些格式。

## 3. 参数高效微调：LoRA/QLoRA

全参微调 3B 模型要数十 GB 显存存优化器状态。LoRA 的洞察：

```
ΔW = B·A，其中 B∈R^{d×r}, A∈R^{r×k}，r ≪ d
前向: h = W₀x + (α/r)·BAx     A 初始化为零，B 高斯
```

只训练 B、A（r=8~64），可训练参数降 ~100×；QLoRA 再把 W₀ 冻结成
NF4 量化。本工程 3B-MoE 若要做垂直场景微调（如手写体），LoRA 到
attention 的 WQ/WO 上是最常见起点；推理端合并方式：`W = W₀ + BA`
后导出（或运行时双权重，本仓库未实现，可作为进阶课题）。

## 4. 偏好数据与奖励建模

- 收集同一 prompt 的多个回答 → 人类标注 y_w ≻ y_l（chosen vs rejected）
- **奖励模型 RM**：在 SFT 模型上改造，输出标量分；用 Bradley-Terry
  成对损失训练：`loss = -log σ(r(y_w) − r(y_l))`
- RM 的坑：偏好 hacking（长回答加分 → 模型变啰嗦）、分布外失效

## 5. RLHF/PPO：用强化学习对齐

PPO 四件套：actor（策略模型）、critic（价值模型）、RM、参考模型（KL 锚）：

```
objective = E[ r(y) ] − β·KL( π_θ ‖ π_ref )
```

KL 项防止策略为讨好 RM 而漂离语言分布（reward hacking）。
成本高：4 个大模型同时在显存里、超参敏感。推理端关联：PPO 之后的模型
EOS 时机、输出长度、格式稳定性都被改变——**本仓库 V3 的 min_new_tokens=32
这种推理补丁，本质是在补偿"对齐后 EOS 行为变化"**。

## 6. DPO 与 GRPO：绕开奖励模型的两条路

- **DPO**：从偏好对直接优化策略，数学上等价于带 KL 约束的 RLHF 目标，
  但把 RM 隐式吸收进策略本身：
  `loss = −log σ( β·[log π(y_w)/π_ref(y_w) − log π(y_l)/π_ref(y_l)] )`
  简单稳定，成为开源社区默认
- **GRPO**（DeepSeek 系）：去掉 critic，用同一问题的 G 个采样答案的
  组内相对优势做 baseline——特别适合**有可验证奖励**（数学答案对错、
  OCR 的编辑距离）的场景，是 R1 类推理模型的核心配方
- RLVR（可验证奖励 RL）：OCR 工程里的对应物——用"识别结果 vs GT 的
  编辑距离"当奖励微调视觉模型，是当前学术热点

## 7. 蒸馏：把大模型能力"练"进小模型

- 输出蒸馏：小模型学大模型的 token 分布（KL）；本工程 3B-MoE 若想再小，
  这是路线
- 数据蒸馏：用强模型生成 SFT 数据（弱标注员不可用时）；注意许可与
  污染问题
- DeepSeek-R1 报告展示了"R1 蒸馏到 1.5B~70B 稠密模型"的完整配方

## 8. 安全对齐：拒绝、红队、越狱与评测

- **安全 SFT**：把有害请求的规范拒绝写进训练数据；分类体系
  （暴力/欺诈/隐私/儿童…）+ 每类拒答话术
- **红队**：攻击者视角找漏洞——角色扮演、编码绕过、多轮诱导、
  模板注入（图片里的文字也是注入源！OCR 模型读图上的"ignore previous
  instructions"是真实风险）
- **越狱军火库**：DAN、前缀注入、低资源语言绕过——对齐是军备竞赛
- **Constitutional AI**（Anthropic）：用一组原则让模型自我批评改写，
  减少人工标注
- **评测**：拒绝率（过度拒绝也是 bug）、ToxiGen/TruthfulQA、
  越狱成功率；OCR 场景特有：**图片内容安全**（违禁文字识别该不该输出？）
  ——边界要产品定义
- 分布外的诚实性：OCR 的对应物是"图里没字时输出 [Non-Text]/EOS"，
  本仓库 V3 的 Non-Text 行为就是训练出来的"不知道就说不知道"

## 9. 本仓库的"后训练指纹"：推理端看到的一切

| 后训练痕迹 | 推理端表现/补丁 |
|---|---|
| 对话模板（plain，无角色标记） | prompt 只有 BOS+图像+指令文本 |
| 指令格式（document parsing / markdown） | prompt 文本切换模型行为模式 |
| grounding/结构化标签训练 | `<\|det\|>` 输出与清理流水线（08 篇） |
| EOS 对齐行为 | min_new_tokens=32、EOS+Ġ 抑制 |
| [Non-Text] 训练 | V3 小图空结果标记 |
| BF16 训练精度 | `ds_bf16_simulate_python` 对齐 |

理解这张表，就理解了"为什么推理引擎长这样"：**推理端一半的复杂度
在优化算力，另一半在补偿/利用后训练塑造的行为**。

## 10. 动手实验

1. 用 llama.cpp/OLLAMA 跑一个 1B 模型，对比其 base 版与 instruct 版对
   同一 prompt 的行为（体会 SFT 的作用）
2. 给本仓库造 20 条"手写数字图→文本"数据，思考若做 LoRA 微调，
   数据格式与 chat template 应该怎么定
3. 把 `min_new_tokens` 设 0/32/128 跑 V3 小图，观察 EOS 行为与幻觉的关系
4. 思考题：OCR 的"可验证奖励"是什么？如果给你 10 万张标注图做 GRPO，
   reward 函数怎么设计才不会 reward hacking？（提示：编辑距离之外，
   要防"输出空串/复读 GT 片段"的投机策略。）

**小结**：预训练给能力，后训练给行为。SFT 教格式、RLHF/DPO 教偏好、
安全对齐教边界；推理工程师每天打交道的 prompt 模板、EOS 行为、
结构化标签，全是这两个阶段的产物。至此 01→12 篇串成完整闭环：
**训练决定模型是什么，推理决定模型值多少。**

# 实战篇：微调与强化学习的完整决策与操作手册

> 本章回答四个问题：**为什么要做？什么时候做？具体怎么做？做坏了怎么办？**
> 工具基线：HuggingFace TRL / LLaMA-Factory / Axolotl（社区三大主流）。

## 11. 决策框架：先问"要改什么"，再选手段

业界共识阶梯（每上一级成本翻数量级，先走低级）：

```
Prompt 工程 → RAG → SFT 微调 → RL 偏好优化 → 蒸馏
```

| 你的问题 | 手段 | 为什么 |
|---|---|---|
| 模型不知道新知识/私有知识 | **RAG** | 知识要**随时更新**，改输入不改权重 |
| 输出格式/风格/语言不对 | **SFT** | 这是**行为**问题，藏在权重里，prompt 压不住 |
| 领域术语/任务分布差异大 | **SFT** | 分布偏移只有梯度能修 |
| 两个回答"都对但一个好" | **偏好优化(DPO/RLHF)** | 无法写出标准答案时用**相对**信号 |
| 结果有客观对错但难写规则 | **RLVR/GRPO** | 可验证奖励是 RL 最稳的落点 |
| 要降本/降延迟 | **蒸馏** | 大模型当老师，小模型上岗 |

**一句话判据**：改"知道什么"用 RAG，改"怎么做"用 SFT，改"哪个更好"
用 RL，改"用多小的模型做"用蒸馏。最常见的错误是：知识问题去微调
（一更新就过时）、行为问题去堆 prompt（治标且吃上下文）。

## 12. 什么时候**不要**微调（血泪清单）

- 数据 < 几百条高质量样本：先 prompt + few-shot
- 需求每周在变：微调迭代周期跟不上
- 问题其实是检索/上下文长度：微调解决不了"没给材料"
- 幻觉：微调**不能**根除幻觉，只会让幻觉更像真的（知识注入靠 RAG/继续预训练）
- 拿不出评测集：没有 eval 的微调是盲飞，先建 100~500 条评测集再动手

## 13. SFT 完整实操（以本仓库 3B-MoE 解码器为例）

### 13.1 数据格式（对话模板）

```jsonl
{"messages": [
  {"role": "user", "content": "<image>document parsing."},
  {"role": "assistant", "content": "识别出的文本..."}]}
```

- 模板必须与推理端一致（本仓库 plain 模板：BOS+图像 token+指令文本）
- 只对 assistant 部分算 loss；几百~几万条即可见效（LIMA：1k 亦足）

### 13.2 LoRA 超参速查表（社区共识 + TRL/SFTTrainer 默认）

| 超参 | 推荐值 | 说明 |
|---|---|---|
| lora_rank r | 8（简单）/ 16-64（任务重） | 可训练参数 ≈ r×(d+k)×层数 |
| lora_alpha | 2×r | 等效缩放 α/r=2 |
| lora_dropout | 0.05 | |
| 目标模块 | q/k/v/o + gate/up/down | OCR 任务建议连 FFN 一起挂 |
| 学习率 | **1e-4 ~ 2e-4**（LoRA）/ 1e-5~2e-5（全参） | LoRA 比 SFT 大 10× |
| epochs | 1-3（>3 基本过拟合） | |
| batch(有效) | 16-64（梯度累积凑） | |
| 调度 | cosine + warmup_ratio 0.03 | |
| QLoRA | NF4 + double_quant + paged_adamw | 单卡 24GB 可调 7B |

### 13.3 LLaMA-Factory 一键式（推荐入门）

```yaml
# deepseek_ocr_lora.yaml
model_name_or_path: ./models/DeepSeek-OCR-2   # 解码器权重需先抽取
stage: sft
finetuning_type: lora
lora_target: all
lora_rank: 16
dataset: my_ocr_sft            # data/dataset_info.json 注册
template: default
cutoff_len: 4096
per_device_batch_size: 2
gradient_accumulation_steps: 8
learning_rate: 1.0e-4
num_train_epochs: 2
bf16: true
```

`llamafactory-cli train deepseek_ocr_lora.yaml` → 导出合并权重 →
转回 safetensors 给本引擎加载。**注意**：本引擎是纯 C 自定义管线，
微调解码器后只需替换权重文件；若动了视觉侧需同步视觉权重格式。

### 13.4 评估闭环（没有 eval 的微调是盲飞）

- 任务指标：字符准确率 / 编辑距离 / 表格 TEDS
- 回归集：100~500 张固定图 + GT，每次微调后跑（可写脚本调本引擎 --silent）
- 对比四点：基座、prompt-only、SFT-LoRA、全参——用数据决定停在那一格

## 14. 强化学习完整实操

### 14.1 为什么 SFT 之后还要 RL

SFT 只能模仿"给定的好答案"：一题多解时它学不会"哪种更好"；
很多品质（简洁、不出戏、答案正确但推理更短）**写不成标准答案，
只能表达成比较或奖励**。这就是偏好优化/RL 存在的理由。
顺序铁律：**RL 之前必须有像样的 SFT**（RL 是放大器，不是起搏器）。

### 14.2 DPO 实操（最简单的偏好优化）

数据：`{"prompt":…, "chosen":…, "rejected":…}`（成对偏好）。
TRL 关键超参（社区共识）：

```python
DPOConfig(
    beta=0.1,               # 0.05~0.5：越大越贴参考模型，越小越激进
    learning_rate=5e-7,     # 1e-7 ~ 5e-7：比 SFT 小 100-1000×
    num_train_epochs=1,     # DPO 极易过拟合，1 轮起步
)
DPOTrainer(model, ref_model=clone, args=..., train_dataset=..., tokenizer=...)
```

失败模式：chosen/rejected 都变差（beta 太小/数据脏）、两边 logp 同涨
（模型在"复读"，查数据长度分布）。

### 14.3 GRPO 实操（可验证奖励，OCR 天然适用）

GRPO 不需要 RM 和 critic：同一 prompt 采 G 个回答，用组内奖励标准化当优势：

```
A_i = (r_i − mean(r)) / std(r)      # 组内相对优势
loss = −E[ min(ρ·A, clip(ρ,1±ε)·A) ] + β·KL(π‖π_ref)     ρ=重要性比
```

TRL GRPOTrainer（Ray/Modal 都有完整可跑例子）：

```python
def ocr_reward(completions, gt, **kw):
    return [1 - edit_distance(c, g)/max(len(g),1) for c, g in zip(completions, gt)]

GRPOConfig(num_generations=8, max_completion_length=512,
           beta=0.04, learning_rate=1e-6)
GRPOTrainer(model, reward_funcs=[ocr_reward], args=..., train_dataset=...)
```

**reward 设计是 GRPO 的全部艺术**（OCR 场景）：
- 主奖励：1−归一化编辑距离
- 结构奖励：表格用 TEDS、数字用精确匹配加权
- 防投机：空串/复读 GT 片段要给负分或零分；长度惩罚防啰嗦
- 课程：先易（清晰印刷体）后难（手写/表格），防早期奖励噪声淹没梯度

### 14.4 PPO 何时还需要

需要"不能写成公式"的整体偏好（语气、安全边界）时仍要 RM+PPO——
代价是 4 模型同显存 + 超参敏感；一般团队 DPO/GRPO 已覆盖 80% 需求。

## 15. 调试速查：微调/RL 常见病与处方

| 病因 | 症状 | 处方 |
|---|---|---|
| 过拟合 | eval 变差、背诵训练集 | 减 epoch、加 dropout、扩数据 |
| 灾难性遗忘 | 旧任务崩 | 混入 10-30% 通用数据、降 lr、LoRA 代替全参 |
| reward hacking | 奖励涨但人评变差 | 补 reward 漏洞、加 KL、人评抽检 |
| DPO 双降 | chosen/rejected logp 同降 | 数据冲突、beta 过小、去重 |
| 长度爆炸 | 输出越来越长 | 长度惩罚 / SFT 数据截断分布 |

## 16. 流程清单（贴在工位上）

1. 定义评测集（先于一切）
2. prompt + few-shot 基线，记录指标
3. 不达标 → RAG（知识类）或 SFT-LoRA（行为类）
4. SFT 收敛 → 有偏好数据走 DPO，有可验证奖励走 GRPO
5. 每步与第 1 步的基线对比；蒸馏是最后的降本动作
