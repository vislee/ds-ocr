## 3. 模型家族谱系

```
DeepSeek-LLM ──→ DeepSeek-V2 (MLA+MoE) ──→ DeepSeek-V3 (V3 版 MLA)
      │                                          │
      └── DeepSeek-OCR (SAM+CLIP+3B-MoE)         └── DeepSeek-OCR-2 (Qwen2-0.5B 编码器)
                                                       │
                 Baidu Unlimited-OCR ──────────────────┘ (同款 3B-MoE 解码器 + R-SWA + 多页解析)
```

三代模型共享同一个解码器骨架（12 层，64 专家 top-6 + 2 共享，1280 隐藏），
差异全在**视觉侧与注意力调度**——这正是 01/06 两篇 + 本仓库三模型
`detect_model_version` 分支所对应的内容。

## 4. 推理系统论文

- **Orca**（OSDI 2022）：iteration-level 调度——请求级并发改为 token 级，
  continuous batching 的源头
- **PagedAttention / vLLM**（SOSP 2023, arXiv:2309.06180）：KV cache 分页，
  消除碎片；本工程"每请求独占连续 KV"是其单请求特例
- **投机解码**（Leviathan 2302.01318 / Chen 2302.04088）：小模型起草+大模型
  验证；对本工程的可探索方向：SAM/编码器特征做"草稿"意义不大，
  但 det 标签结构化输出可以用文法约束采样替代
- **MLC / TVM**：编译期生成内核 vs 本工程手写内核的取舍

## 5. 进阶方向：从读者到作者

1. **实现一个新内核**：给 `ds_kernels_avx.c` 写 AVX-512 版 `ds_rms_norm_per_head`
   （当前走标量路径），用 `test_kernels` 对拍
2. **实现 top-p 采样**：`ds_decoder_forward` 目前只有贪心+温度；补 nucleus
   并在 OCR 数据上证明它没用（这本身就是一个好实验）
3. **KV cache 量化**：F32 cache → INT8 cache，测 V3 长文档的显存/质量
4. **批处理**：把 `ds_decoder_forward_batch` 扩展成 2-4 路并发 OCR 的
   continuous batching，复现 Orca 的核心思想
5. **对齐实验**：用 `DS_BF16_SIMULATE_PYTHON` 与 Python 逐层对拍，
   定位下一个精度敏感点（候选：注意力分数的 softmax 归约顺序）
