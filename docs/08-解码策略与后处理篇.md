## 1. 解码策略全景

### 1.1 问题定义

解码（decoding）回答的问题是：语言模型每一步输出整个词表上的打分向量 **logits**
（未经 softmax 归一化的原始分数）z ∈ R^V，本工程 V = 129280（`ds_ocr.h` 的
`DS_DEC_VOCAB_SIZE`，与 `models/*/config.json` 的 `vocab_size` 一致）——从这
129280 个分数里挑哪一个作下一个 token。挑选规则不改变模型本身，却决定输出的
确定性与质量；"后处理"则回答挑完之后**给用户看什么**。

> 🗣️ **说人话**：解码是整台机器的最后一米：前面 12 层 MoE 把一张图蒸馏成 129,280 个「原始分」（logits，还没归一化），这一步决定谁上台。它像一场选举的全部手续——logits 是各候选人的票数，解码策略只是**选举规则**（谁票高谁上、还是按概率抽签、还是先禁一批人再选），规则不改票数本身。所以所有策略共用同一个解码器、只在 LM head 之后分岔（§1.5、§5.4）；「后处理」则是上台之后给观众看什么（§6/§7）。
> *边界*：logits 是未归一化分数——同样一张脸换个 softmax 温度就换算成不同概率，所以 logits 只在同一步内比大小，跨步比、直接当概率用都是误用。

### 1.2 五种策略：公式与一个手算算例

设某步 5 个候选 token 的 logits 为 z(A)=4.0、z(B)=3.0、z(C)=2.0、z(D)=1.0、z(E)=0.0（其余 ~12.9 万维更低，忽略）：

| 策略 | 公式/操作 | 本工程实现 | 适用场景 |
|---|---|---|---|
| 贪心 Greedy | argmax z | 是（默认，快速路径） | OCR 等确定性任务 |
| 温度 Temperature | p_i ∝ exp(z_i/T) | 是（`--temp`，全量路径） | 调节随机性 |
| Top-k | 只在 k 个最高 logit 里归一化采样 | 否 | 抑制长尾 |
| Top-p (nucleus) | 最小前缀集使 Σp ≥ p | 否 | 自适应截断 |
| Beam search | 保 B 条累计对数概率最高的路径 | 否 | 翻译/摘要，OCR 少用 |

**温度算例**。T=1 时 softmax：p(A)=e⁴/Σ = 54.60/85.79 ≈ 0.636，p(B)≈0.234，p(C)≈0.086，p(D)≈0.032，p(E)≈0.012。
T=0.5 把 logits 加倍（[8,6,4,2,0]）后 p(A)≈0.865——分布变"尖"，接近贪心；T=2 时
p(A)≈0.429——分布变"平"，随机性增大。代码实现（`ds_moe_decoder.c` 全量路径）
先减最大值再做指数（防溢出），然后按累积分布逆变换采样：

```c
for (int i = 0; i < vocab; i++)
    logits[i] = expf((logits[i] - max_logit) / temp);   /* 减 max：数值稳定 */
/* …softmax 归一化后，按累积分布逆变换采样… */
float r = (float)rand() / (float)RAND_MAX;
float cum = 0.0f;
for (int i = 0; i < vocab; i++) { cum += logits[i]; if (cum >= r) { token = i; break; } }
```

**Top-k 算例**（k=2）：只保留 {A,B} 重新归一化：p(A)=54.60/74.68≈0.731，p(B)≈0.269。k 固定——分布尖时浪费、平时不够。
**Top-p 算例**（p=0.9）：按概率降序累积 0.636→0.870→0.957，首次 ≥0.9 的前缀是 {A,B,C}，保留 3 个。集合大小随分布自适应（nucleus，Holtzman et al. 2019 的核心改进）。
**Beam search**：每步保 B 条路径，取累计 log p 最高的整句。计算量 ×B，且倾向选出"平均安全"的平滑文本——对逐字忠实的转写反而是缺点。

**把同一个 logits 向量从头算到尾**。候选 [A,B,C,D,E] 的 logits [4,3,2,1,0]、
T=1，逐步对应 `ds_moe_decoder.c` 的 `ds_decoder_forward`（全量 logits 路径）：

| 步骤 | 操作 | 结果 |
|---|---|---|
| ① 减最大值 | z − 4 | [0, −1, −2, −3, −4]（防 exp 上溢，不改变 softmax 结果） |
| ② 逐个取指数 | e^{z_i−max} | [1.000, 0.368, 0.135, 0.050, 0.018]，Σ = 1.571 |
| ③ 归一化 | 除以 Σ | p = [0.636, 0.234, 0.086, 0.032, 0.012]（与上面 T=1 直算一致） |
| ④ 贪心 | argmax p | A——不掷骰子，永远取众数 |
| ⑤ 逆变换采样 | r ∈ [0,1) 落累积区间 | 累积 [0.636, 0.870, 0.957, 0.988, 1.000]；r=0.7 落在 B 的区间 [0.636,0.870) → B |
| ⑥ top-p（若做） | 按概率降序取最小前缀集 | p=0.9 → {A,B,C}，集合外置 −∞ 后重新归一化再采样 |

①②③ 对应温度路径的 `expf((logits[i] - max_logit) / temp)` 加归一化循环；
④ 对应快速路径的 `ds_argmax_matvec_bf16`（流式扫描，§5）；⑤ 对应 `cum >= r`
的逆变换采样（inverse-CDF）循环——**同一份概率分布，取样本的规则不同**，
"解码策略"的全部内容就是这④⑤⑥的三选一或组合。top-p 本工程未实现（§1.4），
⑥ 是理论插入点：位置在③之后、⑤之前（进阶延伸一节的实验建议同样指在
`ds_moe_decoder.c` 的温度采样之后、逆变换采样之前）。

> 🗣️ **说人话**：温度不是"加随机噪声"，而是"给概率重新分配音量"。把 logits 想成
> 五个候选在投票，T=1 时冠军拿走 64% 票；T=0.5 相当于给大票数者加权，冠军涨到 86%
> ——更像一言堂；T=2 则是给所有人发稀释液，冠军只剩 43%，冷门也有戏。所以"调温"
> 改的是分布形状本身（§1.5 说的对 p 做变换），采样才是从这份分布里掷骰子。
> *边界*：温度只重塑锐度、不改排序，T→0 永远收敛到同一个冠军；要真正换掉冠军得靠
> 截断（top-k/top-p）或惩罚，不是调温。

### 1.3 OCR 为什么默认贪心

关键在任务的**熵结构**。给定图像和已生成前缀后，"正确下一个 token"的分布接近
one-hot——图上写什么就该转写什么，几乎不存在多个同等合理的续写。采样类策略的价值
在于摊开概率质量、引入多样性，而转写任务里这种多样性全是噪声：温度 >0 只会按 p<1
的概率把冠军换成错字，top-p 只会在错字集中营里抽奖。开放式生成（"描述这张图片"）
的分布是平的，才需要采样。所以本工程默认 T=0（贪心），`--temp` 仅保留做实验
（usage 文本："default: 0 = greedy"）。

> 🗣️ **说人话**：转写是「默写」，不是「作文」。图上写着什么，正确答案就只有一个——下一个 token 的分布像一根针（接近 one-hot）：冠军拿走九成票、第二名零星几票。采样策略的卖点是「摊开概率换多样性」，可默写题里多样性就是错字：温度 >0 等于按 p<1 的概率亲手把冠军换成第二名（§1.2 的算例：T=2 时冠军只剩 43% 票）。开放式任务（「描述这张图」）分布是平的，采样才有意义。所以默认 T=0——顺带一个工程红利：贪心才能走 §5 的 8ms 流式 argmax 快速路径，温度 >0 会把它踢回 55–63ms 的全量路径。
> *边界*：one-hot 是任务结构的推论不是保证——模糊照片、艺术字体处分布也会变平，那正是 §9 幻觉的温床；贪心在这些地方同样会抄飞，只是抄得「稳定地错」。

### 1.4 本工程的实现边界

诚实起见划清边界：引擎实现的采样控制只有四个——贪心/温度（互斥）、重复惩罚
（`--rp`）、n-gram 阻断（`--ngram`）、min_new_tokens（`--min-tokens`）；top-k、
top-p、beam search 均未实现，`--temp > 0` 时走全量 logits 路径（§5.4）。另有一个
实现细节：`main.c`/`ds_ocr.c` 均未调用 `srand()`，`rand()` 以 C 标准默认种子起算
——同一二进制、同一输入下，"随机"序列每次运行都相同。

> 🗣️ **说人话**：采样控制台只有四个旋钮：温度、`--rp`、`--ngram`、`--min-tokens`；top-k/top-p/beam 都没装——这不是缺陷声明，是先划清「本引擎管什么」的边界。隐藏彩蛋是没人调 `srand()`：骰子每次都从同一个点数序列开始摇，同一二进制同一输入，「随机」输出每次一模一样。这不是疏忽，是全书回归体系的基石——`tools/regress.sh` 能拿 30 组冻结标签判红绿，前提就是输出本身逐字节可复现（§1.5 的确定性 + §10 实验 3 可当场验证）。
> *边界*：「确定性」只承诺同一构建内——换 libc/换编译器，`rand()` 的实现可以不同；跨平台对拍靠 `DS_DUMP_*` 系列导出中间量，别赌输出一致。

### 1.5 训练视角：模型学的是分布，解码只是取样本

为什么换解码策略不用重训模型？因为策略根本不碰权重。把视角切到训练侧，
这一切会变得显然。

**训练在学什么**：next-token 概率分布。给定前缀 $x_{<t}$，模型输出
$p(\cdot \mid x_{<t}) = \mathrm{softmax}(z)$，训练目标是每个位置的**交叉熵**
$\mathcal{L} = -\log p(y_t \mid x_{<t})$（真实 token $y_t$ 的负对数概率；
完整推导与 logsumexp 数值细节见 [11-预训练篇](./11-从零构建大模型：预训练篇.md) §5.1）。
解码器 12 层 MoE 的全部参数，就是在亿万语料上把"下一个 token 的分布"猜准。

**训练时为什么不需要任何解码策略**：训练用 **teacher forcing**（教师强制）——
把真实文本一次性整段喂入，因果注意力保证位置 t 只看得见 <t，于是**一次前向
就并行算出所有位置的预测分布与损失**，没有"生成一步、喂回一步"的自回归循环。
循环不存在，"从分布里取哪个样本"的问题就不存在：训练永远拿真实 token 当
下一个输入，无需采样。解码策略是**推理期独有的问题**——推理没有真值可喂，
必须从模型自己的分布里选一个 token 当下一步的输入。

**推理策略 = 对同一个 p 的变换**。训练练出 p，推理只决定"怎么从 p 取值"：

| 策略 | 对 p 做了什么 | 改变模型吗 |
|---|---|---|
| 贪心 | 取众数（T→0 的极限） | 否 |
| 温度 T | softmax(z/T)，重塑锐度 | 否 |
| top-p | 砍掉累积质量外的小概率尾 | 否 |
| 重复惩罚 | 历史 token 的 logit ÷/×rp（§2） | 否 |
| n-gram 阻断 | 违规 id 置 −inf（§3） | 否 |

全是 logits/p 上的**单调或截断变换**——所以同一个 checkpoint 可以随任务换
策略；这也解释了 §5.4 为什么贪心与采样能共用一个解码器实现、只在 LM head
之后分岔。

**exposure bias：训练与推理之间的裂缝**。teacher forcing 让训练永远看到
真值前缀，推理却只能看到自己生成的（可能出错的）前缀——误差会滚雪球：一个
错 token 进入上下文，后续分布就建立在"模型在训练中从未见过的前缀"上。重复、
跑飞、对数值扰动敏感（§9 的近并列翻转）都与此有关。重复惩罚、n-gram 阻断、
min_new_tokens 本质上是**给这条裂缝打的工程补丁**——它们不能让推理分布回到
训练分布，只能在症状出现时踩刹车；更彻底的解法在训练侧（docs/12 的 RLHF/GRPO
直接用可验证奖励纠正生成分布）。

OCR 的呼应：V3 会输出 `<|det|>` 坐标框，不是有人给它写了解析规则，而是
SFT 阶段它就在真值里见过这种格式（docs/12 §9 的"后训练指纹"）——**训练决定
模型会什么，解码策略只决定怎么用**。

> 🗣️ **说人话**：训练是「开卷考试永远附标准答案」（teacher forcing）：真值整段一次喂入，因果掩码保证第 t 个位置只看 <t，一次前向并行算出所有位置的损失——循环根本不存在，「从分布里怎么取样」的问题也就不存在。推理没有标准答案，只能拿自己吐的字当下一步的输入，exposure bias 就是这条裂缝：一个错字滚进上下文，后面的分布就建立在「训练时从没见过的前缀」上。所以重复惩罚、n-gram 阻断、min_new_tokens 全是给裂缝打的补丁——只能踩刹车，不能修路（修路在训练侧，docs/12 的 RLHF/GRPO）。
> *边界*：补丁只压症状不除病根——rp 罚得再狠，模型对重复的「自信」分毫未减；§8.4 的内容循环在 V4 上照样发生，最后靠早停止损而不是靠补丁治好。

## 2. 重复惩罚的精确语义与快速路径

### 2.1 HuggingFace/CTRL 语义逐条

重复惩罚（repetition penalty）出自 CTRL 论文，HF `RepetitionPenaltyLogitsProcessor`
沿用其定义。对**历史中出现过的每个 token**，其 logit z 改为：

```
z' = z > 0 ? z / rp : z * rp        # rp > 1，逐 token 施加
```

三条语义逐条解释：

1. **方向对称**：正 logit 除以 rp 变小（3.0→2.5），负 logit 乘以 rp 变得更负
   （−2.0→−2.4）——不管符号，都朝"更不容易被选中"的方向推。
2. **逐 token 罚、不管次数**：罚的是"出现过"这个集合成员资格，出现 3 次也只罚
   一次（快速路径对重复历史条目只是重复同一比较，不叠加惩罚）。
3. **rp=1.0 关闭**：代码门槛是 `if (rp > 1.0f && ...)`，1.0 时整段逻辑不进入。

**手算算例**：历史含 B 与 D，rp=1.2。冠军 A 的 logit 4.0 不在历史 → 保持 4.0；
B：3.0/1.2=2.5；D：−2.0×1.2=−2.4，A 仍胜。加大到 rp=1.5：若冠军 A 也在历史，
4.0/1.5≈2.67 < B 的 3.0 → B 反超。惩罚强度决定"让不让位"。

CLI 默认 rp=1.0（无惩罚），usage 文本给的试验区间是 **1.1–1.5**。惩罚越大对重复
的压制越强，但"合法重复"（表格里的相同单元格、列表符号、省略号）也会被误伤。

> 🗣️ **说人话**：这条罚则的精髓是「方向对称、罚过不记次数」。正分除以 rp（3.0→2.5）、负分乘以 rp（−2.0→−2.4）——不管原来是红榜还是黑榜，一律往「更不被选中」的方向推一把；出现 3 次也只罚一次，罚的是「进过历史」这个资格，不是次数（快速路径对重复历史条目只是重复同一比较）。手算例里 rp=1.2 时冠军 A（4.0，不在历史）稳坐；rp 加到 1.5、若 A 也在历史，4.0/1.5≈2.67 被 B 的 3.0 反超——惩罚强度决定「让不让位」。
> *边界*：对称的除/乘意味着「压幅度」而非「禁身份」——被罚 token 仍可能当冠军（§3.1 对比表第一行）；要它必然缺席，得换 n-gram 阻断的 −inf。

### 2.2 快速路径三步

标准做法先算全量 logits，再对历史 token 罚，再 argmax——要求每步物化 129280 维
logits（连带第 5 节的 F32 副本开销）。贪心场景有个观察：**惩罚只改动历史 token
的分数，非历史 token 之间的相对排序不变**，所以只需：先找冠军，再看"被罚后的
历史 token"能否反超。`ds_moe_decoder.c` 的实现分三步（节选）：

```c
/* Step 1: 流式 argmax 找冠军（不物化 logits，见第 5 节） */
best_token = ds_argmax_matvec_bf16_excluding(x, lm_w, hidden, vocab, banned, n_banned);
float best_val = ds_bf16_dot_row(x, lm_w, hidden, best_token);  /* 补算冠军 logit */

/* Step 2: 冠军在历史中 → 罚它 */
for (int i = 0; i < ctx->token_history_len; i++)
    if (ctx->token_history[i] == best_token) {
        best_val = (best_val > 0) ? best_val / rp : best_val * rp;  /* HF 语义 */
        break;
    }

/* Step 3: 只对历史 token 逐个补算 logit、施加惩罚、比大小 */
for (int i = 0; i < ctx->token_history_len; i++) {
    int tid = ctx->token_history[i];
    if (tid >= 0 && tid < vocab && tid != best_token) {
        if (is_banned) continue;                       /* 被禁 token 永远不参选 */
        float val = ds_bf16_dot_row(x, lm_w, hidden, tid);
        val = (val > 0) ? val / rp : val * rp;
        if (val > best_val) { best_val = val; best_token = tid; }
    }
}
```

两个工程细节：其一，流式 argmax 只返回下标不返回分值，所以第 2 步前要用
`ds_bf16_dot_row` 对冠军**补算一次 logit**（单行 1280 维点积，NEON 下微秒级）；
其二，历史里重复出现的 token 会重复进入第 3 步循环——无害，只是少量冗余（同一
logit 重复比较，与 §2.1 的"不管次数"语义一致）。

> 🗣️ **说人话**：惩罚像给考场里"老面孔"扣分，而新面孔分数分文不动——既然冠军没被
> 扣，它的相对位置就不受这批扣分影响；只有当某个被扣的老面孔翻上来，故事才变。所以
> 不必重排全部 12.9 万张卷子，只要盯住"被扣过的那几百人"。第 2 步那次 `ds_bf16_dot_row`
> 就是给冠军现算一遍分数（流式 argmax 只记名字不记分数），避免"拿名字当分数比"。
> *边界*：这套"只看历史"的前提是惩罚只动历史 token；一旦引入会改变全体排序的变换
> （如+logit bias 全表、或 top-p 截断），冠军必须在截断后重选，快速路径即失效。

### 2.3 O(V) → O(history) 的账

惩罚相关的计算从"全词表"降到"历史条数"。历史 = 本轮已生成的 token id
（`ctx->token_history`，容量 `max_seq + 512`，V3/V4 为 8704）；一次长文档转写约
200–700 token（regress 脚本的 `-n` 上限即 200/700），相对 V=129280 差三个数量级
——源码注释口径："历史通常 < 300 → 129280 降到 ~300，近 430×"。更关键的是带宽：
补算一个历史 token 的 logit 只读 1280×2B=2.5KB 权重，300 个合计 <1MB，相对每步
331MB 的 LM head 扫描（第 5 节）可忽略。**省的不是点积次数，而是"为罚 300 个 token
物化 129280 维 logits"这件事本身**。

> 🗣️ **说人话**：惩罚对象从「全词表 129,280」缩到「历史 ~300 条」，差三个数量级（源码注释口径近 430×）。但真正的红利不是省那 300 个点积——每个才读 1280×2B=2.5KB 权重、300 个合计 <1MB——而是「不必为罚 300 人先物化 129,280 维 logits」这件事本身：全量路径每步要过 662MB 的 F32 LM head 副本（§5.1），快速路径只多付 <1MB。所以这是带宽账不是计算账，与 §5 的 LM head 主题一脉相承。
> *边界*：历史条目不去重——重复 id 会重复补算同一行 logit（§2.1「不管次数」语义的副作用）；长输出、高重复文本时这笔「可忽略」会慢慢变厚，真要较真一个位图去重就够。

### 2.4 为什么惩罚对结构性 token 几乎无效

`<|det|>`（id=128818）、`<|/det|>`（128819）这类结构标签每开一个新检测框都必须
"重新出现一次"，惩罚打的那点折扣往往不足以让它让出 top-1；而它前后的正文 token
每次都不同，n-gram 阻断（下一节）要求的"(n−1)-gram 上下文重复"也几乎不触发。
所以 V3 的标签清理**不指望采样控制**，靠的是第 6 节的确定性后处理——采样管概率，
后处理管结构，各司其职。

> 🗣️ **说人话**：`<|det|>`（128818）是「开一张新检测框必打的工单号」——每个框都得重新出现一次，这是任务结构不是口吃；惩罚打的那点折扣（rp=1.1 时 5.0→4.55）往往不够让它让出 top-1。它前后的正文 token 每次都不同，n-gram 阻断要求的「(n−1)-gram 上下文重复」也几乎不触发——两件武器同时哑火。所以分工明确：采样管概率，后处理管结构（§6 的确定性手术），各司其职。
> *边界*：「后处理管结构」的前提是标签格式稳定（§1.5 的后训练指纹）——模型真把标签吐坏时（§6 第⑦步的断裂 det），采样和后处理都只能善后，防不住发生。

## 3. n-gram 阻断：banned 表收集与排除式 argmax

### 3.1 机制

`no_repeat_ngram_size = n`（HuggingFace 同名参数）：若历史**末尾的 (n−1) gram**
曾在历史更早位置出现过，则所有曾接续它的 token 直接禁掉。手算例（n=3，与源码
注释同例）：历史 `[…, A, B, C, D, E, B, C, ?]`，末尾 2 个 = [B,C] 与位置 1–2 的
[B,C] 相同 → 当时接续的 D 进入禁用表，避免生成重复的 B,C,D 三元组。

与重复惩罚的本质差异：

| 维度 | 重复惩罚 | n-gram 阻断 |
|---|---|---|
| 作用方式 | 压**幅度**（除/乘 rp，可能仍最高） | 禁 **id**（−inf/排除，必不可能被选） |
| 触发条件 | token 出现过就罚，与上下文无关 | (n−1)-gram **上下文**重复才触发 |
| 粒度 | 单 token | n-gram（序列级） |
| 对结构性 token | 几乎无效（§2.4） | 坐标序列各异时也不触发 |
| 误伤面 | 合法重复的 token | 合法重复的**整段**（相同单元格等） |

OCR 的退化重复往往是"整段重抄"——从头再生成一遍刚输出的段落。惩罚只能压每个 token 的分数，拦不住概率差足够大的循环；n-gram 阻断从机制上使"已出现过的整段"不可复现，所以对这类退化特别有效。代价是合法的整段重复（表格重复行）也被拦，故默认值偏保守（§3.4）。

> 🗣️ **说人话**：n-gram 阻断像「接龙裁判」：每步先看历史末尾 (n−1) 个 token 组成的短语是否在更早处出现过——手算例里末尾 [B,C] 与位置 1–2 的 [B,C] 撞车，于是「当年跟在 B,C 后面的 D」进黑名单，B,C,D 这个三元组从此不可复现。它与重复惩罚是两种武器（上表四行差异都是它俩的）：惩罚压**幅度**（被罚者仍可能最高），阻断禁**身份**（−inf，必不可能被选）；惩罚按「出现过」触发，阻断按「上下文重复」触发。OCR 的退化多是「整段重抄」，惩罚拦不住概率差足够大的循环，阻断从机制上让整段不可复现——V3 默认 35 的底气在这。
> *边界*：阻断是整段级的钝刀——表格里合法的重复行（相同单元格）一并被拦，所以 V1/V2 默认关（§3.4），只在长文档场景强制开。

### 3.2 快速路径：先收集 banned 表

阻断不能像惩罚那样"事后补救"——被禁 token 若已是 argmax 冠军就得重选。本工程的做法是**每步先算出禁用表，让 argmax 直接跳过**（`ds_moe_decoder.c` Step 0，节选）：

```c
int banned[48];                  /* 本步被禁 token：warmup ban + n-gram 规则 */
int n_banned = 0;
for (int b = 0; b < ctx->dec_argmax_n_ban && b < 8; b++)      /* EOS/Ġ warmup ban */
    banned[n_banned++] = ctx->dec_argmax_ban[b];
int ngram_n = ctx->no_repeat_ngram_size;
if (ngram_n > 0 && ctx->token_history_len >= ngram_n - 1) {
    int prefix_len = ngram_n - 1;
    for (int i = 0; i <= hist_len - prefix_len - 1; i++) {    /* 扫历史 n-gram 起点 */
        int match = 1;
        for (int j = 0; j < prefix_len; j++)
            if (hist[i+j] != hist[hist_len - prefix_len + j]) { match = 0; break; }
        if (match) {                                          /* 命中：接续者入表 */
            if (n_banned >= 40) goto full_logits_path;        /* 病态情况：回退全量 */
            banned[n_banned++] = hist[i + prefix_len];        /* （去重检查略） */
        }
    }
}
```

容量账：`banned[48]` 中至多 8 个留给 warmup ban（§4），n-gram 部分阈值 40——超过
说明历史已高度退化，步内补丁无意义，整步跳 `full_logits_path` 用全量 logits +
`logits[banned] = -1e30f` 处理（v1.1 之前是"先 argmax、发现被禁再整条走 sgemm
全量路径"，60ms+/步）。每步收集本身 O(history × n)：n=35、历史 700 时约 2.4 万次
整数比较，微秒级。

**数据结构盘点：没有"窗口"，只有扁平数组**。历史是 `ctx->token_history`
（容量 `max_seq + 512`，V3/V4 为 8704）的一维 int 数组，banned 表是 48 项定长
数组，每步对**全历史**线性扫描——没有哈希索引、没有环形缓冲。与官方 Python
参考（`SlidingWindowNoRepeatNgramProcessor(ngram_size=35, window=128)`，
`main.c` 注释）相比，C 端未复刻 window=128 的滑窗范围调校：全历史扫描只会
禁得更多、不会更少，落在偏保守一侧。微秒级的收集成本不值得为此引入更复杂的
结构——这也是快速路径能把 n-gram 并进 Step 0 的前提：数据结构足够简单，
才敢在每步的 argmax 之前同步做。

> 🗣️ **说人话**：每步先在一本 48 页的小册子（`banned[48]`）上记黑名单：至多 8 格留给 warmup 禁 EOS/Ġ（§4），剩 40 格给 n-gram 命中；超过 40 说明历史已高度退化，步内补丁无意义，整步跳全量路径用 `logits[banned]=-1e30f` 处理。收集本身是对全历史的线性扫描——n=35、历史 700 时约 2.4 万次整数比较，微秒级；没有哈希索引、没有环形缓冲，就是一个扁平数组加一个定长数组。数据结构越土，越敢把它塞进每步 argmax 之前的同步路径——这是快速路径能并进 Step 0 的前提。
> *边界*：全历史扫描没复刻官方 Python 的 window=128 滑窗（`SlidingWindowNoRepeatNgramProcessor`）——禁得只会更多不会更少，落在偏保守一侧；合法整段重复被误伤的概率因此略高于官方口径。

### 3.3 排除式 argmax：先扫冠军、命中才重扫

排除式 argmax 的接口与实现（`ds_kernels.c`）：

```c
int ds_argmax_matvec_bf16_excluding(const float *x, const uint16_t *W_bf16,
                                    int in_dim, int out_dim,
                                    const int *exclude_ids, int n_exclude);
```

它不是"扫描时逐行查禁用表"，而是两段式：

1. **正常流式 argmax**（多线程按词表分段并行）——绝大多数步冠军不在禁用表里
   （通常禁 0–2 个 token），到此为止，成本与无禁用完全相同；
2. **冠军命中禁用表才重扫**（`ds_argmax_rescan_excluding`）：禁用 id 排序去重
   （`ex[64]`），词表被切成若干连续段，每段跑一次区间 argmax 内核、只跳过被禁的
   行——保证结果是"真正的最优非禁 token"，而非某分段的次优。

第 2 段的代价是多一次全词表扫描（~8ms，注释原话："one extra full-vocab scan
(~8ms) on the rare ban-hit step"）。不在第 1 段就跳的原因：禁用集是稀疏无序小表，
逐行查表会把 129280 次比较变成 129280×n_banned 次；排序切分只在 n_exclude ≤ 64 的小表上花一次 O(n log n)，摊销后便宜得多。

> 🗣️ **说人话**：这像一个"先看保安是不是通缉犯，是才查名单"的门岗。绝大多数步冠军
> 是良民——一次全表扫描就放行（成本和不设禁词一模一样）。只有冠军恰好被禁，才触发
> 第二遍：先把黑名单排好序（顺便去重），再对每段区间重新选优，保证抓到的是"真·全场
> 最优秀的守法者"，而不是某一段的土状元。
> *边界*：便宜的前提是"命中罕见"。若禁词多到每次冠军都中，就退化成每步扫两遍全表
> （翻倍开销）；banned 表撑过 40 项时干脆转走全量路径（§3.2）。

### 3.4 各模型默认值

| 模型 | 默认 ngram | 出处 |
|---|---|---|
| V1/V2 (DeepSeek-OCR/-2) | 0（关闭，`--ngram` 可开） | `ds_ocr.c` `init` + main.c |
| V3 (Unlimited-OCR) | **35（main.c 强制开启）** | Python `SlidingWindowNoRepeatNgramProcessor(ngram_size=35, window=128)` |
| V4 (Unlimited-OCR-2) | 0（官方 infer() 即纯贪心，保持一致） | `ds_ocr.c` 注释 |

一个必须知道的 CLI 怪癖（`main.c`）：V3 上传 `--ngram 0` 会命中
`if (model_version == 3 && no_repeat_ngram_size == 0)` 分支被**改写回 35**——该旗标
在 V3 上只能调大、不能经 `--ngram 0` 关闭。Python 侧口径是"非评测 20 / 评测 35"
（`ds_ocr.c` 注释），usage 建议是 "try 20-35 if output is degenerate"。

> 🗣️ **说人话**：三个模型三种态度：V1/V2 默认关（0，`--ngram` 可开），V3 出厂锁定 35——CLI 上传 `--ngram 0` 会被 `main.c` 的分支当场改写回 35，这个旗标在 V3 上只能调大、不能经命令行关闭；V4 默认关，与官方 `infer()` 的纯贪心保持一致。V3 锁 35 的依据是 Python 侧的 `SlidingWindowNoRepeatNgramProcessor(ngram_size=35, window=128)`——长文档整段循环是它见过的真病，宁可保守也要锁上。
> *边界*：「改写回 35」是礼貌的强制不是 bug；但真想关掉做对照实验只能改代码（§10 实验 2 用的就是 V4 对照）。这个怪癖本身就是 §3.1「误伤合法重复」代价的官方表态。

### 3.5 约束解码：banned 表就是最简的 logits processor

n-gram 阻断在业界有个更一般的名字——**约束解码**（constrained decoding）。
它的统一抽象是 **logits processor**：在 softmax 之前对 logits 做一次变换，
把"不允许的 token"压到 $-\infty$：

$$ z'_i = \begin{cases} z_i & i \in \mathcal{A}(x_{<t}) \\ -\infty & \text{否则} \end{cases} $$

其中 $\mathcal{A}(x_{<t})$ 是"当前上下文下合法的 token 集合"。**本工程的
`banned[48]` 表就是这个抽象的一个具体实例**——$\mathcal{A}$ 由 n-gram 规则
和 warmup ban 共同决定（§3.2）。区别只在实现：本工程用"排除式 argmax"
（§3.3）避免物化 129280 维 logits，而 HuggingFace 的 `LogitsProcessor` 是
直接改数组。

**约束解码的三代做法**：

| 代际 | 做法 | 合法性保证 | 代表 |
|---|---|---|---|
| ① 后处理修补 | 生成完再正则/JSON 修复 | 无（可能修不好） | 早期 prompt 工程 |
| ② 黑名单 | 禁用 token 表（本工程） | 只保证"不出现禁词" | `no_repeat_ngram_size`、`bad_words_ids` |
| ③ 语法约束 | 用文法（CFG/正则）驱动状态机，每步只允许合法后继 | **结构必然合法** | Outlines、llama.cpp GBNF、XGrammar |

**第 ③ 代的核心机制**：把目标格式（JSON Schema、SQL、正则）编译成一个
**有限状态机**，解码时维护当前状态，每步把"该状态下不可能出现的 token"
全部屏蔽。以 JSON 为例：

```
状态: 期待 '{' → 只允许 token "{"（及其变体）
状态: 期待 key → 只允许引号开头的 token
状态: 期待 ':' → 只允许 ":"
状态: 期待 value → 允许数字/字符串/true/false/null 的首 token
```

**为什么 OCR 场景用不上（但值得知道）**：本工程的输出是**自由文本 + 布局
标签**（`<BLOCK>`/`<FORK>`），不是严格结构化格式，所以只需要第 ② 代。
但如果要把 OCR 结果直接喂给下游系统（如输出固定 schema 的表格 JSON），
第 ③ 代就是正解——**它把"后处理修补"变成"生成时就不可能错"**。

**代价与陷阱**：

- **状态机编译成本**：大 schema 编译出的 FSM 可能上万状态，每步查表开销
  不可忽略（XGrammar 用下推自动机的缓存优化）
- **token 边界问题**：BPE 的一个 token 可能跨语法边界（如 `"key":` 是一个
  token），FSM 必须按 token 而非字符建模，否则会误禁
- **与投机解码冲突**：草稿模型不知道约束，验证阶段要重新施加 mask，
  接受率会下降（docs/13 §6.6）

**与本工程的关系一句话**：`banned[48]` + 排除式 argmax 是"约束解码"的
最小可用形态——**理解了它，就理解了 Outlines/llama.cpp GBNF 在做什么，
只是后者的 $\mathcal{A}$ 由文法而非 n-gram 规则给出**。

> 🗣️ **说人话**：三代做法是三种质检：①事后修补=产品出门了再返工（正则/JSON 修复，可能修不好）；②黑名单=本工程，出门前检查「禁词不许出现」；③文法状态机=Outlines/GBNF/XGrammar，把 JSON Schema 编译成有限状态机，每步只发「该状态下合法的 token」——结构必然合法，错误没机会发生。三代的全部区别只在合法集合 $\mathcal{A}(x_{<t})$ 谁来给：n-gram 规则给（本工程），还是文法给（第③代）。实现上本工程用排除式 argmax 避免物化 129,280 维 logits，HF 的 LogitsProcessor 是直接改数组——同一抽象的两种账法。
> *边界*：第③代在 OCR 用不上不是技术原因——BPE token 可能跨语法边界（FSM 必须按 token 建模）、大 schema 编译上万状态每步查表不便宜；且本工程输出是自由文本+布局标签，没有「格式」可约束（§1.3 的熵结构）。

## 4. min_new_tokens 与 EOS 抑制：两难与工程解

### 4.1 两难困境

EOS（id=1，`DS_TOKEN_EOS`，与 `generation_config.json` 的 `eos_token_id: 1` 一致）
是"停机键"。完全不抑制：V3 在数值偏差下（§9）EOS logit 偏高，第一步就想停机，
输出空结果。全程抑制：正文结束后模型被迫继续写，幻觉登场。所以需要的是**有期限的
抑制**：前 `min_new_tokens` 步内不许停，之后"想停就停"。

### 4.2 机制：预先声明禁用表，而非事后补选

`ds_ocr.c` 解码主循环每步先把禁用 token 声明到 `ctx->dec_argmax_ban[8]`：

```c
ctx->dec_argmax_n_ban = 0;
if (step < ctx->min_new_tokens) {
    ctx->dec_argmax_ban[ctx->dec_argmax_n_ban++] = eos_token;
    if (cfg->model_version == 3)
        ctx->dec_argmax_ban[ctx->dec_argmax_n_ban++] = 223;   /* Ġ */
}
token = ds_decoder_forward(ctx, dec_input);   /* 快速路径把 ban 并入 banned[] → 排除式 argmax */
```

设计动机（源码注释）：旧实现是"argmax 返回 EOS 后再用 `ctx->dec_logits` 重选次优"，
但快速路径**从不更新** `dec_logits`——它还停留在 prefill 时的旧值，"次优"来自陈旧
分布，可能每步选到同一 token 造成死循环。预先声明 + 排除式 argmax 保证选出的
是**当前步真实分布**的次优。旧的事后重选分支（主循环 `if (token == eos_token
&& step < min_new_tokens)` 里对 `dec_logits` 置 −inf 再 argmax）仍保留作全量路径
的安全网。

> 🗣️ **说人话**：这是「先挂号后看病」对「看完病再挂号」的替换。旧方案：argmax 已经选了 EOS，再拿 `dec_logits` 里的「次优」顶上——可快速路径从不更新 `dec_logits`，它还停在 prefill 时的旧值，于是「次优」可能每步都是同一个，原地死循环。新方案：每步先把 EOS（V3 连 Ġ=223）塞进 `dec_argmax_ban[8]`，让排除式 argmax（§3.3）在**当前步的真实分布**里选次优。教训一句话：修复要作用于当前分布，别拿缓存里的旧地图找新路。
> *边界*：`dec_argmax_ban[8]` 容量 8 是硬上限——warmup 只占 2 格（EOS+Ġ），余量留给未来；真要禁一大片 token，就得走全量路径的 `logits[...]=-1e30f`。

### 4.3 Ġ 耦合抑制与 EOS↔Ġ 振荡

只禁 EOS 不够：V3 在 F32 精度下 EOS 被禁后的次优常是 **Ġ（id=223，
`models/Unlimited-OCR-2/tokenizer.json` 核实，"带空格词首"载体字符，见
[07-分词与词表篇](./07-分词与词表篇.md)）**，而模型在 "10." 这类前缀上自激，
EOS↔Ġ 来回振荡产生 "10." 循环（源码注释："Suppression EOS alone picks Ġ (space)
which leads to '10.' loops"）。所以 V3 的 warmup 期把 EOS 与 Ġ **成对禁用**。
注意 Ġ 伴禁仅 V3 生效（`dec_argmax_ban` 与事后兜底两处都有
`if (cfg->model_version == 3)` 判断），V4 的 warmup 只禁 EOS。

### 4.4 第一个 token 的特殊处理

step 0 的 token 来自 prefill logits（`ds_decoder_prefill` 之后直接 argmax），不走
快速路径。V3/V4 对"prefill 冠军就是 EOS"有专门修复：把 `logits[1]`（EOS）与
`logits[223]`（Ġ）置 −inf 后重新 argmax。这是 §9 幻觉链条的源头治理：被逼选出的
次优（如 ĠThe）可能产出一段短英文幻觉，由第 6 节后处理移除。

### 4.5 默认值

| 模型 | min_new_tokens 默认 | Ġ 伴禁 | 出处 |
|---|---|---|---|
| V1/V2 | 0 | 无 | `ds_ocr.c`: `(model_version == 3 \|\| 4) ? 32 : 0` |
| V3 | 32 | 有 | 同上 + `dec_argmax_ban` 的 V3 判断 |
| V4 | 32 | 无 | 同上 |

CLI 旗标 `--min-tokens <n>`（usage："default: 0; Unlimited-OCR: 32; 0 disables"；
传 ≥0 覆盖引擎默认）。为什么是 32：32 步 warmup 后上下文已有足够正文，EOS logit
自然回落——经验值，`ds_ocr.c` 注释原话 "lets the model settle into stable
content generation"。

> 🗣️ **说人话**：这是"婴儿学步时先别让他坐"的策略。头几步模型还没站稳（上下文太短，
> EOS 分数虚高），先按着不让收尾；等它写出三十来字、进入了正题，再松手——此时 EOS
> 分数自己就落回了低位。V3 还要连 Ġ 一起按（否则被禁 EOS 的次优是 Ġ，模型会卡在
> "10." 里左右横跳，§4.3）。
> *边界*：min_new_tokens 是"时长限制"而非"质量保证"——正文本就短于 32 步时，它反而
> 逼模型超写、催生幻觉；步数只压 EOS 那条通道，压不住模型想提前收尾的真实意图。

## 5. 贪心快速路径：LM head 的带宽账

### 5.1 LM head 的尺寸账

LM head（输出投影，[V, hidden] = [129280, 1280]）是单步解码中**最大的一块权重**。尺寸逐级算清楚：

```
参数量   = 129280 × 1280            = 165,478,400
BF16     = 165,478,400 × 2 B        = 330,956,800 B ≈ 331 MB（十进制）= 315.6 MiB
F32 副本 = 165,478,400 × 4 B        = 661,913,600 B ≈ 662 MB（十进制）= 631.1 MiB
```

**"631MB" 的出处**在此：引擎把 LM head 转 F32 给 sgemm 用时打的日志是
`LM head: converted ... (631.1 MB)`——代码用 `/1048576.0`（MiB）计算却标成 MB；
[05-性能优化实战篇](./05-性能优化实战篇.md) §4.1 的"需要 631MB BF16→F32 转换"
同源。本篇旧版"读 631MB 权重"是错的：**BF16 权重本身是 331MB；631 是 F32 副本的
MiB 尺寸**。旧版第 7 节"LM head 331MB"是对的（129280×1280×2B）。

> 🗣️ **说人话**：这是一段「数字侦探」现场：日志打印 `LM head: converted ... (631.1 MB)`——同一块权重，BF16 原件 331MB、F32 副本 662MB，631.1 哪来的？答案：代码用 `/1048576.0`（MiB 口径）却标成 MB，662 MB = 631.1 MiB，单位标错、数字没算错。所以读到 631 别当成「每步读 631MB」——每步流式 argmax 扫的是 331MB 的 BF16 原件（§5.3）；631 MiB 是只有温度采样时才创建的 F32 副本的 MiB 尺寸。三个数各有用途，张冠李戴会把带宽账放大一倍。
> *边界*：排查同类问题先查「除以 10⁶ 还是 2²⁰」——09 篇 §1.1 的"631.1 MB"脚注踩的是同一个口径；本书所有 MB 均为十进制（1 MB = 10⁶ 字节），引擎日志例外。

### 5.2 流式 argmax：不物化 logits

标准链路每步：sgemm 算全量 logits（读 662MB F32 副本，首次还需一次性 331MB 读 +
662MB 写的转换）→ 物化 129280×4B≈0.5MB logits → argmax。贪心只需要 top-1，
`ds_argmax_matvec_bf16` 换了个算法：**逐行流式读 BF16 权重、在飞转换（`vshll`
左移 16 位还原 F32）、在线比较只记当前最优**，从不分配 logits 数组。单行点积内核
`ds_bf16_dot_row` 与区间 argmax 内核 `argmax_bf16_range` 按词表切成线程数段并行
（`ds_argmax_task_t`），各线程报回本地最优再归并。

### 5.3 数字对比

| 路径 | 每步权重读取 | 实测单步 | 出处 |
|---|---|---|---|
| 全量 logits（sgemm） | 662MB F32（631 MiB） | ~55ms（源码注释）～63ms（05 篇 §4.1，7.9× 加速前） | `ds_moe_decoder.c` 注释 / 05 篇 |
| 流式 argmax | 331MB BF16 | ~8ms（源码注释）；05 篇 profiler 样例 365.8ms/226 步 ≈ 1.6ms/步 | 同上 |
| 理论带宽下限 | — | 331MB ÷ 200GB/s ≈ 1.65ms（M2 Pro，注释口径） | 推算 |

账怎么读：流式 argmax 实测 1.6–8ms，取决于页缓存热度——全热时逼近带宽下限
1.65ms；全量路径实测 55–63ms，对应有效带宽约 10–12GB/s，被"F32 转换 + sgemm 效率
+ logits 回写"摊薄（注释原话："实际 ~55ms 因效率低"）。这就是 decode 优化里性价比
最高的一刀：不改数学，只改"要不要算出全部 logits"。

> 🗣️ **说人话**：把 LM head 想成一本 331MB 的账本，每生成一个字都要从头翻一遍。全量
> 路径是"把整本账抄到一张大纸上再找最大的数"——抄写（F32转换）和誊录（logits回写）
> 才是真花钱的地方；流式 argmax 则是"边翻边比，手里只攥着目前看到的最大值"，纸都省了。
> 每步 331MB ÷ 200GB/s≈1.65ms 是物理下限（内存条的速度上限），实测 1.6–8ms 说明已经
> 贴着天花板跑；全量路径 55ms 则相当于只跑出 10GB/s，钱全花在搬运而非翻账上。
> *边界*：这刀只在"只要 top-1"时能砍。一旦要熵、要 top-5、要做采样，就必须物化整本
> 分布——快与"可观测/可采样"在贪心路径上二选一（§5.5）。

### 5.4 快速路径的准入条件

```c
if (ctx->temperature <= 0.0f && lm_w) {   /* 贪心 → 快速路径 */
```

只要 `--temp` 不大于 0，重复惩罚与 n-gram 阻断（≤40 项）都在快速路径内消化；
`--temp > 0` 或 banned 超限才落回全量路径。另有 GPU 旁路：设置 `DS_METAL_LM`
且 Metal 可用、本步无禁用 token 时走 `ds_metal_lm_head_argmax`。**LM head 不存在
"采样"问题，只有 argmax**——除非显式要温度采样，这是"贪心场景"与"采样场景"
架构分歧的全部原因。

### 5.5 置信度与校准：贪心路径为什么算不出熵

生产系统常需要"这个 token 有多可信"——用于拒识、重试、或给用户标出可疑
区域。标准做法是看**分布的熵**或 **top-1/top-2 的 margin**：

$$ H(p) = -\sum_i p_i \log p_i, \qquad \text{margin} = z_{(1)} - z_{(2)} $$

- 熵低 / margin 大 → 模型很确信
- 熵高 / margin 小 → 近并列，容易翻转（**这正是 docs/08 §9 幻觉的数值根源**）

**本工程的工程约束**：流式 argmax（§5.2）**只保留 top-1，不物化 logits**，
所以**算不出熵**——要算熵必须走全量路径（55–63ms/步，比快速路径慢 7–8 倍）。
这是一个真实的架构权衡：**"快"与"可观测"在贪心路径上互斥**。

**可行的折中**（本工程未实现，但成本可算）：流式 argmax 时**顺带记录 top-2**
（多一个寄存器变量，几乎零成本），得到 margin 而不要熵。margin 是熵的廉价
代理——margin 小意味着 top-2 接近，分布至少有两个峰。docs/08 §9 的"近并列
token 翻转"诊断，本质上就是在看 margin。

**校准（calibration）**：模型输出的概率往往**过度自信**——说 0.95 实际只对
0.8。**温度缩放**（temperature scaling, Guo et al. 2017）是最简单的修复：
在验证集上拟合一个标量 $T>1$，推理时用 $p_i \propto \exp(z_i/T)$ 把分布压平。
它**不改变 argmax**（单调变换），所以对贪心解码的输出**完全无影响**——只影响
"报告给用户的置信度"。

**为什么 OCR 场景需要它**：若要把"低置信度区域"标出来让人复核，未校准的
概率会误导——模型说 0.99 的地方可能错得离谱。校准后的概率才能当"错误率
预测"用。**注意**：本工程的 `--temp` 是**采样温度**（改变输出），不是校准
温度（不改变输出）——两者数学形式相同、用途完全不同，这是最容易混淆的一点。

> 🗣️ **说人话**：「这个 token 有多可信」看两个量：熵（分布平不平）与 margin（冠军领先第二名多少）。近并列像两人同时冲线、摄像头却模糊——margin 小处最容易翻转（§9 幻觉链条的数值根源）。麻烦在架构：流式 argmax 手里只攥 top-1（§5.2），熵根本没算过——想要它每步多付 7–8 倍时间走全量路径；廉价出路是顺带记 top-2（一个寄存器变量），margin 就是熵的代理。另一个易混点：采样温度改输出（softmax(z/T) 重塑锐度），校准温度（Guo 2017 温度缩放）只改「口头自信度」——单调变换不动 argmax，治的是「说 0.95 实际只对 0.8」的过度自信。
> *边界*：校准概率只能当「错误率预测」用，不能当「逐字对错」用——低置信度处可能恰好全对；本工程两个都没实现，`--temp` 是采样温度不是校准温度，想上校准得先有验证集拟合 T。

## 6. V3 的输出后处理流水线

### 6.1 为什么需要：V3 的 grounding 输出格式

V3（Unlimited-OCR）的训练目标含版面检测（grounding），原始输出混有检测标签：

```
实际文字<|det|>text [x1, y1, x2, y2]<|/det|>更多文字<|ref|>…<|/ref|><|det|>…<|/det|>
```

标签 token 是整词占位（`<|det|>`=128818、`<|/det|>`=128819、`<|ref|>`=128816、
`<|/ref|>`=128817，已对 `tokenizer.json` 核实），用户只要正文。另因幻觉前缀无法
逐 token 判定，V3/V4 干脆关闭流式显示（`main.c` 只给 V1/V2 挂
`ds_set_token_callback`），等生成完毕再一次性经**流式层 + 终态层**两级清理。

> 🗣️ **说人话**：V3 的训练目标含 grounding，所以它说话自带「舞台提示」：正文后面跟着 `<|det|>text [x1, y1, x2, y2]<|/det|>` 这样的坐标工单——标签是整词占位 token（`<|det|>`=128818、`<|/det|>`=128819、`<|ref|>`=128816、`<|/ref|>`=128817，已对 tokenizer.json 核实），观众只要台词。也因此 V3/V4 干脆关掉流式显示——幻觉前缀没法逐 token 判定（§6.3 第④⑤步都是终态才做的事），与其边生成边删边改口，不如生成完一次性过「流式层+终态层」两级清理。
> *边界*：关流式是 V3/V4 专属——V1/V2 没有 det 标签，main.c 只给它们挂回调；代价是首字延迟换输出正确性，交互式场景这是笔取舍账。

### 6.2 流式层：`ds_stream_filter_det` 缓冲状态机

难点：BPE 可能把一个标签切成多个 token（`"<|de"` + `"t|>…"`），必须缓冲。V3 专用
过滤器（`ds_ocr.c`，缓冲区 `ctx->_det_buf[256]`）每收到一个 piece 做三件事：

1. **孤立闭合标签前缀抑制**（`_v3_prefix_done` 门控）：输出开头若是一串
   `</td></tr></table>`（模型解析图表类内容时的 opener 丢失产物），识别文本永远
   不会"从表格中间开始"，整段丢弃；token 被扣住直到能判定（出现真实内容或生成结束）。
2. **完整标签剥离**：`ds_try_strip_det_tag` 在缓冲区内匹配 `<|det|>…<|/det|>` 或
   `<|ref|>…<|/ref|><|det|>…<|/det|>` 整对，命中即整块丢弃。
3. **安全前缀 flush**：找不到完整标签时，从后往前找最后一个 `'<'`——它之前的内容
   不可能再构成标签，安全回给回调；`'<'` 之后继续扣留。缓冲将满时强制 flush 并
   放弃前缀抑制。

> 🗣️ **说人话**：难点一句话：BPE 可能把一个标签切成两半（`"<|de"` + `"t|>…"`），所以过滤器不能见字吐字，得像「快递拆完再签收」：每收一个 piece 先在缓冲区（`ctx->_det_buf[256]`）里试凑完整标签对，凑成就整块丢弃；凑不成，从后往前找最后一个 `'<'`——它之前的内容不可能再构成标签，安全放行，`'<'` 之后继续扣留。开头那串 `</td></tr></table>` 是「opener 丢失」的产物：识别文本永远不会从表格中间开始，整段丢弃。
> *边界*：扣留有代价——流式显示会「一顿一顿」；缓冲将满时强制 flush 并放弃前缀抑制，那一刻半截标签可能漏到屏幕上，终态层（§6.3）会再兜一次底。

### 6.3 终态层：权威缓冲的八步清理

流式层只管"好看"，**权威输出缓冲 `output` 全程保留原始文本**，识别结束后按代码顺序（`ds_recognize` 尾部）做最终清理，V1/V2 仅做第 ① 步：

| # | 步骤 | 代码位置 | 说明 |
|---|---|---|---|
| ① | 尾部 whitespace strip | 全模型 | 对齐 Python `.strip()` 的行为 |
| ② | `ds_strip_det_tags` | V3/V4 | 读写双指针：跳过 `<|det|>…<|/det|>` 与 ref+det 对，保留不成对的碎标签（不猜）；随后把连续换行合并到 ≤2 个 |
| ③ | V4 净化 | 仅 V4 | `ds_v4_warn_degenerate` + `ds_v4_strip_layout`（§7、§8） |
| ④ | `[No text detected]` 截断 | V3/V4 | 首 token 被迫越过 EOS 时的英文幻觉以该标记收尾，整体移到标记为止；前 400 字符内搜索 |
| ⑤ | 英文幻觉前缀 | V3/V4 | 无标记时匹配固定短语表（"The image contains no text"、"There is no text"、"No text is present"、"The OCR result"），截到 `\n\n` 或首个 CJK 字节（UTF-8 首字节 ≥0xE0） |
| ⑥ | 点阵占位行剥离 | V3/V4 | 位置嵌入插值正确后偶发的"纯点+空白"占位网格行（空检测网格的占位符），整段剥离；若全文皆点行则清空 |
| ⑦ | 断裂 det 片段 | V3/V4 | 首 det 族 token 是 closer（`<\|/det\|>`，opener 丢失/双 closer）→ 连 fragment 一起剥，最多 4 轮处理连续残留 |
| ⑧ | 孤立闭合标签前缀 | V3/V4 | 与流式层第 1 步同一规则的终态兜底——流式过滤与最终清理是**双层独立实现**，谁先命中都无碍 |

⑤ 的短语表与 ⑥⑦ 的触发条件都来自真实故障样本（源码注释记录了各自事故形态），这批"确定性手术"因此能写成纯文本函数。

> 🗣️ **说人话**：权威缓冲 `output` 从头到尾「原件不修一字」，八步清理全发生在识别结束之后——像法院卷宗：庭审直播（流式层）可以有删改，归档卷宗（output）永远保留原始记录，判决（终态清理）从原件重放。八步各有来头：②剥标签「不猜优于猜错」（不成对的碎标签保留）；④⑤治幻觉前缀（前 400 字符找 `[No text detected]`，或短语表截到 `\n\n`/首个 CJK 字节）；⑥⑦⑧清真实事故残留（点阵占位行、断裂 det 片段最多 4 轮、孤立闭合标签兜底）。两层是独立实现，谁先命中都无碍——双层冗余是对「过滤器 bug」的保险（§6.4）。
> *边界*：八步全是确定性文本手术、治已知病；新版面的新症状不在清单里——那归第 8 节的「喊一声+重试」管流程，不归手术管内容。

### 6.4 设计原则

1. **权威缓冲与流式显示分离**：`output` 全程保留原始文本，流式显示走独立过滤器
   ——两层各自的 bug 互不污染，终态层永远可以从原始文本重放。
2. **纯函数可单测**：`ds_strip_det_tags` 等全部是"输入字符串 → 输出新长度"的
   纯文本操作，无模型依赖，`test_unit.c` 可直接覆盖。
3. **不猜优于猜错**：不成对的碎标签宁可保留（②）、畸形行宁可计数（§7），
   把"想当然的修复"留给人或重试机制。

## 7. V4 输出净化：布局标签剥离与 `--raw-layout`

> 本节对应提交 `11454dc`（feat(v4): 输出净化）。V3 的标签是**行内**的（正文后跟
> 坐标框，§6 删框留文）；V4 的布局标签是**行级**的（每行一个块），处理方式不同。

### 7.1 V4 原生输出长什么样

V4（Unlimited-OCR-2，[14-V4与DASH注意力篇](./14-V4与DASH注意力篇.md)）的文档解析
输出自带头部标签 `<PAGE>`（id=128827）与逐块结构 `<BLOCK>`（128828）/`<FORK>`（128829）。
真实样例（`docs/golden/labels/Unlimited-OCR-2_test_crop_640.txt` 重冻前的原貌）：

```
<PAGE><BLOCK>title<LEVEL1>[88, 62, 611, 158]<FORK>Description
<BLOCK>text[84, 262, 980, 315]<FORK>云WAF系统，支持黑白名单和CC的防护。
<BLOCK>text[85, 387, 507, 440]<FORK>系统分为以下阶段：
<BLOCK>other[129, 509, 748, 818]<FORK>
<BLOCK>text[130, 511, 728, 569]<FORK>- skip: 实现了白名单功能。
```

行格式：`<BLOCK>` + 类型（title/text/other…，可带 `<LEVELn>`）+ `[x1, y1, x2, y2]` 坐标
+ `<FORK>` + 正文。第 4 行是**空容器块**（`<FORK>` 后无内容，其子项由后续块承载）。
结构化信息对下游排版工具是资产，对终端用户是噪声。

> 🗣️ **说人话**：V3 的标签是**行内**的（台词后面贴坐标框，§6 删框留文）；V4 换了格式——每行 = `<BLOCK>`（128828）+类型（title/text/other，可带 `<LEVELn>`）+`[x1, y1, x2, y2]` 坐标+`<FORK>`（128829）+正文，文件头还有 `<PAGE>`（128827）当页分隔。像「每句台词前面先递一张工单」。样例第 4 行是**空容器块**：`<FORK>` 后没内容，它的子项由后续块承载——对排版工具这是「父节点」，对终端用户是空行噪声。
> *边界*：行级格式让净化能按行原地重写（§7.2 输出恒 ≤ 输入）；但某行的 `<FORK>` 被吐丢时这行就没法拆——那是 §8.3 的畸形行，只计数不清洗。

### 7.2 默认净化：`ds_v4_strip_layout`

默认（不传 `--raw-layout`）输出按**行**原地重写（读写指针同行内推进，输出恒 ≤ 输入），
规则与代码一一对应（`ds_ocr.c`，节选）：

```c
if (n >= 6 && strncmp(src, "<PAGE>", 6) == 0) { src += 6; n -= 6; }  /* 行首 <PAGE> 删 */
/* 行内找第一个 <FORK> */
if (!fk && n >= 7 && strstr(src, "<BLOCK>") != NULL) malformed++;    /* 畸形行：计数 */
if (fk) {
    const char *content = fk + 6;                 /* 只留 FORK 之后的内容 */
    /* 尾部空白 trim 后若为空 → 整行丢弃（空容器块） */
    if (k == 0) { p = eol ? eol + 1 : end; continue; }
    src = content; n = clen;
}
```

| 规则 | 输入行 | 输出行 |
|---|---|---|
| 行首 `<PAGE>` 删除 | `<PAGE><BLOCK>title…<FORK>Description` | `Description` |
| 只留 FORK 后内容 | `<BLOCK>text[84, 262, 980, 315]<FORK>云WAF系统…` | `云WAF系统…` |
| 空容器块整行丢 | `<BLOCK>other[129, 509, 748, 818]<FORK>` | （无） |
| 畸形标签行（有 `<BLOCK>` 无 `<FORK>`） | 原样保留 + `malformed++` | 原样（作为退化信号，§8） |
| 裸文本行 | 原样保留 | 原样 |

注意畸形行**不被清洗、只被计数**：清洗它需要"猜"模型想输出什么，而计数触发的重试（§8）能换来一份从头生成的干净输出。上例净化后即：

```
Description
云WAF系统，支持黑白名单和CC的防护。
系统分为以下阶段：
- skip: 实现了白名单功能。
```

净化只删标签、不碰正文，V4 相对 V3 的完整度优势（嵌套子项、引用块、长句全量转写）
原样保留——提交说明的验收标准是"默认输出与 V3 同级可读、内容完整度更高"。7 组 V4
黄金标签（`docs/golden/labels/Unlimited-OCR-2_*.txt`）已按净化后输出重冻，
`tools/regress.sh` 30/30 全绿（32 组合减 2 组排除）。

> 🗣️ **说人话**：净化的原则是「只删工单、不碰台词」：行首 `<PAGE>` 删、行内第一个 `<FORK>` 之前全丢（类型/坐标都不要）、FORK 后 trim 为空的整行丢（空容器）、裸文本行原样保留——读写指针同行内推进，输出恒 ≤ 输入。关键设计是畸形行（有 `<BLOCK>` 无 `<FORK>`）**只计数不清洗**：清洗它需要「猜」模型想输出什么，而计数触发的重试（§8.3）能换来一份从头生成的干净输出，比想当然的修复可靠。验收硬指标：7 组 V4 黄金标签按净化后输出重冻，regress.sh 30/30 全绿。
> *边界*：「只删不猜」意味着 V4 的嵌套子项、引用块这些结构资产在默认输出里也一起消失——要它们请 `--raw-layout`（§7.3）；净化对正文零改动，但「层级信息」只活在原生输出里。

### 7.3 `--raw-layout`：保留结构化输出

`main.c` 把旗标装进 `ctx->keep_raw_layout`（`ds_ocr.h`："1 = 保留原生
<BLOCK>[坐标]<FORK> 结构化输出；0 = 默认剥离布局标签、丢弃空内容块"）。置 1 时
`ds_v4_strip_layout` 不执行，`last_output_degenerate` 也直接置 0——结构化输出是给
下游工具的契约，CLI 不替它做自愈决策。`ds_strip_det_tags`（§6 第 ② 步）对 V4 仍生效。

> 🗣️ **说人话**：这是给下游工具的「契约模式」：`keep_raw_layout=1` 时 `ds_v4_strip_layout` 整个不执行，`last_output_degenerate` 也直接置 0——契约消费方拿到的是第一手结构化输出，畸形行要不要重试由它自己定，CLI 不越俎代庖。注意两层的对象不同：跳过的只是 `<PAGE>/<BLOCK>/<FORK>` 剥离，§6 第②步的 `ds_strip_det_tags`（V3 系 det/ref 标签）对 V4 仍生效。
> *边界*：raw 模式下退化护栏的自动重试也静音了——包括可能的畸形行，一并原样交付；「契约优先」的代价是自愈关闭。

## 8. 退化护栏与自愈：检测、警告、重试

### 8.1 问题来源

提交 `a73a6d8` 记录了一次真实排查：用户在 `--silent` 下拿到"块结构正确但
`<FORK>` 后内容全空"的输出。作者在当前构建上 12 次运行（含 8 路重负载）输出逐字节
一致且正确，无法复现；用 `git worktree` 构建修复前状态（3e4c131）实测复现出同类
退化——**用户跑的是修复前旧构建**。护栏由此而生：识别结果若 ≥2 个 `<FORK>` 块且
内容全空，stderr 打印重建提示（stdout 不变，保证回归可比对）。

> 🗣️ **说人话**：这是一次真实排查的侦探故事：用户在 `--silent` 下拿到「块结构正确但 `<FORK>` 后全空」的输出；作者当前构建跑 12 次（含 8 路重负载）逐字节正确、无法复现；最后用 `git worktree` 构建修复前的 3e4c131，复现出同类退化——**用户跑的是旧构建**。护栏由此而生：≥2 个 `<FORK>` 块且内容全空时，stderr 打印重建提示，stdout 一字不动（保证回归输出可比对）。教训：「我这里没问题」≠「没问题」，先让对方复现你的构建，再谈别的。
> *边界*：护栏判的是「全空」这一种形态（§8.2），不是万能退化探测器；它提示的「重新 make blas」针对旧构建场景，真正的数值性退化另有 §9 的三层防御。

### 8.2 检测：`ds_v4_warn_degenerate`

`11454dc` 把护栏从 `main.c` 迁入引擎——它必须在**净化前**调用（依赖原始块结构，
净化后空块已被丢弃）：

```c
static void ds_v4_warn_degenerate(const char *t) {
    int forks = 0, empty = 0;
    const char *p = t;
    while ((p = strstr(p, "<FORK>")) != NULL) {
        forks++;
        const char *c = p + 6;
        if (*c == '\0' || *c == '\n' || strncmp(c, "<BLOCK>", 7) == 0) empty++;
        p = c;
    }
    if (forks >= 2 && empty == forks)
        fprintf(stderr, "\n警告：识别结果疑似退化（%d 个块内容为空）。"
                "请确认使用最新代码并重新 make blas；若仍复现请附 `git log -1` 与图片反馈。\n", forks);
}
```

判定条件是"**全部**块皆空"（`empty == forks`）且至少 2 块：正常版面里空容器块
（§7.1 第 4 行）与内容块混着，全空才说明整次生成退化。当前仅 V4 调用（V3 无
`<FORK>` 标签）。

> 🗣️ **说人话**：判定条件是「**全部**块皆空（`empty == forks`）且至少 2 块」——两个条件都刻意收紧。只看「有空块」会误报：正常版面本来就有空容器块（§7.1 第 4 行），单块空多半合法；整次生成全空才说明真退化了。还有个次序陷阱：检测必须在**净化前**调用——§7.2 会把空块整行丢弃，净化后再数，空块已经不在了，想报警都找不到证据。
> *边界*：判空标准很窄（FORK 后紧跟结尾/换行/`<BLOCK>` 都算空），覆盖不了「内容是垃圾但非空」的退化——后者只能靠下游工具或人眼，护栏管不了。

### 8.3 自愈链路：畸形行 → 标志位 → CLI 重试一次

第二类退化是**块边界早停**：解码偶发在块边界截断，留下"有 `<BLOCK>` 无 `<FORK>`"
的畸形标签行。处理链路（全链在 `ds_ocr.c` + `main.c`）：

```
ds_recognize (V4)
 ├─ ds_v4_warn_degenerate(output)          # 全空护栏（净化前，需原始块结构）
 ├─ ds_v4_strip_layout(output, &malformed) # 畸形行计数（不清洗）
 └─ last_output_degenerate = (malformed > 0) || getenv("DS_FORCE_RETRY")
main.c: if (V4 && last_output_degenerate)
        → stderr "检测到退化输出片段，自动重试一次…"
        → 释放首跑结果，ds_recognize 整体重跑（含编码），命中概率 p → p²
```

为什么重跑能自愈：V4 近并列 argmax 的翻转偶发于运行间内存布局差异（05 篇的数值
敏感性话题），同一输入两次运行的退化命中相互独立，一次重跑把命中率从 p 压到 p²。
畸形行仍留在本次 stdout 里（不猜、不删），重跑成功的输出整体替换它。`DS_FORCE_RETRY`
环境变量无条件置位标志，用于联调这条链路（源码注释："DS_FORCE_RETRY: 自愈链路联调"）。

> 🗣️ **说人话**：重跑为什么有用？因为退化是**偶发**的：V4 近并列 argmax 的翻转受运行间内存布局差异影响（05 篇的数值敏感性话题），同一输入两次运行的命中近似独立——一次重跑把命中率从 p 压到 p²，掷两次硬币全反面的概率平方级下降。链路三段式：畸形行只计数（不猜、不删）→ 置 `last_output_degenerate` 标志 → main.c 看到 V4 且标志位，stderr 报一声、整体重跑一次（含编码），重跑成功的输出整体替换它。`DS_FORCE_RETRY` 无条件置位，专供联调。
> *边界*：重跑只治「偶发」不治「必然」——模型对该图就是会退化时 p² 依然很大；那时的对策是查输入（分辨率、crop 数、训练分布）而不是再掷一次硬币。

### 8.4 第二类退化：内容循环与解码中途早停（r4）

V4 标签退化之外，还有一类更隐蔽的退化：**公式/表格密集页模型陷入内容循环**——
反复生成同一片段直到 `max_new_tokens`（默认 4096），每页可浪费 60s 以上。
官方 generate 同样如此，这不是实现 bug，是解码策略的固有风险（§9.1 幻觉成因
的同族现象：模型对重复输出"很自信"）。

**检测设计**（`ds_output_tail_loopy`，`ds_ocr.c`）：解码**中途**每 16 步（且 ≥48 步）
对输出尾部做多尺度字节级周期检测——

```
窗口:   3072 / 1536 / 768 / 384 字节依次检查（取装得下的最大者）
归一化:  剔除数字 / 空白 / [] , / .
判定:   存在周期 p ∈ [4, 512] 使 norm[i] == norm[i+p] 对全部 i 成立
        （即 ≥3 个完整周期全窗匹配）→ 命中即 break，已生成部分保留
```

两个设计动机：

- **为什么剥数字与括号**：循环的原始形态多样——单行重复（`World World…`）、
  多行周期（附录/资料库 ×3）、**坐标逐圈抖动的标签流**（数字在变、文本结构
  重复）。归一化让三类形态落入同一检测。
- **为什么多尺度窗口**：「真实内容 + 尾部循环」混合时，循环只占尾部一小段，
  小窗口仍能整体落入循环段。全窗逐字节匹配是极强条件，正常文本不可能满足——
  黄金标签 32 份同逻辑扫描零误报。

**处置与护栏语义**：命中即提前终止并置 `last_output_loopy = 1`（与 §8.3 的
`last_output_degenerate` 同构的标志位模式），stderr 报 `Loop detected at token N`。
已生成部分保留在 stdout——同样是"CLI 不猜、下游工具决策"契约（§6 第 ⑤ 步）。
`DS_NO_EARLY_STOP=1` 关闭检测。与 §8.3 重试自愈的区别：循环早停**只止损不重试**——
31 页 PDF 实测里循环带逐圈抖动坐标标签并非精确重复（88415 token ≡ 基线），
重跑大概率再循环；止损靠 `-n 1536` 上限（页 11 正常内容实测 1035 tok > 1024，
上限别低于 1536）+ 早停双保险。

> 🗣️ **说人话**：这是「复读机检测器」：解码中途每 16 步（且 ≥48 步）把输出尾部塞进 3072/1536/768/384 字节的多尺度窗口，剥掉数字/空白/括号后找周期——存在 p∈[4,512] 使 norm[i]==norm[i+p] 全窗成立（≥3 个完整周期）才算命中。剥数字是关键一招：循环的原始形态里有「坐标逐圈抖动的标签流」——数字在变、文本结构重复，不剥就漏检；多尺度窗口则专抓「正常内容+尾部循环」的混合。命中即 break 并置 `last_output_loopy=1`，已生成部分保留——**只止损不重试**：31 页 PDF 实测里循环带逐圈抖动坐标并非精确重复，重跑大概率再循环。
> *边界*：全窗逐字节匹配是极强条件，换来零误报（黄金标签 32 份零命中）也换来漏报——「每 16 步查一次」窗口期之外的循环、换同义词复读都躲得过；`DS_NO_EARLY_STOP=1` 可整体关闭做对照。

## 9. 幻觉问题：成因与三层防御

> **先讲一般成因，再讲本引擎的特殊成因。** 所有 LLM 共有的幻觉根源：接龙机器的"知识"不是档案柜里可查证的条目，而是统计语感——它知道"参考文献通常长什么样"，却不知道"这份文献是否真的存在"，追问事实时会生成**文体无懈可击、事实查无此物**的结果（一位只读过海量文献、从未进过档案馆的掉书袋先生）。通病的对策是给语感补外部事实源（RAG，检索增强生成）。OCR 场景的幻觉风险**结构性偏低**：答案就贴在眼前，"作弊材料"（视觉 token）已随提示词进入上下文，任务是抄写而非回忆——但仍可能"抄飞"（脑补图中没有的字），所以下面这套工程防御依然必要。本节聚焦本引擎特有的一种**数值性幻觉**——由计算精度差引起的抄飞与退化。

### 9.1 成因链条

把 §4、§6 反复出现的"幻觉"拆成因果链（每级箭头都有对应的工程对策）：

```
C 引擎 F32 计算 ↔ Python BF16 autocast 的 16 位尾数差
  → 12 层 MoE 逐层累积（每层 RMSNorm、SwiGLU、top-6 专家求和）
  → 近并列 token 的相对高低可能翻转（EOS 偏高 / 正文峰被削）
  → 症状 A：EOS logit 偏高 → 提前停/空输出（§4 的两难）
    症状 B：EOS 被抑制 → 被逼续写英文幻觉前缀（§6 第④⑤步的来源）
    症状 C：V4 上表现为块边界早停/畸形标签行（§8 的退化）
```

> 🗣️ **说人话**：这条因果链是「精度差滚雪球」：C 引擎用 F32 算、Python 训练时 BF16 autocast——尾数 7 位 vs 23 位（差 2¹⁶ 倍分辨率），单步看着无害，但 12 层 MoE 每层的 RMSNorm、SwiGLU、top-6 求和都在放大它；滚到 LM head，近并列 token（第 7、8 名只差 0.001）的相对高低可能翻转。三种症状同根：EOS 偏高→提前停/空输出（A）；EOS 被抑制→被逼续写英文幻觉前缀（B）；V4 表现为块边界早停/畸形标签行（C）。每一级箭头都有对策：§9.2 的 BF16 对齐治根，§4/§6 治症状。
> *边界*：近并列翻转是概率事件不是必然——大多数步不翻转，所以这类 bug 表现为「偶发、难复现」（§8.1 的 12 次跑不出来）；对拍要靠 `DS_DUMP_*` 分段定位，别整链路猜。

### 9.2 三层防御

1. **数值对齐（釜底抽薪）**：`ds_bf16_simulate_python`（`ds_ocr.c` 全局开关，默认
   1，`DS_BF16_SIMULATE_PYTHON=0/false/off` 关闭）在关键中间点调用
   `ds_bf16_truncate_array` 把 F32 截断回 BF16 精度再继续——覆盖 prefill 的
   QKV/投影/FFN、decode 的专家与共享专家中间结果、final norm 输出与 LM head 之前的
   隐状态。分布贴近 Python 后，EOS 在正确位置触发，幻觉前缀在源头消失。
2. **位置对齐（前疫）**：crop 位置嵌入用 bicubic + antialias 重采样
   （`ds_deep_encoder.c` 的 `ds_bicubic_resample_dim`）对齐 Python 的
   `interpolate(..., mode='bicubic', antialias=True)`，根治了输出以
   `</td></tr></table>` 开头的一类前缀幻觉——见 [06-视觉编码器篇](./06-视觉编码器篇.md) 第 4 节。
3. **输出净化（兜底）**：§6/§7 的确定性流水线——数值与位置对齐把幻觉压到罕见，
   后处理保证罕见的那次也不直达用户。

第 8 节的退化护栏是第四道哨兵：它不清理任何内容，只在"这次输出不可信"时喊一声并触发重试——三层防御管内容，护栏管流程。

> 🗣️ **说人话**：这三层像治水，顺序不能反。第一层是修上游堤坝（BF16 数值对齐），让
> 洪水根本不发——因为幻觉多半是"第 7 名和第 8 名只差 0.001，计算误差一抖就换人"的
> 产物，把精度对齐 Python 就从源头掐掉了；第二层是疏通河道（位置嵌入重采样），专治
> "上游放水就冲垮某处"的老毛病；第三层才是城区沙袋（后处理）——前两层做到位，它一年
> 也用不上几次。
> *边界*：层层设防只压概率、不能归零。真遇到训练语料里从没见过的版面，三层都可能漏，
> 这时唯一兜底是第 8 节的"喊一声 + 重跑一次"（概率 p→p²），而不是后处理"猜"着修。

### 9.3 怎么量化"幻觉"：CER / WER 与编辑距离

"幻觉少了"必须能被测量，否则所有防御都是玄学。OCR 领域的标准指标是
**字符错误率（CER）** 与 **词错误率（WER）**，二者都建立在**编辑距离**
（Levenshtein distance）之上。

**编辑距离**：把预测串 $P$ 变成真值串 $G$ 所需的最少单字符操作数
（插入、删除、替换各计 1）。动态规划求解：

$$ D[i][j] = \min\begin{cases} D[i-1][j] + 1 & \text{删除}\\ D[i][j-1] + 1 & \text{插入}\\ D[i-1][j-1] + [P_i \ne G_j] & \text{替换/匹配} \end{cases} $$

**CER / WER** 是归一化后的编辑距离：

$$ \text{CER} = \frac{D(P, G)}{|G|}, \qquad \text{WER} = \frac{D_{\text{word}}(P, G)}{|G|_{\text{word}}} $$

- CER 按**字符**算，对中文/公式/表格这类"词边界模糊"的 OCR 更合适
- WER 按**词**算（空格切分），适合英文；中文需先分词，反而引入额外误差
- 两者都可能 >1（预测比真值长很多时），不是百分比

**为什么它是本仓库的"回归标尺"**：`tools/regress.sh` 用 `docs/golden/labels/`
里的冻结标签做对照，任何改动（位置插值、BF16 截断点、量化开关）都要看 CER
是否退化。**这是把"幻觉"从主观感受变成可回归数字的唯一办法**——docs/06 §6.3
的 bicubic 修复、docs/09 §3 的量化验收，最终都以 CER/输出一致性收口。

> **⚠️ 本仓库的 CER 是"近似 CER"，不是严格编辑距离**：`tools/regress.sh`
> 实际用的是 Python `difflib.SequenceMatcher(None, gold, out).ratio()`，
> 再取 `(1 - ratio) * 100` 当百分比。`SequenceMatcher` 求的是**最长匹配块
> 序列**（Ratcliff/Obershelp 算法），与 Levenshtein 编辑距离**不等价**——
> 对"整段重排"和"局部替换"的惩罚权重不同。所以：
>
> - 它**适合做回归门控**（同一算法前后对比，退化必然反映为数值上升）
> - 它**不适合跨论文/跨工具比较**（别人报的 CER 是严格编辑距离，数值不可直接对齐）
> - 阈值是"冻结时基线 + 1pt"（`regress.sh` 注释，冻结于 2026-10-30），
>   变更须批准并记 PROGRESS.md
>
> 若要严格 CER，需换成 `Levenshtein.distance(gold, out) / len(gold)`——
> 本仓库没这么做，因为 `difflib` 是标准库、零依赖，符合"纯 C + 零外部依赖"
> 的项目哲学（docs/03 §1）。**知道这个差异，才不会把 18% 的假 CER 事故
> （`regress.sh` 注释里 2026-10-30 的教训：按 `#` 剥行剥掉了正文标题）
> 误读成模型退化**。

**与 PPL 的分工**（docs/11 §5.1）：PPL 衡量"模型对下一个 token 有多确信"，
是训练期指标；CER 衡量"最终转写对不对"，是任务指标。**PPL 低但 CER 高完全
可能**——模型很确信地写错字。所以推理端的优化目标永远是 CER，不是 PPL。

**RLVR 的奖励函数**（docs/12 §6）：GRPO 类方法在 OCR 场景下可以直接用
$-\text{CER}$ 或 $-\text{编辑距离}$ 当可验证奖励——这正是"有可验证奖励的
任务"的典型例子，不需要人类标注偏好。

> 🗣️ **说人话**：编辑距离就是「改几个字能改对」：插入/删除/替换各计 1，动态规划逐格填表；CER/WER 是它除以真值长度的归一化。中文/公式/表格选 CER（按字符算，不引入分词误差），英文用 WER；两者都可能 >1（预测比真值长很多时），不是百分比。本仓库的尺子是近似版——`difflib.SequenceMatcher` 求最长匹配块序列，不是严格 Levenshtein：适合同算法的回归红绿，不适合跨论文对数（`regress.sh` 注释里 18% 假 CER 事故的教训就在这）。PPL 低但 CER 高完全可能——模型很确信地写错字，所以推理端只认 CER（docs/11 §5.1 的分工）。
> *边界*：阈值「冻结基线+1pt」只承诺同一把尺子下不退化，承诺不了「18.0% 一定比论文里的 15% 差」——跨报告比较必须换严格编辑距离（本警告块开头说的那段）。

## 小结

解码策略决定"怎么选 token"，后处理决定"输出什么"。OCR 场景在本工程的最优组合：

- **贪心**（转写任务的熵结构使然）+ 流式 argmax 快速路径（331MB/步，~8ms）；
- **重复惩罚压幅度、n-gram 阻断禁 id**：前者管 token 级惯性，后者管整段循环，
  V3 默认 35、V4 默认关；
- **min_new_tokens=32（V3/V4）+ EOS/Ġ 成对禁用（仅 V3）**：排除式 argmax 选出
  当前分布的真实次优，warmup 过期即停；
- **两级后处理**：流式过滤器管实时显示，权威缓冲 + 终态清理管最终输出；
- **V4 新增**：默认净化成纯文本（`--raw-layout` 可还原）、退化护栏 + 一次自愈重试。

采样层每多一分随机，后处理就多一分不确定。本工程把随机性压到零，让后处理成为
纯函数——这是整条"从 logits 到干净文本"链路能逐字节回归（`tools/regress.sh`）的前提。
