## 1. 解码策略全景

设第 t 步 logits 为 z ∈ R^V（V=129280）：

| 策略 | 公式/操作 | 适用 |
|---|---|---|
| Greedy | argmax z | OCR 等确定性任务（本工程默认） |
| Temperature | p ∝ exp(z/T) | T<1 变贪，T>1 变散 |
| Top-k | 只在 k 个最高 logit 里采样 | 抑制长尾 |
| Top-p (nucleus) | 最小集合使 Σp ≥ p | 自适应截断 |
| Beam search | 保 B 条路径 | 翻译/摘要，OCR 少用 |

OCR 要的是"忠实转写"，随机性都是噪声——本工程默认 T=0（贪心），
`--temp` 保留做实验。

## 2. 重复惩罚的精确语义

HuggingFace 语义（`ds_moe_decoder.c` 快速路径）：

```
z' = z > 0 ? z / rp : z * rp     # 对"出现过的 token"
```

注意是**逐 token 出现过就罚**（不管次数，除非指定），且方向对称——
正 logit 除以 rp 变小，负 logit 乘 rp 变得更负。rp=1.0 关闭；
OCR 推荐 1.01–1.05（过大开始伤害数字/单位等合理重复，如 "…"、"=="）。

**快速路径的聪明之处**：不需要全量 logits 就能应用惩罚——
1) argmax 得冠军；2) 若冠军在历史中则罚它；3) 只对历史中出现过的
~300 个 token 逐个补算 logit 比大小。O(V)→O(history)。

## 3. n-gram 阻断：为什么它对 OCR 更有效

no_repeat_ngram_size=n：若历史末尾的 (n-1) gram 曾在历史出现，
则所有曾接续它的 token 直接设 -inf。与惩罚的区别：

- 惩罚压**幅度**（可能仍最高）；阻断禁**id**（必不可能被选）
- OCR 的重复往往是"整段重抄"，n=35 拦截整段循环极其有效
- 副作用：合法重复（表格里的相同单元格）也可能被误伤 → V2/V1 默认关闭

实现要点：**先收集 banned 表，再用排除式 argmax 一次扫描**（容量 32，
超过才回退全量 logits），这是 v1.1 的优化点（旧实现是先 argmax 再检查、
被禁则整条走 sgemm 全量路径，60ms+/步）。

## 4. min_new_tokens 与 EOS 抑制：两难与工程解

- 不抑制：V3 在 BF16/F32 数值偏差下 EOS logit 偏高，输出空结果
- 全程抑制：文本结束后模型被迫继续，产生幻觉

本工程解：`min_new_tokens`（V3=32，其余 0）内发现 EOS → 置 -inf
**并连带禁 Ġ(id=223)**（V3 会 EOS↔Ġ 振荡产生 "10." 循环），重新 argmax。
warmup 期过后 EOS 自然触发，模型"想停就停"。

## 5. 本工程的贪心快速路径（~8ms/步）

标准链路是 logits = lm_head @ x（读 631MB 权重）→ 采样，~55ms/步。
贪心场景只需 top-1：`ds_argmax_matvec_bf16` 流式读 BF16 权重行、
在线比较、不物化 logits 数组——**LM head 不存在"采样"问题，只有 argmax**
（除非 --temp>0）。这是 decode 优化里性价比最高的一刀。

## 6. V3 的输出后处理流水线

V3 训练目标含版面/grounding 标记，原始输出混有非正文内容。清理流水线
（`ds_ocr.c` 尾部 + 流式过滤器 `ds_stream_filter_det`）：

```
1. ds_strip_det_tags        移除 <|det|>…<|/det|> 与 ref+det 对
2. 断裂 det 片段            首 token 是 <|/det|>（双 closer）→ 循环剥离
3. [No text detected] 前缀  幻觉开头整体移除
4. 孤立闭合标签前缀         </td></tr></table> 开头 → 剥离（流式+最终双层）
5. 首尾 whitespace strip    对齐 Python .strip()
```

设计原则：**权威缓冲（output）永远保留原始文本，流式显示单独过滤**；
清理函数全部是纯文本操作、可单测。

## 7. 幻觉问题：成因与三层防御

成因链条：C 的 F32 计算 vs Python 的 BF16 autocast 存在 16 位尾数差 →
12 层 MoE 累积 → EOS logit 相对下降 → min_new_tokens 强行续写 → 幻觉。

三层防御（全部已落地）：
1. **数值对齐**：`ds_bf16_simulate_python` 关键点截断（prefill QKV、共享专家、
   final norm），使 logits 分布贴近 Python
2. **位置信息对齐**：crop 位置嵌入 bicubic+antialias 插值（v1.1 根治
   `</td></tr></table>` 前缀）
3. **输出净化**：第 6 节流水线兜底

---

**小结**：解码策略决定"怎么选 token"，后处理决定"输出什么"。OCR 场景的
最优组合是：贪心 + 轻量重复惩罚 + n-gram 阻断（重复型模型）+ min_new_tokens
（EOS 不稳的模型）+ 确定性的标签清理流水线。
